* 快速开始

** 装机（新机器）

#+begin_src sh
# 用官方 Guix ISO 启动后，克隆本仓库
git clone https://codeberg.org/BrokenShine/Guix-configs
cd Guix-configs

# 使用锁定的频道准备包含 blue 的引导 shell（不分区、不做破坏性操作）
./tools/bootstrap.sh

# 修改 source/information.scm 里的用户名、机器 ID 与挂载点等基础信息，然后初始化系统

passwd

** 日常使用（已装机）

日常维护的核心命令：

- =blue rebuild= ：tangle → 括号平衡检查 → 单次 reconfigure 同时应用系统与 Home（需要 sudo）。
- =blue home= ：仅构建并应用 Home 层配置，更新 immutable dotfiles，无需 sudo。
- =blue stow= / =blue stow-all= ：管理 GNU Stow mutable dotfiles（Emacs、Agent 配置等），改源即时生效。
- =blue check= ：快速检查 Scheme 块括号平衡，精准定位出错块。
- =blue update= ：刷新频道锁并签名提交； =blue pull= 执行 =guix pull= 。

完整命令清单可直接运行 =blue list= 查看。任何 blue 构建命令追加 =--dry-run= 均只做干跑验证，不写入系统。

* 核心概念

深入配置前，建议了解以下 Guix 核心机制：

** Channel（频道）

Guix 的软件包定义分布在多个频道中。本配置除官方 =guix= 频道外，还启用了 =nonguix=（提供 Linux 非自由内核与专有固件）、=jeans=（个人软件源）、=rosenthal=（提供 =Limine= 引导器等增强组件）。具体定义见 [[./source/channel.scm][source/channel.scm]]，各频道的确切 commit 由 [[./source/channel.lock][source/channel.lock]] 锁定。

** System + Home（统一声明）

系统遵循「能放在 Home 层就不上浮至 System 层」的原则，保持系统层轻量。Home 配置通过 ~guix-home-service-type~ 挂载到系统定义中：
- =blue rebuild= ：单次操作同时构建并激活系统层与 Home 层，固化为新世代（generation）。
- =blue home= ：日常调试时快速部署用户态环境。
- 启动回滚：系统每次开机默认进入最新世代；若某次更改存在问题，可在引导菜单选择旧世代即刻恢复。

** Org 文学编程

配置以 Org Mode 代码块的形式组织在 [[./source/config.org][source/config.org]] 中，由 Org Babel 自动提取为 Scheme 代码。代码块之间利用 Noweb 语法（如 =<<ref>>= ）完成装配，文档描述与实际配置代码紧密结合。

** 构建管线

#+begin_example
source/config.org
        │
        │  blue rebuild (org-babel-tangle + 括号检查)
        ▼
tmp/config.scm
        │
        │  guix time-machine --channels=source/channel.lock system reconfigure
        │  (单次同时应用系统与 Home 环境)
        ▼
新世代 (generation)
#+end_example

* 常见修改

** 用户名 / 持久化目录 / 频道

- *用户名、机器 ID、持久化目录与 Btrfs 子卷*：编辑 [[./source/information.scm][source/information.scm]]（声明 ~%data-dirs~ 与 ~%btrfs-subvolumes~ ），保存后运行 =blue rebuild= 。若新增了子卷挂载，需在 =config.org= 的文件系统部分补充对应的挂载项。
- *新增或切换频道*：编辑 [[./source/channel.scm][source/channel.scm]]，然后运行 =blue update= 刷新锁文件。

** 自定义 blue 任务

blue 命令由 [[./blueprint.scm][blueprint.scm]] 驱动。定义新任务时使用 ~(define-command (NAME-command arguments) ...)~ 形式，并在文件底部的命令列表中注册。测试时可先运行 =blue --dry-run <name>= 验证。

* 故障排除

** 改动后验证步骤

1. =blue check= ：快速检查每个代码块的括号平衡，定位出错块名。
2. =blue --dry-run rebuild= ：执行完整的 tangle 与系统构建验证，不写入实际系统。

** 常见报错与排查

- ~unbound variable~ ：缺少模块导入。可通过 https://search.guix.moe 查询该符号所在的 Guix 模块路径并加入 `use-modules`。
- ~invalid field specifier~ ：括号闭合不匹配（常见于 gexp 表达式）。可通过 Emacs 的括号高亮或 =blue check= 定位。
- 语法或逻辑异常：优先检查最近修改代码块中的拼写与引用块名称。

** 开机后用户目录数据丢失排查

根目录 =/= 挂载在 tmpfs（内存盘）上，每次关机重启自动重置。持久化数据由 [[./source/information.scm][source/information.scm]] 显式管理：
- ~%data-dirs~ ：通过 bind-mount 挂回 ~$HOME~ 。
- ~%btrfs-subvolumes~ ：挂载系统持久化子卷。
若发现文件丢失，请检查 ~/data~ 分区的挂载状态以及 ~%data-dirs~ 是否已登记对应目录。
