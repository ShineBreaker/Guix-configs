* 快速开始

** 装新机器

#+begin_src sh
# 用官方 Guix ISO 启动，克隆本仓库
git clone https://codeberg.org/BrokenShine/Guix-configs
cd Guix-configs

# 准备 blue 所在的引导环境（不分区、不动盘）
./tools/bootstrap.sh

# 改 source/information.scm 里的用户名、机器 ID、挂载点，再初始化
blue init

# 仓库不存密码哈希，装好后立刻设一个
passwd

自建 Live ISO 代替官方 ISO：见 [[./docs/iso-build.md][docs/iso-build.md]] 。SSH 私钥等机密怎么加密入仓：见 [[./docs/secrets.md][docs/secrets.md]] 。

** 日常维护

日常真正会用到的命令只有这几个：

| 命令 | 作用 |
| ---- | ---- |
| =blue rebuild= | tangle 出系统配置，括号检查通过后一次 reconfigure 同时应用系统层与用户态，需要 sudo |
| =blue home= | 只应用用户态那一层，更新 immutable dotfiles，不需要 sudo |
| =blue stow= / =blue stow-all= | 管 GNU Stow 那批可变 dotfiles（Emacs、Agent 配置等），改源即时生效 |
| =blue check= | 只查代码块括号平衡，秒级出结果并指出是哪一块 |
| =blue update= | 刷新频道锁；有门禁校验，失败会自己回滚 |
| =blue pull= | 执行 =guix pull= ，拉频道最新 |

完整清单跑 =blue list= 看。任何 blue 构建命令加 =--dry-run= 都只干跑不写系统。

* 仓库导读

系统的声明源只有 [[./source/config.org][source/config.org]] 一处。想找某个配置项在哪改，按这张表跳：

| 想改什么                       | 去哪                                                  |

| 频道定义                       | [[./source/channel.scm][source/channel.scm]]                  |
| 频道锁定的 commit               | [[./source/channel.lock][source/channel.lock]] ，由 =blue update= 生成 |
| 引导环境的包清单               | [[./source/manifest.scm][source/manifest.scm]] ，供 bootstrap 用  |
| 需路径注入的静态模板           | [[./source/files/][source/files/]]                     |

| blue 的任务定义                | [[./blueprint.scm][blueprint.scm]]                       |
| 只读层 dotfiles（进 store）     | [[./dotfiles/immutable/][dotfiles/immutable/]]                 |
| 可变层 dotfiles（Stow 直链）    | [[./dotfiles/mutable/][dotfiles/mutable/]]                   |
| 专题文档                       | [[./docs/][docs/]]                                 |
| 引导与构建脚本                 | [[./tools/][tools/]]                                |

几个关键词先解释清楚，后文一律用代称：

- *不可变*层：构建时整份复制进 =/gnu/store= ，再软链回用户目录。改了不生效，必须 =blue home= 重新部署。
- *可变*层：GNU Stow 直接把 =$HOME= 下的位置软链到仓库源码。改完存盘就是生效。

各主要子目录都有一份 =AGENTS.md= 写清楚该目录的规矩和索引，读到哪个目录就近看哪份。

* 核心概念

深入改配置前先弄懂 Guix 的四个机制，其余都是细节。

** Channel（频道）

Guix 的包定义散在多个频道里。本配置除官方 =guix= 频道外还启用了三个：

- =nonguix= ：非自由内核与专有固件。
- =jeans= ：作者自己的软件源。
- =rosenthal= ：提供 =Limine= 引导器等增强组件。

频道定义在 [[./source/channel.scm][source/channel.scm]] ，到底用哪个 commit 由 [[./source/channel.lock][source/channel.lock]] 锁定。这层锁定是整套配置可复现的前提，别手改 lock 文件。

** System 与 Home

系统层遵循一条原则：能放在用户态就不上浮到系统层。整套 Home 配置通过 =guix-home-service-type= 挂进系统定义，两者写在同一份 Org 文件里。三个动作的区别只在权限和范围：

- =blue rebuild= 一次做完系统层和用户态，固化成新世代。
- =blue home= 只刷用户态，调试时用。
- 改崩了不要慌：开机引导菜单里直接选旧世代，进老环境再修。

** Org 文学编程

配置以 Org Mode 代码块的形式写在 [[./source/config.org][source/config.org]] 里，Babel 负责把块抽成 Scheme。块与块之间靠 Noweb 引用（=<<ref>>= ）拼装，所以说明文字和配置代码天然挨在一起，改代码时上下文就在眼前。

** 构建管线

#+begin_example
source/config.org
        │
        │  blue rebuild（tangle + 括号检查）
        ▼
tmp/config.scm
        │
        │  guix time-machine --channels=source/channel.lock system reconfigure
        │
        ▼
新世代（generation）
#+end_example

* 常见修改

** 改用户名、持久化目录或频道

- 用户名、机器 ID、持久化目录与 Btrfs 子卷：改 [[./source/information.scm][source/information.scm]] 里的 =%data-dirs= 与 =%btrfs-subvolumes= ，然后 =blue rebuild= 。如果新增了子卷挂载，还要到 =config.org= 的文件系统那节补上对应挂载项。
- 增删频道：改 [[./source/channel.scm][source/channel.scm]] ，再跑 =blue update= 刷新锁文件。

** 自定义 blue 任务

blue 的命令来自 [[./blueprint.scm][blueprint.scm]] 。加新命令就是定义一个 =(define-command (NAME-command arguments) ...)= ，并在文件底部的命令列表里注册。测新命令用 =blue --dry-run <name>= 。

* 故障排除

** 改完先验证

改 =source/config.org= 之后，这两步是硬要求：

1. =blue check= 查括号平衡，指出是哪一块。
2. =blue --dry-run rebuild= 跑完整 tangle 与构建验证，不写系统。

** 常见报错

- ~unbound variable~ ：模块没导入。用 https://search.guix.moe 查符号属于哪个 Guix 模块，补进 =use-modules= 。
- ~invalid field specifier~ ：括号没闭合，常见于 gexp 表达式。 =blue check= 能直接定位。
- 逻辑不对但没报错：先看最近改的代码块里 Noweb 引用名有没有拼错。

** 用户数据不见了

根目录 =/= 挂在 tmpfs（内存盘）上，每次关机重启就重置。持久数据由 [[./source/information.scm][source/information.scm]] 显式管理：

- =%data-dirs= ：以 bind-mount 方式把 =/data= 下的目录挂回 =$HOME= 。
- =%btrfs-subvolumes= ：系统侧持久化子卷。

遇到文件丢失，先看 =~/data= 分区挂上了没有，再看 =%data-dirs= 里有没有登记对应目录。
