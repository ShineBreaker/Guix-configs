* Agent 指引

** System

职责： *operating-system* 层。引导器（Limine）、文件系统（LUKS+Btrfs+tmpfs）、内核（自编译 CachyOS LTS =linux-cachyos-lts= ，定义自包含于 =source/files/kernel/= ）、八个按职责拆分的服务块、用户账户。

全局变量定义在 =source/information.scm= （username、%btrfs-subvolumes、%data-dirs、guix-channels）。

=source/files/= 存放需路径注入的静态模板（nftables.conf、qt/rounded.qss 与 qt/check-white.svg、qt/chevron-{up,down}.svg、zed.json、skel/），走 home-files-service-type。

原则：系统层最小化，能用 Home 解决不上浮到 System。

** Home

职责： *home-environment* 层。4 个包列表（desktop/terminal/devtools/user）、dotfiles 部署（home-dotfiles-service-type，layout stow 从 dotfiles/immutable/<app>/ 软链接到 ~）、Home 服务、环境变量、字体。

=source/files/= （home-files-service-type + 路径注入 $$bin/foo$$）与 =dotfiles/immutable/= （stow 软链接）为两套独立部署路径，不互通。

新增应用流程：

1. =dotfiles/immutable/<app>/= 建目录
2. 加到包列表
3. 加到 =dotfile-services packages= 列表。

Emacs 新包必须同时在 =emacs-services= 的 ~specifications->manifest~ 中声明。

=~/.config/<app>/= 指向 */gnu/store 只读副本* ，改源后必须 ~ blue home~ 重建软链接才生效。

** 核心概念

+ *Org Noweb* ：#+NAME 命名块 → <<ref>> 引用 → tangle 为 tmp/config.scm。<<ref>> 是 Org Mode 语法，非 Scheme
+ =config.org= 是唯一 Org 源， *不要新建第二个* ； *不要手动编辑 tmp/ 下的产物*

** 工作方法

*** 块级编辑（优先于读全文件）

修改 config.org 中单个 #+NAME: 块时，用 =block-*= 任务避免读 2000 行：

1. ~blue block-show <name>~ → 提取块 body 到 tmp/block-<name>.scm（并打印路径）
2. ~tail -n +3 <文件>~ → 编辑 body（前两行是 lang= 和 noweb/plain 标记）
3. ~blue block-replace <name> <body-file>~ → 原子写回 + 括号验证

*注意* ：body 可能含 <<ref>> 占位，需自行追踪引用块。括号验证只对 scheme 块触发。

高耦合大块（emacs-services 等）仍建议 read 整段。失败后手动 git checkout source/config.org 恢复。

*** 验证流程

+ ~blue check~ → 逐块括号平衡检查（最快，能定位到具体出错的块）
+ ~blue --dry-run rebuild~ → 完整构建但不写入系统（tangle/括号检查真跑，reconfigure 短路）
+ ~blue home~ → 仅 Home 层生效，不需 sudo（首选调试方式）
+ Agent *禁止* 自行 ~blue rebuild~ / ~guix system reconfigure~ （需 sudo，卡住 CLI）

*** 决策规则

+ 优先改 =dotfiles/immutable/<app>/= ，只当需要 Guix 介入时才改 config.org
+ 新增/重命名 dotfile 子目录后必须同步更新 =dotfile-services packages= 列表
+ 能用 Home 解决就不用 System
+ 修改后必走验证流程

** FileSystems
这里的配置文件需要根据自己的实际情况进行修改。

我目前是使用了 =LUKS + Btrfs= 的架构，同时高强度地使用subvol功能，具体的subvol配置放置在 [[../information.scm][information.scm]] 中，方便我直接做相应地修改

Guix 的 Guile initrd 不支持从加密 swap 恢复休眠镜像，加密与休眠二选一时保留了休眠，所以休眠镜像会把内存 *明文* 写到该分区。

#+NAME: filesystem-defines
#+begin_src scheme
(define %swap-uuid "169557cc-00a4-448c-9bb6-7bd80fc2b023")

(define %mapped-devices-config
  (list (mapped-device
         (source (uuid "327f2e02-1e4f-48b2-87f0-797c481850c9"))
         (target "root")
         (type luks-device-mapping))))

(define %tmpfs
  (list (file-system
         (mount-point "/")
         (device "tmpfs")
         (type "tmpfs")
         (flags '(no-atime))
         (options "mode=0755,nr_inodes=1m,size=10%")
         (needed-for-boot? #t)
         (check? #f))
        (file-system
         (device "tmpfs")
         (mount-point "/var/lock")
         (type "tmpfs")
         (flags '(no-suid no-dev strict-atime))
         (options "mode=1777,nr_inodes=100k,size=1%")
         (needed-for-boot? #t)
         (create-mount-point? #t)
         (check? #f))))

(define %persist-filesystem
  (map (match-lambda
         ((subvol mount-point)
          (file-system
           (device (file-system-label "Linux"))
           (mount-point mount-point)
           (type "btrfs")
           (dependencies %mapped-devices-config)
           (options (string-append "subvol=" subvol ",compress=zstd:3"))
           (create-mount-point? #t)
           (needed-for-boot? (not (string=? mount-point "/tmp")))
           (check? (string=? mount-point "/gnu"))))) %btrfs-subvolumes))

(define %data-filesystem
  (file-system
   (device (file-system-label "Linux"))
   (mount-point "/data")
   (type "btrfs")
   (dependencies %mapped-devices-config)
   (options (string-append "subvol=" %btrfs-subvol-data ",compress=zstd:3"))
   (create-mount-point? #t)))

(define %bind-mounts
  (map (lambda (dirs)
         (file-system
          (mount-point (string-append "/home/" username "/" dirs))
          (device (string-append "/data/" dirs))
          (type "none")
          (flags '(bind-mount))
          (options "x-gvfs-hide")
          (dependencies (list %data-filesystem))
          (create-mount-point? #t))) %data-dirs))

(define %file-systems-config
  (append %bind-mounts %persist-filesystem %tmpfs
          (list %data-filesystem
                (file-system
                 (device (uuid "9699-52A2"
                               'fat))
                 (mount-point "/efi")
                 (type "vfat")
                 (create-mount-point? #t))) %base-file-systems))

(define %swap-devices
  (list (swap-space
         (target (uuid %swap-uuid)))))
#+end_src

**** 内核模块加载
~ip_tables/iptable_nat~ 是 iptables 兼容层，libvirt 与 podman 的网络后端依赖它，与 nftables 规则集共存

zstd 是模块而 zswap 初始化（late_initcall）早于任何 userspace modprobe，cmdline 的 ~zswap.compressor=zstd~ 必然回退 lzo；此处在模块加载后运行时切换（官方支持：旧页留原池，新页用新算法）。

#+begin_src scheme
(list (simple-service 'extend-kernel-module-loader
                      kernel-module-loader-service-type

                      '("ip_tables" "iptable_nat" "kvm_intel" "ntsync" "sch_fq"
                        "tcp_bbr" "uhid" "uinput" "v4l2loopback" "zstd"))


      (simple-service 'zswap-zstd shepherd-root-service-type
                      (list (shepherd-service
                             (documentation
                              "zstd 模块加载后把 zswap 压缩器切到 zstd。")
                             (provision '(zswap-zstd))
                             (requirement '(kernel-module-loader))
                             ;; 内核拒绝时（zstd 不可用）静默放行，不阻断 boot

                                        (system* "/bin/sh" "-c"
                                                 "grep -qw zstd /proc/crypto 2>/dev/null \
&& echo zstd > /sys/module/zswap/parameters/compressor 2>/dev/null; exit 0")
                                        #t))
                             (stop #~(lambda _ #t))
                             (one-shot? #t)
                             (auto-start? #t)
                             (respawn? #f))))

      (simple-service 'v4l2loopback-config etc-service-type
                      (list `("modprobe.d/v4l2loopback.conf"

**** sysctl 调优
- =vm.dirty_writeback_centisecs= —— 空闲时减少 SSD 唤醒（续航）；笔记本有电池，掉电风险可忽略
- =net.core.default_qdisc=fq= —— BBR 的 pacing 依赖 fq 的 EDT 模型，fq_pie 会让 BBR 退化为内核软件 pacing（CPU 开销更高、突发延迟更差）
- =net.ipv4.tcp_rmem= 与 =tcp_wmem= 三元组 —— 高 BDP（跨国代理链路）下放开自动调优上限；只设 =*_max= 不设三元组时 tcp_wmem 仍受默认 4M 限制

#+begin_src scheme
(list (simple-service 'setup-resume-device
                      shepherd-root-service-type
                      (list (shepherd-service
                             (provision '(resume-device))
                             (requirement '(file-systems))
                             (one-shot? #t)
                             ;; 设备号由内核枚举顺序决定，不能硬编码：
                             ;; 由 swap UUID 的符号链接反查块设备名，
                             ;; 再从 sysfs 读出 major:minor 写入 resume
                             (start #~(lambda ()
                                        (let ([dev (call-with-input-file
                                                       (string-append
                                                        "/sys/class/block/"
                                                        (basename
                                                         (readlink
                                                          (string-append "/dev/disk/by-uuid/"
                                                                         #$%swap-uuid)))
                                                        "/dev")
                                                     read-line)])
                                          (call-with-output-file "/sys/power/resume"
                                            (lambda (port)
                                              (display dev port))))))))))
#+end_src

**** 开机清空 /tmp
/tmp 已改为 btrfs 持久化挂载，用此服务替代原 tmpfs 的「重启自动清空」行为。
+ 标志文件保证每个开机周期只有首次执行真正清空，其余全部跳过。清空时用 =find -mindepth 1 -delete= 保留目录本身，单条目删除失败不阻断启动；随后把粘滞位强制修正为 1777（btrfs 子卷挂载点默认权限可能非 1777）。
+ *cleanup-/tmp-prereq* 把 =cleanup-/tmp= 注入 =user-processes= 的 requirement，使所有经 user-processes 启动的服务（dbus/桌面/ssh-agent 等）确定性地排在 /tmp 清空之后。复用 Guix 官方 file-systems→user-processes 注入机制（见 gnu/services/base.scm 的 file-system-service-type 同款手法）。

#+NAME: cleanup-tmp-services
#+begin_src scheme
(list (simple-service 'cleanup-/tmp
                      shepherd-root-service-type
                      (list (shepherd-service
                             (documentation "Empty /tmp once per boot.")
                             (provision '(cleanup-/tmp))
                             (requirement '(file-systems))
                             (one-shot? #t)
                             (start
                              (with-imported-modules (source-module-closure
                                                      '((guix build utils)))
                                                     #~(lambda ()
                                                         (use-modules (guix build utils))
                                                         (unless (file-exists? "/run/cleanup-tmp-done")
                                                           (false-if-exception
                                                            (invoke #$(file-append findutils "/bin/find")

*** 网络相关配置
使用一份静态 nftables 规则集，NetworkManager dispatcher 只原子更新 =inet filter= 表的 =trusted_ifaces= 集合。它绝不执行 =flush ruleset=，因而不会删除 libvirt 或其他服务在运行时安装的 nftables 规则。

- =source/files/nftables.conf= —— 唯一由 =nftables-service-type= 加载的规则集
- 可信 connection profile 列表只保存在 age 密文中，不在 Scheme 源码保留明文副本
- dispatcher 在可信 profile 的 =up= 事件中加入 =wlp0s20f3= ；在非可信或 =down= 事件中删除它，失败时默认严格
- =/etc/NetworkManager= 是 btrfs 持久化挂载点，etc-service-type 无法直接写入，dispatcher 脚本经 activation-service-type 在每次 reconfigure 时拷贝到位

白名单使用 NetworkManager 的 ~CONNECTION_ID=（profile 名称）~ ，不是 SSID；它必须与 ~nmcli connection show~ 的名称一致。列表以 age 密文保存在 =dotfiles/mutable/tools/secrets/.local/share/secrets-encrypted/wifi-trust.age= 。dispatcher 只注入密文与 =age=、=nft=、=grep= 的 store 路径，事件触发时把解密结果直接通过管道交给 =grep= ，不产生持久化明文。私钥缺失或解密失败时仅撤销 WiFi 信任，NetworkManager 继续正常运行，因此不会阻断普通联网。

+ 热点 AP + WiFi 客户端并发（2026-09-09 事故复盘后重构）

硬件事实（=iw phy= 组合规则）：=managed + AP= 并发合法，但 =#channels <= 1=——AP beacon 一开，整个 radio 锁死单一信道，STA 必须与 AP 同信道。事故五环因果链与本设计的对应防御：

1. *隔离用 udev，不用 conf.d*：NM 1.54 不认 =device.interface-name= 键（unknown key 警告），=managed=0= 从未生效；且 =/etc/NetworkManager= 是持久子卷，坏 conf 文件跨系统代、跨重启残留——回滚救不了，只能手动清。现改用 NM 官方 udev 机制 =ENV{NM_UNMANAGED}="1"=（规则文件随系统代原子切换），activation 顺带删除持久层里的历史残留 =20-uap0-unmanaged.conf=。
2. *信道不确定绝不起热点*：AP 起在错误信道会把 radio 锁死，STA 从此连不上其他信道的网络（开机抢跑即断网事故）。热点信道只允许两个来源：STA 已连信道；扫描可见的 autoconnect WiFi profile 信道（这样 NM 稍后自动关联时天然同信道）。两者皆无时 =exit 0= 等下一个触发点重判——每分钟一次的 =hotspot-recheck= timer 保证收敛。
3. *hostapd 配置必须带 =hw_mode=*：默认 =g= 只有信道 1-14，5G 信道号配 =g= 即 =Could not determine operating frequency=（事故中热点 8 连败的真凶）。执行体从 =/run/auto-hotspot/channel= 读决策脚本选定的信道，文件缺失即拒绝启动——respawn 或误启动不会用假信道起 AP。
4. *=hotspot-ap= 不 respawn*：执行体失败即停，由决策脚本在下个触发点重拉。respawn 只会产生反复折腾接口的风暴（事故中 shepherd 日志被刷爆）。
5. *事件上下文后台化 + flock*：udev RUN 与 NM dispatcher 里同步跑决策会拖慢事件处理（dispatcher 版本曾被 NM 退出的 SIGTERM 杀死）；检测到 =SUBSYSTEM= / =NM_DISPATCHER_ACTION= 环境时自重入后台执行，flock 保证多入口并发收敛为串行。

应急开关：=touch /run/hotspot-disabled=（tmpfs，重启自愈）后决策只关不开，可在热点链出任何问题时立即止血。

# Auto-generated by Guix config.org.

# 热点开关决策：AC 供电 且 物理无线口未连可信 profile 时开启热点，
# 其余情况（电池供电、已连可信 WiFi）关闭。四个入口共用：shepherd
# auto-hotspot（开机）、NM dispatcher（任意设备 up/down）、udev
# power_supply 插拔、hotspot-recheck timer（每分钟兜底）。
#
# 2026-09-09 断网事故的安全不变式（改动前必读）：
#   1. AP 与 STA 并发共享 radio（#channels<=1），AP beacon 会把 radio
#      锁死在其信道——起在错误信道 = STA 永远连不上别的信道。因此
#      target_channel 无法给出确定信道时绝不起热点，exit 0 等下个触发点。
#   2. udev / dispatcher 上下文里同步执行会拖慢调用方的事件处理
#      （dispatcher 版曾被 NM 退出的 SIGTERM 杀死），检测到事件环境
#      即自重入后台执行。
#   3. 多入口并发由 flock 串行化。
#   4. 应急开关：/run/hotspot-disabled 存在时只关不开（tmpfs，重启自愈）。
#
# 变量可用环境覆盖，便于离线真值表测试；udev 与 dispatcher 环境
# 不含这些名字，默认值即部署值。只依赖 sh 内建与注入的绝对路径，
# 在 udev 的贫瘠 PATH 下也能运行。

# 后台化：自重入后立即返回，不阻塞 udev 事件队列或 dispatcher。

wifi_trusted() {
    conn=$("$NMCLI_BIN" -t -g GENERAL.CONNECTION device show "$WIFI_IFACE" 2>/dev/null) || return 1
    [ -n "$conn" ] || return 1
    [ -r "$AGE_IDENTITY" ] || return 1

hotspot_active() {
    "$PGREP_BIN" -x hostapd >/dev/null 2>&1

# iw link 输出只有 freq（MHz），按频段换算信道号：
# 2.4G: ch=(freq-2407)/5，5G: ch=(freq-5000)/5
sta_channel() {
    freq=$("$IW_BIN" dev "$WIFI_IFACE" link 2>/dev/null |
           "$SED_BIN" -n 's/^[[:space:]]*freq: \([0-9][0-9]*\)$/\1/p')
    case "$freq" in
        "") return 1 ;;
        *) if [ "$freq" -ge 5000 ] 2>/dev/null; then
               echo $(( (freq - 5000) / 5 ))
           else
               echo $(( (freq - 2407) / 5 ))
           fi ;;
    esac
}

ap_channel() {
    "$SED_BIN" -n 's/^channel=\([0-9][0-9]*\)$/\1/p' "$HOSTAPD_CONF" 2>/dev/null
}

# 目标信道——热点的唯一合法信道来源（安全闸）：
#   1. STA 已连接：跟随 STA 信道；
#   2. STA 未连接：扫描缓存里可见的 autoconnect WiFi profile 的信道
#      （按信号序取首个命中），让 NM 稍后自动关联时天然同信道；
#   3. 都没有：返回失败，调用方必须放弃本次动作。
# nmcli -t 会把值里的冒号转义为 "\:"，前后两种输出的转义形式一致，
# 故全程用转义形式匹配。不做子串 grep（"Office" 会误吞 "HomeOffice:"），
# 改为对扫描行按信号序逐行做字面前缀剥离 + 纯数字校验。
target_channel() {
    ch=$(sta_channel) && { echo "$ch"; return 0; }
    scan=$("$NMCLI_BIN" -t -f SSID,CHAN device wifi list ifname "$WIFI_IFACE" 2>/dev/null) || return 1
    [ -n "$scan" ] || return 1
    autoconns=$("$NMCLI_BIN" -t -f NAME,TYPE,AUTOCONNECT connection show 2>/dev/null |
                "$SED_BIN" -n 's/:802-11-wireless:yes$//p')
    [ -n "$autoconns" ] || return 1
    while IFS= read -r sline; do
        [ -n "$sline" ] || continue
        while IFS= read -r name; do
            [ -n "$name" ] || continue
            ch=${sline#"$name":}
            case "$ch" in
                ''|*[!0-9]*) continue ;;
                *) echo "$ch"; return 0 ;;
            esac
        done <<EONAMES
$autoconns
EONAMES
    done <<EOSCAN
$scan
EOSCAN
    return 1
}

stop_hotspot() {
    "$HERD_BIN" stop "$HOTSPOT_SVC" 2>/dev/null
    "$IP_BIN" addr flush dev "$HOTSPOT_IFACE" 2>/dev/null
    return 0
}

if [ -e "$DISABLE_SENTINEL" ]; then
    hotspot_active && stop_hotspot
    exit 0
fi

if on_ac_power && ! wifi_trusted; then
    ch=$(target_channel) || exit 0
    if hotspot_active; then
        ap_ch=$(ap_channel)
        [ -n "$ap_ch" ] && [ "$ap_ch" = "$ch" ] && exit 0
        # 目标信道变化（STA 漫游 / 出现可关联网络）：重启热点跟随
        stop_hotspot
    fi
    "$MKDIR_BIN" -p "${CHANNEL_FILE%/*}"
    printf '%s\n' "$ch" > "$CHANNEL_FILE"
    exec "$HERD_BIN" start "$HOTSPOT_SVC"
fi

hotspot_active && stop_hotspot
exit 0

type ifname

iifname "lo" accept

**** CachyOS LTS 内核

对标上游 linux-cachyos-lts 变体：CachyOS 官方预拼补丁的 6.18 LTS 源码 tarball（Cachy Sauce + EEVDF 调度器，无 BORE、无 LTO），nonguix =linux-6.18= 出构建配方，经 =customize-linux= 换源换配置。defconfig 取自 Testament 作者 hako 的 kernel-config 仓库 =defconfig_server= （钉 49c98a1，已在 6.18 线多机验证，钉在本仓 =source/files/kernel/defconfig-cachyos-lts= ），kconfig 片段把它调成桌面档并按设备裁剪。

策略：其他软件编译要快、内核性能优先、LTS 降低重编频率；升级与换机零摩擦。

内核配置自包含于 =source/files/kernel/= 目录，config.org 只 load 一行：

+ =linux-cachyos-lts.scm= —— 包定义自包含：版本与源（升级点）、defconfig 引用、通用桌面档（Cachy Sauce、-O3、1000Hz、preempt full、THP always、BBR、debuginfo 反选、Guix 沙箱与 initrd 必需符号、default-y 门控钉住）、机器拼合
+ =defconfig-cachyos-lts= —— pristine 的 hako defconfig，永不手改，只随上游 commit 更新
+ =machines/redmibook-pro-16-2024.scm= —— 本机硬件钉住（AX211/SOF-MTL/i915+xe/NPU/UVC/i2c-hid 触摸板/TBT4 等，防 defconfig 漂移）+ =machines/redmibook-trim.kconfig= 大类裁剪（1780 符号：非 Intel 无线/网卡/GPU/声卡、DVB 采集卡、SCSI 阵列、XEN/HYPERV/VMware 客体、CAN/NFC/ATM/ISDN、USB 串口、触摸屏/游戏杆、老平台驱动等，裸符号 = 反选，分组注释）

+ 换机：新建 =machines/<设备>.scm= （导出同名 =%machine-configs= ）与 =<设备>-trim.kconfig= ，改 =linux-cachyos-lts.scm= 里一行 load；本机裁剪依据（硬件清单）写在 machine scm 文件头
+ 升级点版本（如 6.18.49-1）：只改 =linux-cachyos-lts.scm= 的 =%cachyos-lts-version= 与 base32；hako defconfig 更新时重跑裁剪清单 diff 再核对
+ 裁剪符号若与 defconfig 漂移冲突，构建期 =verify-config= 会点名报错，按提示补列或删行即可收敛
+ =CONFIG_USER_NS=y= 必须保留：guix 构建沙箱依赖用户命名空间（在通用档）

不启用 BORE（2026-09-08 消融复核）：firelzrd 已发布精确适配 6.18.48 的 BORE 6.8.0 补丁（对 CachyOS 源需手工融合 fair.c 一处 hunk，与 Cachy Sauce 的 base_slice 分支共存），QEMU 消融实测吞吐无增益且 pipe 场景 -7.7%（超出噪声带），与 Phoronix 对 CachyOS BORE 变体的评测一致（其 geomean 亦不及默认 EEVDF）；交互响应收益无客观测量支撑，且 CachyOS 官方 LTS 已切回 EEVDF。维持 EEVDF，想再试时按 =kernel/AGENTS.md= 的消融流程复测。

消融落地（2026-09-08，按分层放置）：通用档关 SCHEDSTATS/SCHED_TRACER（桌面不用调度统计）并反选 hako defconfig 的 MAXSMP（发行档通用性遗留，把 NR_CPUS 钉死 8192 且连带 CPUMASK_OFFSTACK 堆分配位图，任何 ≤512 CPU 桌面机通用）；machine 层按本机拓扑关单节点 numa balancing（故障扫描纯开销）、NR_CPUS=64（22 线程）——消融 fork +1.7%、syscall +4.6%，组合终验 fork +2.3% 无倒退。另实测 =spectre_bhi=off= 无收益（MTL 的 BHI 缓解是 BHI_DIS_S 硬件位，近零开销），cmdline 无需动。

不启用 ThinLTO/AutoFDO（CachyOS 主线默认是 Clang ThinLTO + AutoFDO/Propeller）：Phoronix/Google 数据显示 Clang+LTO 相对普通 GCC 约 +5%，但相对本配置的 GCC -O3 + native 基线增量约 1-3% 且负载相关（Gentoo wiki 明确可能持平或倒退）；clang-LTO 内核还要求外部模块同链 clang 工具链（v4l2loopback 会被波及）；AutoFDO 依赖 perf LBR 采样与 autofdo 工具链（guix 频道无此包）加两遍式 profile 基建。收益与复杂度不成比例，留作后续可选实验。

下载 tarball 后 =guix hash <tarball>= 取 base32。tarball 的 Makefile 决定 =uname -r= （6.18.48），包版本号 6.18.48-2 只是元数据。

**** 指纹识别栈

本机指纹传感器为 Goodix =27c6:689a=（match-on-chip 型，出厂固件，无需额外固件文件）。上游 libfprint 的 =goodixmoc= 开源驱动自 v1.94.9 才认领该 PID，而 Guix 上游停在 1.94.5，设备枚举时无人认领 —— fprintd 报 "No devices available"，这就是 Guix 下指纹不可用的根因（NixOS 的 libfprint ≥1.94.9 故可用；网传 Goodix 闭源 TOD 驱动只覆盖 533C/539C/550a 等其他型号，与本机无关，勿装）。

方案：libfprint 升至 1.94 维护线 =1.94.100=，fprintd 1.94.2 → 1.94.5（其构建要求 libfprint ≥1.94.9，两包必须同步升级）。相对上游包定义的全部变体点：

+ 1.94.7 起 URU4x00 驱动由 NSS 改用 OpenSSL ≥3：输入替换 =nss → openssl=，原为 lib/nss 设 rpath 的 configure flag 一并移除（OpenSSL 库位标准，ld-wrapper 自动补 RUNPATH）
+ eudev 的 pkg-config 故意报 systemd 兼容版本（251），libfprint 的 =udev_hwdb=auto= 逻辑误判"systemd ≥248 已内置 autosuspend hwdb"而跳过安装——Guix 上必须 =-Dudev_hwdb=enabled= 强制装（仅多一条无害 warning），否则 autosuspend 条目全系统缺失
+ fprintd 1.94.5 把 libsystemd provider 做成 meson 选项：=-Dlibsystemd=libelogind= 取代旧 =patch-systemd-dependencies= 补丁（新版 meson.build 写法变了，旧正则会匹配失败）
+ 1.94.5 的 pam_wrapper 降为 =required:false=、Python 测试依赖检查只发 warning：旧 =ignore-test-dependencies= 补丁整体删除
+ =patch-output-directories= 保留：相关行的 meson.build 写法未变，正则仍命中

系统侧接线（desktop-services 板块）：=fprintd-service-type= 换新包（fprintd 守护进程经 D-Bus 按需激活，非 shepherd 常驻服务，=herd= 里看不到是正常的）；PAM transformer 把 =pam_fprintd.so= 以 sufficient 插到 pam_unix 之前（对标 NixOS fprintAuth 语义，指纹失败回落密码）；libfprint 的 autosuspend hwdb（含 =27c6:689a= 条目）挂 =udev-service-type=。升级仅改两个 version 与对应 hash（=guix hash -f nix-base32=）。

#+name: usb-power-watch
#+begin_src sh :tangle ../tmp/usb-power-watch
#!/bin/sh
# Auto-generated by Guix config.org.

# 熄屏断电守护：轮询背光 bl_power（普通用户可读，灭屏 0→4），
# 全灭持续 THRESHOLD 秒 → 挂起清单端口上的 USB 设备；复亮立即恢复。
# 覆盖手动 power-off-monitors、合盖关屏等一切熄屏路径；外接无
# 背光屏不产生信号，取向安全侧（不断电）。只读 sysfs，不依赖
# 图形会话——避开 graphical-session 启动竞态导致的拉起失败。
THRESHOLD=120
INTERVAL=30

# 断电端口清单：挂在这些物理 USB 口上的设备（含 hub 子树）无论
# 是什么一律挂起，清单外端口不碰。名称为 /sys/bus/usb/devices/
# 下的设备名（bus-port）；同一物理口的 USB2/USB3 视图各占一个名
# 字（3-5 与 4-5 为同一口），空口列上无副作用。3-2 是外接 dock 的
# USB2 视图，键盘/鼠标等 USB2 外设挂其子树；USB3 视图 2-2 不列入
# ——网卡在 2-2.4，避免熄屏断网（USB3 设备不占 USB2 视图，互不影
# 响）。挂起的 HID 收到输入由内核自动恢复，事件不丢；不要把承
# 载远程链路的设备插进清单口。依赖 udev 规则
# 95-usb-power-control-perms.rules 已把 power/control 放开为 0666，
# 本脚本以普通用户身份运行。
PORTS="3-2 3-5 3-6 4-5 4-6"
in_ports() {
    for p in $PORTS; do
        case "$1" in "$p"|"$p."*) return 0 ;; esac
    done
    return 1
}

 # 清单端口熄屏写 auto、亮屏写 on，不看设备当前值也不记挂了谁：
 # 写入幂等，熄屏期每轮都执行，新插设备下一轮即被覆盖。
 set_ports() {
     for dev in /sys/bus/usb/devices/*-*; do
         case "${dev##*/}" in *:*) continue ;; esac   # 跳过接口目录
 [ -f "$dev/power/control" ] || continue
 if in_ports "${dev##*/}"; then
     echo "$1" > "$dev/power/control" 2>/dev/null
 fi
done
 }

  off_since=0
  state=on
  while :; do
      lit=0; dark=0
      for b in /sys/class/backlight/*/bl_power; do
          [ -r "$b" ] || continue
          if [ "$(cat "$b" 2>/dev/null)" = 0 ]; then lit=1; else dark=1; fi
      done
      if [ "$lit" = 0 ] && [ "$dark" = 1 ]; then
          now=$(date +%s)
          [ "$off_since" = 0 ] && off_since=$now
          if [ $((now - off_since)) -ge $THRESHOLD ]; then
              set_ports auto; state=off
          fi
      else
          off_since=0
          if [ "$state" != on ]; then set_ports on; state=on; fi
      fi
      sleep $INTERVAL
  done
#+end_src

* Live ISO

这里定义自研 Live ISO 的 =operating-system=, 与主机 =%system= 完全独立.

=blue build-iso= (见 blueprint.scm build-iso-command) 会 tangle 出 =tmp/live-iso.scm=, 再调 =tools/build-image.scm= 生成 iso9660 镜像. label 内嵌构建日期：有意放弃逐字节可复现，换取镜像版本的直观辨识.

+ =desktop= (主要, XFCE 桌面环境 + lightdm 自动登录 live 用户, 默认 Wayland 会话 via labwc).

** 重要约束 (改本节必读)

- tangle 目标 =../tmp/live-iso.scm= 绝对不能复用 =../tmp/config.scm=, 否则 =%live-installation-os= 会污染主机配置 (见 docs §9.4.5 陷阱 1).
- =<<live-modules>>= 只在本节被 =live-installation-os= 引用, 绝不能塞进主 =<<modules>>= 块 (会污染 tmp/config.scm).
- =blue check= 不做 cross-tangle 验证, 改完务必 =tail tmp/live-iso.scm= 确认末行是 =%live-installation-os= (裸值).

** 系统主体

基础 OS 继承 guix core 的 =make-installation-os=（默认 grub hybrid 引导；仅维护 x86_64 镜像，无 aarch64 计划）。

Live 环境只用精简频道（guix + nonguix，参照 Testament minimal.scm 的 channels-with-nonguix）：ISO 不需要 bluebox/jeans/rosenthal 这些主机的建站频道，装机后由 =blue rebuild= 重建完整频道集。它经 modify-services 写进 guix-configuration 的 channels 字段，让 Live 环境的 =/etc/guix/channels.scm= 预置 nonguix， =guix pull= 直接拉到。与 =<<guix-substitutes>>= 的关系：substitutes 管「下载二进制」（4 套镜像），channels 管「拉源码频道」（pull 用），两者互补不冲突。

=skeletons= 把 =source/files/livecd= 整个目录树平铺进 =/etc/skel= ：skeleton-directory 对每个条目执行 copy-recursively，target 为 ="."= 会把源目录内容（保留 .config/... 相对结构）平铺到 home 根，新增/删除文件只需改 livecd/ 目录、无需在此打表（local-file 的 =#:recursive? #t= 让整个目录作为一个 store 项导入）。必须保留 %live-base-os 的默认 skeleton（尤其 zsh 登录所需的 .zprofile）——skeletons 字段覆盖继承值，不会自动合并。

包列表里 =labwc= 是 =startxfce4 --wayland= 的默认合成器依赖； =wlr-randr= 供 XFCE 4.20 Display 设置面板在 Wayland 下调缩放/分辨率（底层走 wlr-output-management 协议，需要它作为客户端工具）。

services 侧：elogind 负责 PAM session 管理（创建 =/run/user/<uid>= 、提供 loginctl ），labwc 的 libseat logind 后端也通过它获取 seat。greetd 开机直接 autologin live 用户进 xfce-wayland 桌面：greetd 直接 execl 会话命令，不走 xinitrc/session-wrapper（lightdm 正是因此无法启动 wayland 会话）； =greetd-user-session= 编译成 Guile execl（不查 PATH），command 必须用 =file-append= 给出 store 绝对路径； =xdg-session-type "wayland"= 加 =xdg-env?= 让脚本设好 =XDG_SESSION_TYPE= 和 =XDG_RUNTIME_DIR= 后再 execl。autologin 退出后由 agreety 文本登录兜底。
