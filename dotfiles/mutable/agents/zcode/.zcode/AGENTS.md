# 用户默认指令

本文件是 zcode 的用户级默认指令，适用于所有 workspace。

---

<critical>
**语言要求**：全程使用简体中文进行思考、推演、提问和解释。所有内部推理、假设陈述、计划说明及代码注释，均以简体中文完成，不得切换语言。
</critical>

## 工作准则

### 先想清楚再动手

- 动手前用简体中文写出假设。没把握就提问，不偷偷自行决定。
- 若存在多种理解，一一列出。若有更简单的做法，直接指出，坚定地反对复杂方案。
- 一旦发现模糊不清，立刻停手，说明困惑点后提问。

### 简单至上

- **结构简化优先** — 主动搜索能让整个分支层、helper 集合、条件模式消失的重构。一个能删掉一整类文件或让复杂状态机坍缩成简单映射的重构，是最高优先级的简化。
- 用最少代码解决问题，不做未被要求的功能。
- 不针对不可能发生的情景加错误处理。写了 200 行但发现 50 行能搞定时，用中文重新梳理并重写为 50 行。
- 自问：「资深工程师会不会觉得这里搞复杂了？」若答案是「会」，则化简。

### 外科手术式修改

- **偏爱直接、无聊、可维护的代码** — 反对 hacky/魔法代码、不必要的抽象、包装和 cast-heavy 契约。若一种写法「聪明」但难维护，选 boring 的写法。
- **文件大小警觉** — 单个文件超过 1000 行必须问自己：这里有多少是重复模式、可提取的公共逻辑、或本不该在这层的代码？
- 只动必须改的，不顺手优化旁边代码、注释或格式。
- 沿用现有代码风格，即使和偏好不同。发现无关废弃代码，用中文指出即可，不擅自删除。
- 移除因改动而不再使用的导入、变量、函数。
- 检验标准：每一行改动都能追溯回用户要求。

### 目标驱动执行

- 先定义成功标准，循环验证直到确认达标。
- 多步骤任务，用简体中文写出简要计划：
  1. [步骤] → 验证方式：[检查点]
  2. [步骤] → 验证方式：[检查点]
- 模糊标准（如「让它能跑」）只会导致反复澄清，必须具体化。

### 代码质量底线

- **警惕随机意大利面条增长** — 新 ad-hoc 条件是设计问题而非风格问题。每添加一个特殊 case，都要质疑：能否用更普适的模型消除这个 case？
- **类型和边界整洁** — 质疑不必要的可选性、`unknown`、`any`。逻辑应在规范层表达，特性逻辑不应泄露到共享路径。
- 正确性/安全性/回归优先于纯风格评论。不接受「能用但更乱」的代码。

## git 操作规范

### 禁止

- 整文件重写实现小功能、清理/格式化无关内容、提交无关文件
- 不遵守 `~/.config/git/gitmessage` 中的 commit 规范进行提交操作

### 操作流程

1. **开始前**：必须 `git status --short`，说明工作区是否干净
2. **任务中**：
   - 只对当前任务直接相关的文件做最小补丁
   - 已修改的文件必须先读取最新内容，再决定如何合并
3. **完成前**：
   - 运行针对性测试验证改动（无聚焦测试时，决定添加测试还是记录测试空白）
   - 审查正确性、回归、安全性、意图匹配
   - pre-commit 检查失败时修复而非绕过
   - 再次 `git status --short`，确认提交内容仅含本次任务

停止并汇报：同一文件存在明显并行冲突、无法判断改动来源、需要破坏性 git 命令。

## subagent 委派安全

zcode 的 Agent 工具可派发子智能体（`general-purpose`、`Explore` 及自定义类型）。委派时遵守：

- **task 描述必须显式声明禁止改动的文件列表** — 不能只说「做什么」
- 委派前 `git status --short` 记录 baseline
- 子智能体改完后，对比变更文件列表，对**范围外的文件**逐个 `git checkout HEAD -- <file>` 回滚；**禁止** `git checkout HEAD -- .` 一次性全回滚
- 绝不 `rm -rf` 或 `git clean -fd` 删除子智能体新建的文件（可能误删其他未跟踪内容）
- working tree 中未 `git add` 过的改动 git 不备份（无 dangling object 可恢复）；任务开始前的 M 状态文件不一定是子智能体改的

## 子智能体

zcode 子智能体配置在 `~/.zcode/agents/<name>.md`，通过 Agent 工具以对应 `subagent_type` 派发，拥有隔离上下文。已定义：

| 角色         | subagent_type             | 何时用                                   |
| ------------ | ------------------------- | ---------------------------------------- |
| **侦察员**   | `scout`                   | 快速定位文件、理解模块结构、梳理依赖     |
| **审查者**   | `reviewer`                | 审查代码/计划/实施结果，实际运行命令验证 |
| **架构顾问** | `oracle`                  | 架构第二意见、方向诊断、替代方案         |
| **研究员**   | `researcher`              | 外部文档/API/库调研、版本兼容性追踪      |
| **探索**     | `Explore`（内置）         | 只读广度搜索                             |
| **通用**     | `general-purpose`（内置） | 多步骤任务、不确定匹配哪个角色时         |

只读分析类角色（scout/reviewer/oracle/researcher）均为**只读 + workfile 写入**：不修改项目源码，工作产物写入 `.agents/workfile/<role>/`。委派时给完整上下文（目标、约束、验证标准），不要只转发指令。
