# 只读提炼 worker 任务书骨架

把 `<...>` 占位换成实际值。一次派 N 个时，这份文本在每份任务书里重复（子 agent 看不到彼此的任务）。

```text
编号 <C1>。阅读文件：<绝对路径列表，含每个文件体积>

【背景】<语料是什么、谁产的、时间范围；用户的工作领域与技术栈关键词>。
文件是已压缩的导出文本：<格式说明，如「消息以 `* 标题` 开头，正文含 USER:/ASSISTANT: 段，reasoning 与 tool 占位已剔除」>。

【目的】为 <目标库/报告> 做 <周期> 回顾，提炼「值得沉淀的持久经验」。
不要：任务进度流水账、TODO、拼写/语法修正、一次性任务细节。

【产出格式（final answer 直接给出内容，不要只说已完成）】
1) threads：工作主线，每条 ≤60 字，含平台与结果
2) cards：≤<N> 张最高价值候选，字段：
   title（结论式标题，含具体技术对象）/ category（合法取值：<列出>）/ tech（宽口径域：<列出>）
   / type（<列出>）/ entry（note=查到的知识，mistake=踩坑，ascended=多轮试错后的正确做法）
   / summary（一句话结论）/ body（正文，含 <章节结构>，代码块用 <标记>）
   / evidence（日期 + 平台 + 文件路径 + 原文 1-2 句）
   / dedupe（先跑 `<查重命令>` 查重，命中就写 `已有: <ID> <标题>`，不要重复提议）
3) prefs：可跨会话复用的用户偏好或纠正，≤3 条，各附证据
4) env_improvements：agent 工作环境改进候选（导航指针 / 自动化检查 / 编码规范 / steering 冗余 /
   工具调用经济性 / no-op 指令 / 信息获取通道），≤3 条，写清「观察 → 建议 → 证据」

【硬规则】
- 只用文件里真实出现的内容，不推测；不确定标 `存疑`
- 只收非显而易见且可复用的经验；语言与格式：<要求>
- **不要写入任何库/文件**（只提议，不落库）
- 大文件用 python 分块读（一次约 40KB），不要整文件 read
- 最终 JSON 另存 <工作目录>/<编号>.json
```

## 派发时一并给的东西

- 文件绝对路径（不是相对），以及每个文件的大小
- 合法 category / tech / type 取值清单（直接取现有库的枚举，不要让它猜）
- 查重命令的确切写法（含必要的前缀环境变量，如 `AGENOTE_AGENT=<agent>`）

## 反例（会让提炼质量崩掉）

- 「好好总结一下」（没有 schema → 回来的是散文）
- 「尽量多找点」（没有上限 → 回来的是流水账）
- 「顺便帮我改一下 X」（只读任务混入写操作 → 权限边界与产物都脏了）
- 不要求落盘 JSON（摘要被截断后主会话拿不到中段取舍）
