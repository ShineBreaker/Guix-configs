# 语言风格（语言风格章）

源：语言风格/ 六节。上游该章案例节多为「欢迎补充」，正文以规则条目为主。

## 对话式

- 语气应平易近人、直截了当，推荐对话式，如「你可以……」。内容本身常枯燥，过于正式的语言更乏味。
- 对话式 ≠ 日常口语：口语冗长啰嗦、缺乏逻辑，编写时须极力避免。
- 案例节上游为空（欢迎补充），无现成反例可引。

## 客观礼貌

- 客观传达技术信息，不是在推销产品，否则易引起反感。
- 保持友好礼貌，不显强硬粗鲁；指导性文档保持冷静、客观、简洁。
- 应避免拟人手法（把人的特征、情感、动作赋予无生命物体）。
- 玩笑：偶尔一次可取（展现作者/公司个性），但首要目的是传达技术信息，不能为追求轻松让读者不明所以。
- 不要使用反问句（让读者感觉被质疑和挑战）。
- 不要轻易使用感叹句；感叹可能让读者感到被责备。仅用于特别强调场景，例：某操作可能永久删除数据、需强烈警示时。
- 不要轻易使用「请」「抱歉」，除非真的对读者造成了困扰。
- 避免过分亲切的称呼（如「亲爱的」）；建议始终用「您」或「你」。

## 简洁清晰

- 核心操作：**完成初稿后再通篇读一遍**，删去所有对表达意思没有明显作用的字、词、句，在不影响表达效果前提下把文案压到最短。
- 禁止啰嗦冗长；禁止逻辑混乱。
- 同一文档中勿重复表达同一事物。
- 尽量用**主动时态**，尤其要**阐述清楚主语和宾语**。

## 通俗易懂

- 不推荐使用只有特定人群才了解的语词。
- 不推荐行话黑话、俚语、脏话。上游反例：「魔改」（应写「做特殊的优化」）、「CPU 打到 60%」（应写「CPU 使用率为 60%」）。
- 不推荐网络流行语及故意谐音错别字：「墙裂」「童鞋们」。
- 案例一：【错误】「欢迎各位 TW 们补充……」→【正确】「欢迎各位文档工作者补充……」；TW 是 Tech Writer（技术文档工程师）的缩写，属从业者才知道的缩略语，为更广泛受众应改写。

## 用户导向

- 充分考虑文档**受众的技术水平分布**及实际操作中可能出现的问题，尽可能全面、清晰地把技术信息普及给大众。
- 操作型技术文档除语言审校外，建议做「文档可用性测试」：由一位无技术背景测试人员照文档完整操作；成功则通过，失败则继续修改。
- 操作型文档不仅要准确描述步骤，还要设身处地考虑用户可能面临的问题：
  - 需输入的信息 → 提供输入格式等详细要求
  - 报错信息 → 提供解决报错的可选操作
  - 为方便排查错误 → 提供详细的错误码速查列表

## 用词恰当

用词恰当 = 用词正确 + 用词统一。分禁用词、常用词、易用错的词三块。

### 禁用词

参考新华社 2015 年 11 月《新华社新闻报道中的禁用词（第一批）》。技术文档虽非新闻报道，但作为技术传播领域的大众传播物，应同样考虑传播影响；避免冒犯性词语能为个人或公司省掉不必要的麻烦。适用于技术文档的要点：

- 报道事实特别是产品、商品时，不用「最佳」「最好」「最著名」「最新技术」「最高水平」「最先进水平」等强烈评价色彩词语。
- 对身体伤疾人士不用「残废人」「独眼龙」「瞎子」「聋子」「傻子」「呆子」「弱智」等蔑称，应用「残疾人」「盲人」「聋人」「智力障碍者」。
- 医药报道禁用「疗效最佳」「根治」「安全预防」「安全无副作用」；药品报道禁用「药到病除」「无效退款」「最新技术」「最高技术」「最先进制法」「药之王」「国家级新药」。
- 涉及中国领土、主权和港澳台的词汇须正确：**不得将台湾、香港、澳门与中国并列提及**（不用「中港」「中台」「中澳」，可用「内地与香港」「大陆与台湾」「京港」「沪港」「闽台」）；不建议将中国某地区与其他国家并列。
- 不用「哇噻」「妈的」等俚语、脏话、黑话；网络缩略脏语「SB」「TMD」「NB」等也不得使用。引语中不得不使用时应用括号加注说明内涵。

### 常用词

指经常使用的人称代词、指示代词、语态助词、操作动词、技术术语等。

1. **必须用对「的」「地」「得」**：形容词/名词（代词）+ 的 + 名词（如「迁移到其他的存储节点上」）；副词 + 地 + 动词（如「显式地使用事务」）；动词/形容词 + 得 + 副词补语（如「不宜调得过大」）。
2. **必须明确「其」「该」「此」「这」等代词的指代**，不造成歧义。错误：「构建 PD、TiKV 或 TiDB 的镜像，需要将其 `image` 字段留空。」正确：「……需要将相应镜像的 `image` 字段留空。」
3. **不建议使用表程度、强调语气的词**（词义模糊或显主观绝对），应用具体数据或实例代替：
   - 表程度：较多、较好、完全地、基本地、决定性的、最后的、仅仅、事实上、值得注意的。错误「很好地提升了性能」→「性能提升了 50% 或者延迟从 10ms 降为 1ms」。
   - 表量：有些、非常、大量、一些、少许、部分、几乎、数倍。错误「执行时间会是关闭该变量的数倍」→ 说明影响因素并举一两个具体实例（硬件为 …、PD 参数配置为 … 时是 … 倍）。
4. **不建议使用冷僻、生造或文言文词语**，应用现代汉语常用表达。错误「这是唯二的快速启动的方法」→「这是仅有的两种快速启动的方法」。
5. **禁止使用过多形容词修饰名词**。错误：DDL JOB 恢复那句（修饰词组堆叠、拗口费解）→ 适当断句明晰语义，拆成「首先找到……并且……再对这张表进行恢复」。

用词统一：

1. **必须保证全文人称代词一致，人称不能反复改变**：
   - 指称读者/用户推荐「您」或「你」，两者皆可，**禁止混用**。
   - 代指文档作者推荐「作者」「文档作者」等第三人称，**不推荐用「我」**（显主观、引起不必要的疑惑）。
   - 可用「我们」代称整个公司，但建议少用。
2. **建议尽量使用主动语态，不使用被动语态**。错误「假如此软件尚未被安装」→「假如尚未安装这个软件」。
   - 【注意】汉语**被字句**与英语**被动式**含义不同：英语被动式为避免提及施事者，汉语被字句往往带负面含义；中文用主动语态还能帮助**明确句子主语和宾语**，对后续技术翻译极为重要。

### 易用错的词

上游按字母表列了高频易错词（参考《常见语言文字错误防范手册》《现代汉语词典》第 7 版、《现代汉语规范词典》）。高频陷阱：

| 易混 | 判定 |
| --- | --- |
| 的/地/得 | 形+的+名；副+地+动；动/形+得+补 |
| 安装/按装 | 安装（无「按装」） |
| 包含/包括/包涵 | 包含=里面含有（部分与总体不可分解）；包括=总体中含有（总体由部分组成）；包涵=客套请求原谅 |
| 包修/保修 | 包修=总揽负责修理；保修=按规定免费修理 |
| 本义/本意 | 本义=字词原始意义；本意=原来的意思意图 |
| 必须/必需 | 必须=副词「一定要」；必需=动词「一定要用」，API 文档中参数是否「必需」对应 Required |
| 标明/表明 | 标明=用文字符号标记（书面）；表明=清楚明白地表示（可书面/图表/口语） |
| 查看/察看/检查/检察 | 查看=以检查为目的；察看=以观察考察为目的；检查=为发现问题而用心查看；检察=检察机关法律监督 |
| 长亮/常亮 | LED 一直亮用「常亮」 |
| 大致/大概 | 大致偏肯定；大概偏猜测 |
| 登录/登陆 | 登录=login 注册进入；登陆=到达陆地/打进市场 |
| 预订/预定/制订/制定/审订/审定 | 预订=预先订购；预定=预先规定约定；制订=拟订草拟；制定=确定下来正式实施；审订=查阅修订；审定=审查认定 |
| 反映/反应 | 反映=表现客观实质/告诉上级；反应=受刺激引起的活动 |
| 分/份 | 份=量词、省县年月后、股份份额、身份等；分=成分、分内分外、知识分子 |
| 分辨/分辩 | 分辨=区分辨别（思维）；分辩=分说辩解（言语） |
| 含义/含意 | 含义=明确客观的意义；含意=隐含主观的意义 |
| 好像/好象 | 好像 |
| 即/既 | 即=到、靠近（即使=假设前提未发生）；既=已经（既然=前提已发生） |
| 记录/纪录 | 记录=记下；纪录=一定范围最高成绩 |
| 截止/截至 | 截止=不及物，日期放前面；截至=及物，后必须带宾语 |
| 界限/界线 | 界限=抽象分界/限度；界线=地区间具体分界线 |
| 其他/其它 | 用「其他」 |
| 券/卷 | 入场券、优惠券 |
| 权利/权力 | 描述版权信息只用「权利」 |
| 稍后/稍候 | 「服务器正忙，请稍后再试」用稍后；「软件正在安装，请稍候……」用稍候 |
| 声明/申明 | 声明=公开宣布态度/事实真相；申明=申述解释立场观点 |
| 消/销 | 消失除去义通用，但首选「取消」「撤销」 |
| 阈值/阀值 | 阈值 |
| 以至/以致 | 以至=延伸（直到）；以致=不良结果（因果） |
| 粘/黏 | 粘=使连接（粘贴）；黏=具有连接性能（黏性、黏合） |
| 账号/帐号 | 账号（无「帐号」） |
| 作/做 | 抽象/书面色彩重用「作」；具体/口语色彩重用「做」；分辨不清时宁可用「作」不用「做」（吕叔湘） |
