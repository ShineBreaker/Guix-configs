# blind-review — 盲审机制

## When to Use

- 用户说「盲审 / 去掉注释审查 / blind review / 匿名审查」
- reviewer 不该看到作者的自我解释，需要独立判断代码是否自洽
- 剥注释的副本怎么生成、怎么自检、怎么避免剥一半

不适用：常规代码审查（走 `code-reviewer`）、只想隐去作者身份的 diff 审查（改 git author 即可，不必动代码）。

「去掉注释让 agent 审查」是一个**特定工具**，不是默认审查方式。先判边界，再动手。

## 适用边界（每次先问这个）

默认**不要**剥注释。注释本身就是被审对象——它记录「为什么不能用 X」「这个分支为什么必须留着」。剥掉后 reviewer 只会正确地报告「意图不明」，那是你人为制造的信息缺失，不是新发现。

值得做盲审的只有一个窄场景：**独立验证「代码离开作者解释后是否自洽」**——不靠 README / 注释 / commit message 的自我说明，逻辑本身是否站得住。

用户的目标若是「避免 reviewer 被作者说服」，先说明上面这条，让他重新选，不要直接开干。

## 流程

1. **定边界**：一次问全（不逐题追问）——盲审要验证什么 / 是否同时给 reviewer「原文件 + 剥离差异」/ 产出是 skill、CLI 还是脚本。用户不在场（clarify 超时）时不要自行扩范围，把状态交代清楚即可。
2. **生成副本**：位置保留式剥离。
3. **自检**：断言不变量，不硬编码期望字面量。
4. **校验检测器**：用已知答案的样本证明「残留检测」本身是对的，再让它下结论。
5. **交付**：副本 + 原文件 + 差异说明一并交 reviewer。派发时显式告知「输入被变换过、哪些信息被移除」，否则 reviewer 会把缺失当缺陷反复猜。

## 位置保留式剥离

把注释字符替换为**等长空白**（保留换行），使副本的行号列号与原文件一致——reviewer 报的 `path:42` 能直接对回原文件，不需要映射表。

副本只收语言表内的源文件。README / docs / 配置 / lock 是作者的散文，属于盲审要隐去的信息，一律不进副本。

## 按语言接真实解析器（硬规则）

**不要用字符级引号配对判断注释边界。** 真实代码里它必错，且错法是静默的：

- Scheme 注释里的 `` `symbol' `` 反引号被当成字符串起点 → 引号状态错位，错位点之后几百字符的 `;;` 注释全被当成字符串内容吞掉；
- JS 模板串 `` `...${dir.size}` `` 的 `` ` `` 让扫描器跳到下一个反引号才算字符串结束 → 中间的注释被吞；
- JS 正则字面量 `/^\s*=\s*'([^']*)'$/` 里的引号同样造成错位。

已验证可用的解析入口与最小代码见 `references/comment-stripping.md`。

**首选 Emacs `syntax-ppss`**：一条命令覆盖 py / el / scm / js / ts / sh 六类，
比按语言接解析器省事，脚本在 `scripts/blind-strip.el`。

Emacs 没有对应 major-mode 的语言（YAML / TOML / C 系 / Go / Rust 等），
**明确标 UNVERIFIED / 不支持**，不要交付一个手写扫描器顶替。剥一半比不剥更危险——reviewer 会以为看到的代码就是全部。

## 自检与检测器校验

- **自检断言不变量**：行数守恒、逐行宽度守恒、指定注释内容消失、指定字符串内容原样保留。不要硬编码期望输出字面量——手数空格必错，会让人误判实现有 bug 而去改正确的代码。
- **残留检测的正则本身会误报**：CSS `#id` 选择器、`#include`、shebang、heredoc 里的 `;;`、Scheme `#f`/`#t` 都会被 `^\s*(#|//|;)` 命中。先用已知答案的样本校准检测规则，再让它下结论。
- **检测器结论与肉眼读档不一致时，两边都不信**，回到原始字节重新推导（用 `repr()` 逐行看，不要靠 `cat` / `cat -A` 的视觉判断——空白行在视觉上和有内容行难以区分）。
- **检测器误报是已知事实，不是缺陷**。别写「检测器不该命中这些行」的断言——它必然命中。该断言的是**定性规则**：定界符后紧跟非空白字符（`#progressBar`、`#include`、shell case 的 `/*)`）说明不是注释。

## 验证

`scripts/verify-blind-strip.py` 覆盖边界样本、检测器校准、真实仓库形状守恒：

```bash
python3 scripts/verify-blind-strip.py --repo <仓库路径>
```

改完 `scripts/blind-strip.el` 必须重跑，产出 `N/N PASS` 才算完成。

## Pitfalls

- 交付前必须**量化残留面**：按扩展名统计「剥离后仍以注释标记开头」的行，再逐个定性，不能只跑一个 grep 就宣布干净。
- **残留检测器自己会误报，且误报率很高**。已确认的误报源：CSS `#id` 选择器、`#include`、shebang、heredoc 内的 `;;`、Scheme `#f`/`#t`、shell `case` 的 `/*)` 分支模式、Python 三引号字符串里的 CSS `/* */`。判定真残留前先用 `repr()` 逐行看原始字节，不要靠 `cat` / `cat -A` 的视觉判断——空白行和有内容行在视觉上难以区分。
- **形状漂移逐个查**：真实仓库里会混进二进制或生成物（如 `.go` 后缀的编译缓存），行数都不同。先确认该文件是否该进副本，再决定剔除还是标记，不要当作 bug 去修。
- 自检用的期望字面量写错时，先怀疑自己手算的期望值，再怀疑实现。
- **批量跑必须检查 stderr 里的 `Error:`**。mode 未加载（如 `typescript-mode` 不随 Emacs 分发）时 `funcall` 报错，输出被 backtrace 截断成十几行——不查 stderr 会以为剥离成功，实际内容几乎全丢。
- **`subst-char-in-region` 不能用来替换成空格**：它要求新旧字符字节长度相同，注释里的中文与制表符（多字节 UTF-8）会让它直接报错。用 `delete-char` + `insert " "`，并从后往前处理以免位置移动。
- **不能边遍历边改文本**：修改 buffer 会让 `syntax-ppss` 缓存失效，块注释闭合后 `nth 4` 仍报非 nil，后半文件被误清空。先收集位置，再统一替换。
- `--batch -l` 下 `argv` 含 `--` 分隔符，用 `(pop argv)` 取值会连带把它传给下游；按索引取并过滤掉 `--`。
- 被 `load` 复用的脚本不要在主程序里 `kill-emacs`，否则探针脚本一加载就退出。
