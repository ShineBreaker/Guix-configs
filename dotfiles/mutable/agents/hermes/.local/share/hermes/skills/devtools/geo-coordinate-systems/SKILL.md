# 中国地理坐标系：判定、转换、落地口径

同一块地有三套坐标并存，数据源常常不写自己是哪套：

| 坐标系 | 谁在用 | 相对 WGS-84 的偏移量级（华南一带） |
| ------ | ------ | ---------------------------------- |
| WGS-84 | GPS / OSM / 国际标准 | 0 |
| GCJ-02（火星坐标） | 高德 / 腾讯等国内合规地图 | 约 500–700 m |
| BD-09（百度坐标） | 百度系，含经百度系录入或抓取的政务与第三方数据 | 约 1.1–1.3 km |

**不要默认「国内数据 = GCJ-02」**：政务/第三方源常常是 BD-09（百度系产物）。
两者表面偏移都是数百米到公里级，单点肉眼比对分辨不出来。

## 判定：同名点位三假设残差统计

1. 取样：**点状明确、同名唯一**的条目（博物馆类最佳），n ≥ 5，分散在同一数据源的不同地区。
2. 取对照真值：OSM（即 WGS-84）。Overpass 查询必须 **bbox 限定 + 名称精确匹配**
   （`["name"="全名"]` 或 `~"^全名$"`）——模糊匹配会命中同名异地（搜一座山的名字，
   能命中百公里外的同名山峰），污染统计。
3. 对每个样本算「到 OSM 同名点的距离」，分别按三种假设取中位数：
   直接取值 / gcj2wgs 换算后 / bd2wgs 换算后。
4. 判读表：

   | 直接 | 假设 GCJ-02 | 假设 BD-09 | 结论 |
   | ---- | ----------- | ---------- | ---- |
   | ~1.1 km+ | ~0.9 km（仍大） | **< 50 m** | 数据是 BD-09 |
   | ~600 m | **< 50 m** | ~1 km | 数据是 GCJ-02 |
   | **< 50 m** | — | — | 数据是 WGS-84 |

5. 交叉验证：找同一地点暴露两套坐标值的来源（部分旅游平台 POI 页同时给
   `googlePoint` / `baiduPoint` 字段），两值分别解码到 WGS-84 应收敛到同一点（< 100 m）。
   注意此类页面标称的「google 坐标」实为 GCJ-02，不是 WGS——判读时以解码一致性为准。

## 转换

- 工具：`scripts/coord_convert.py`（bd2wgs / wgs2bd / gcj2wgs / wgs2gcj / bd2gcj / gcj2bd
  六向互转，默认预演，`--write` 落盘，`--selftest` 跑 round-trip 自检）。
- **GCJ↔WGS 用迭代求逆**：单次加减近似只有米级精度；迭代 5 次可压到 < 10 cm。
- **BD↔GCJ 用标准偏移式**（对 x−0.0065 / y−0.006 做 z/θ 重投影），再与 GCJ↔WGS 组合成 BD↔WGS。
- 转换后必须自检：round-trip（wgs→bd→wgs）残差应为 cm 级，超过 1 m 说明实现有误。
- 境外坐标没有 GCJ/BD 变体（偏移公式只在中国境内有效），直接用 WGS-84；
  国内 + 境外混合的数据统一到 WGS-84 最省事。

## 落地口径

- **一张表内部统一一套坐标系**。多批次来源不同时，入库时就转换到目标口径。
- 保留多套口径时（如展示池 WGS-84 + 底座表保留原始 BD-09），在数据 README 写清：
  哪张表用哪套、为什么、以及一条可复制的转换命令。只写「有坐标」不算交代。
- 转换是改既有数据、影响面大：先备份、可回滚，commit message 说明影响条数。
- 转换脚本随数据一起进库（可复现、可审计），别只留一次性内联代码。

## 常见坑

- 政务/第三方数据经百度系录入或抓取 → 是 BD-09，却被当 WGS/GCJ 直接用，地图上整体平移约 1.1 km。
- 用「看起来差不多」的单点比对判坐标系 → 结论随机；必须 ≥5 点 + 三假设统计。
- Overpass 用名字模糊匹配取对照点 → 同名异地污染；样本必须精确匹配 + bbox。
- 混合来源数据不做转换直接入库 → 同一表里国内点偏几百米、境外点正确，接入地图时才暴露。
