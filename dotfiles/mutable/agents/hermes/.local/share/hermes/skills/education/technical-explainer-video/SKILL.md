# 技术解释视频

把抽象技术过程画成一条能看懂的故事：**具体输入 → 可见过程 → 明确输出 → 证据指标**。适用于机器学习、算法、数据流和系统机制；不用于旁白型长视频、产品宣传或纯素材剪辑。

## 始终遵守

- **先给具体案例，再画通用网络。** 观众必须能指出输入是什么、模型做了什么、最终输出是什么。
- **声明的数字必须由真实绘制数据生成。** 标题写 `16-8-10`，画面就必须从同一组数组画出 16、8、10 个节点；不要只改标签。
- **先保证可读，再追求复杂度。** 低分辨率画布中，密集连线会吞掉节点。必要时减少边、缩小层数，或把完整矩阵抽象成规则排列的输入网格。
- **画布内容不能只靠自动检查。** DOM 审计可能检查不到 Canvas 内的文字、节点数和相互遮挡，必须另做关键帧视觉验收。
- **渲染前快照不等于最终成片正确。** 最终 MP4 还要抽帧复核，确认编码后仍完整可见。
- **用户明确要求“直接发截图或视频”时，视为渲染授权。** 对方不在电脑前时，不要把 localhost 预览地址当成交付阻塞点；直接导出并附文件。

## 工作流

### 1. 锁定一个可演示案例

把宽泛主题压缩成单一闭环。例如“训练神经网络”不要只画抽象节点，改成：

```text
MNIST 手写数字 3
  → 4×4 像素输入
  → 16-8-10 网络
  → 0–9 类别概率
  → 预测 3
  → loss 下降 / accuracy 上升
```

先写清输入、预期输出、最终状态和能证明成功的指标。案例一旦锁定，标题、布局、动画、标签和输出必须围绕它服务。

### 2. 建立单一语义源

在动手前定义数据对象或常量：

```js
const model = {
  layers: [16, 8, 10],
  classes: 10,
  target: 3,
  loss: [0.86, 0.68, 0.49, 0.34, 0.23, 0.16, 0.12, 0.09, 0.07],
};
```

节点位置、标题、类别数量、最终高亮和预测框全部从它派生。保存项目内 `BRIEF.md` 与 `shot-plan.json`，让意图、镜头和代码使用同一份事实。

### 3. 设计四个视觉角色

短解释片优先采用四区布局：

1. **输入**：一个具体样本，必须能独立辨认。
2. **过程**：用信号脉冲、节点激活或数据流动表达因果。
3. **输出**：概率、排名、状态或生成结果，获胜项有明确落点。
4. **证据**：指标随时间变化，最终状态与输出一致。

像素画布优先从 320×180 或 384×216 起步，再用最近邻放大。所有像素字体、外框和说明文字都要留出安全边距。

### 4. 构建可 seek 的确定性动画

- 每帧画面只由时间值和数据决定。
- 不用墙钟、未播种随机数或事件触发关键状态。
- 用一个暂停的主时间线驱动全局时间。
- 动画结束态与静态首帧布局保持一致。

低分辨率 Canvas、网络图和验收配方见 `references/pixel-technical-explainers.md`。

### 5. 做语义自检

自动布局检查之前，先验证：

```js
console.assert(model.layers.reduce((a, b) => a + b, 0) === nodes.length);
console.assert(model.classes === outputBars.length);
console.assert(model.target === finalPrediction);
```

断言不够时，增加页面内诊断节点，报告实际节点数、输出条数和最终预测。诊断必须来自绘制所用的同一数组，不能另写一份“看起来正确”的计数。

### 6. 运行分层质量门

按项目固定版本依次执行：

```bash
npx hyperframes lint .
npx hyperframes check . --at <开场>,<过程>,<结果>,<尾帧>
npx hyperframes snapshot . --at <开场>,<过程>,<结果>,<尾帧>
```

至少检查四个时刻：

- 开场：输入案例已出现；
- 过程：信号或状态确实在变化；
- 结果：最终输出和指标一致；
- 尾帧：干净收束或可接受回环。

逐张看图，确认完整可见、标签与图形一致、无文字叠印和压边。Canvas 自动报告“0 个文本检查”不代表画面没有文字问题。

### 7. 渲染后验证真实交付物

渲染完成后使用 `scripts/verify_video.py` 检查分辨率、帧率、时长、帧数，并从成片抽取代表帧。视觉判断必须基于这些成片帧，而不是只基于渲染前快照。

```bash
python scripts/verify_video.py renders/video.mp4 \
  --width 1920 --height 1080 --fps 30 --duration 8 \
  --times 0.8,4.2,5.8,7.95
```

任何指标不符、抽帧失败或代表帧有硬伤，都先修再交付。

### 8. 交付

- 附最终视频文件。
- 写明实际时长、分辨率、帧率和是否有音频。
- 至少附一张来自最终 MP4 的代表帧。
- 只报告真实验证过的状态；未验证项明确标注。

## 常见硬伤

- 抽象网络有节点，却没有可辨认的输入和输出。
- 标签写 10 类，实际只画 9 条概率条。
- 画布内文字互相覆盖，但 DOM 布局检查仍然全绿。
- 预览快照正确，重渲染后因 Canvas 缩放或裁切丢失内容。
- 用户要文件，却只返回需要本人打开的 localhost 预览地址。
