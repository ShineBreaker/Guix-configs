# 名称与命名（文件命名 / 产品命名 / 名称使用）

源：名称与命名/ 三节。

## 文件命名（以 Markdown 源文件为例）

- 文件名应能对文档内容作简要概括。
- 文件名不宜过长。
- 多个英文单词组成时，单词中间用短划线「-」隔开。
- **不建议使用下划线「_」**：URL 中下划线不利于 SEO，且在部分 Markdown 实现中是修饰字符。
- 多个英文单词组成时建议全小写，全大写亦可接受（如 FAQ.md）。
- **禁止大小写混用**。
- 文件后缀名用小写。
- Markdown 用「.md」后缀，「.markdown」亦可接受，但要保证风格统一。

## 产品命名

- 命名不可随意：重则有法律风险（重名），轻则影响对外品牌输出。
- 建议全公司范围建立产品命名统一流程，**维护一份统一的产品名称表**。

## 名称使用

国外公司、品牌或产品名称的三种情形：

| 情形 | 用法 |
| --- | --- |
| 中文读者熟知中文官方译名 | 只用中文官方译名（微软、苹果、甲骨文） |
| 中文读者不熟悉、但有中文官方译名 | 「中文官方译名 (英文官方名称)」形式（威睿 (VMware)） |
| 无中文官方译名 | 直接用英文，**必须使用正确的大小写**（MySQL、GitHub、TikTok、WeChat；错误：mysql、github、tiktok、wechat） |

注意事项：

- 判断中文读者是否熟知具有主观性；不确定时优先用「中文官方译名 (英文官方名称)」形式。
- 「中文官方译名 (英文官方名称)」只需在**第一次出现**时用完整形式，之后用中文官方译名即可。
- 上游提供参考名称表（微软/苹果/甲骨文/推特/脸书/领英 属熟知译名；威睿 (VMware)/塔多思 (Trados)/西门子 (Siemens)/思科 (Cisco) 属不熟悉但有译名；GitHub/SDL/MySQL/Alphabet/MongoDB/Azure 属无中文译名）。上游注明该表待补充，各公司可自行调整。
