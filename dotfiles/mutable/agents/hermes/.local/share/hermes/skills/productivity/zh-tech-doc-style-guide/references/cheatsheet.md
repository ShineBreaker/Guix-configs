# 成稿前自检清单

综合全书高频硬规则，交付前逐条过。标注 [强制] 的是上游用「禁止/必须」表述的，[建议] 是 SHOULD 级。

## 标点与空格（最高频返工点）

- [强制] 中文语境标点一律全角；全角标点两旁不空半角空格。
- [强制] 一律半角空格，不用全角空格；中文字符之间不空半角空格。
- [建议] 英文单词/阿拉伯数字用半角空格包围；句首左侧、右侧紧跟标点时省略。
- [强制] 数值与单位符号间空一个半角空格；角度/摄氏度/百分号/英尺英寸符号不空格。
- [强制] 括号内全英文 → 半角括号且前后各空一格；含任何中文 → 全角括号且前后不空格。
- [强制] 斜杠两旁不加空格；多个并列项用顿号不用斜杠。
- [强制] 破折号前后不空格；省略号用六个点，不用英文三点。
- [强制] 不用多个感叹号连用；慎用感叹号与反问句。

## 数字

- [强制] 阿拉伯数字一律半角，禁用全角数字。
- [建议] 半角数字两旁各空一格；数值不跨行断开。
- [建议] 千位以上加半角逗号分节（四位以内可不分节，小数部分不分节）。
- [建议] 数值范围用「～」或「—」；前后单位相同且不歧义时可省略前一个。
- [强制] 概数两数字连用不用顿号（「六七十年代」不写「六、七十年代」）。
- [强制] 序数词阿拉伯数字后用点号（「3.」不写「3、」）。
- [强制] 「零」用于计量、「〇」用于编号。

## 结构

- [强制] 标题最多四级，从一级递增，禁止跳级。
- [强制] 项目列表下禁止嵌套任何级别标题。
- [建议] 同级标题避免孤立编号；三级下有并列短内容用列表代替四级标题。
- [建议] 标题描述操作任务用「动词+主题词」；同级别标题结构一致。
- [强制] 段落顶格开始，不缩进。
- [建议] 段落 50～200 字，不超 250；一个段落一个主题，中心句放段首。
- [建议] 句子不超 100 字，用简单句和并列句，避免复合句。
- [强制] 代码块前后各空一行；列表项下代码块再缩进四格。
- [强制] 表格不留空白单元格，不用「同上」。

## 语气与用词

- [强制] 不用反问句；不轻易用感叹句、不轻易用「请」「抱歉」。
- [建议] 始终用「您」或「你」，不用「亲爱的」等过亲称呼。
- [建议] 不用行话黑话、网络流行语、谐音错别字。
- [建议] 初稿完成后通读一遍，删去不承担表意功能的字词句。
- [建议] 主动时态，主宾语清楚。

## 名称与缩略语

- [强制] 英文名称大小写正确（MySQL/GitHub/WeChat）。
- [建议] 夹用英文单词词组时普通词小写、专有名词保留大写；夹用英文句子时首字母大写。
- [强制] 缩略语第一次出现时解释完整含义并提示下文代称。
- [强制] 不用不规范缩略语（16c32g、10w）。
- [建议] 标题中不解释缩略语。
- [建议] 文件名多单词用短划线、全小写、不用下划线、禁止大小写混用。

## 中英混排

- [强制] 中文句子句末一律中文标点；夹用的英文内容自带英文标点保留。
- [强制] 英文标题/引文的结尾问号叹号保留。
- [建议] 英文书籍报刊名用斜体或中文引号，不用书名号《》。

## 收尾

- [建议] 操作型文档做可用性测试（无技术背景人员照文档走完整操作）。
- [建议] 配编辑器自动检查：Grammarly / LanguageTool / Vale / VS Code Code Spell Checker + Markdownlint。
