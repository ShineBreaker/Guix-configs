# 实例：14 天跨平台会话回顾（2026-09-01 ~ 09-14）

来源：用户要求「总结最近十四天所有平台的对话，沉淀到 agenote 和 hermes 中」。语料 = 6 个 AI 编码 agent（zcode / omp / crush / opencode / codex / claude）的会话 + Hermes 自己的会话。

## 实际数字（可用作下次的体量估算）

| 阶段 | 数字 |
| --- | --- |
| 原始抽取 | 14 天 × 6 源 = 3.5MB org（每天约 7 秒） |
| 压缩后 | 1.6MB（≈48%）——只去 `[reasoning]`/`[tool:]` 占位 |
| 噪声占比 | 原始抽取里 TodoWrite 提醒 / task-notification / system-reminder 占 **40~78%**（某单日 89/166 块是同一段 TodoWrite 提醒，重复 58,958 字符） |
| 切片 | 10~12 片，最大单片 599KB（再按消息边界拆半成 300KB×2） |
| 并行 | 10 个 worker 同时跑，340~650 秒 |
| 产出 | 115 条主线、40 张候选卡（C 系列）+ 8 张（Hermes 会话）+ 若干，最终写入 42 张 |
| 落库后 | 卡片总数 295 → 337，孤立率 28% → 22%（挂链后） |

压缩后体积分布是**高度不均**的：zcode 一天 599KB，另一天只有 1KB；按大小配对切片，不要按天平均。

## worker 产出结构（JSON）

```json
{
  "threads": ["09-01 zcode｜<工作主线 ≤60 字>"],
  "cards": [{"title": "<结论式标题>", "category": "...", "tech": "...", "type": "...",
             "entry": "note|mistake|ascended", "summary": "...", "body": "<Org 正文>",
             "evidence": "<日期+平台+路径+原文>", "dedupe": "无命中 / 已有: <ID> <标题>"}],
  "prefs": [{"pref": "...", "evidence": "..."}],
  "env_improvements": [{"observation": "...", "suggestion": "...", "evidence": "..."}],
  "dropped_candidates": ["<考虑过但丢弃的，附理由>"],
  "notes": ["<存疑项>"]
}
```

`dropped_candidates` 与 `notes` 是意外收获：一眼能看出哪些是「查重命中已覆盖」、哪些是「证据不足」——主会话据此决定写不写，不用重读原文。

另：worker 会在摘要被截断时把关键取舍放在中段；主会话应直接读它落盘的 JSON，或用 `read_file` 分页读完摘要文件。

## 汇总与落库（本轮实际踩到的坑）

1. **配额纪律生效过一次**：按策展约定「单轮新增 >10 张即暂停」，先写 10 张，把剩下的 24 张连同来源列给用户，用户回「全写」后才补写 32 张。这个暂停不是形式主义，它让用户有机会看到提炼口径。
2. **来源行串位事故**：批量补「来源」时用 `zip(sorted(keys), sorted(paths))` 配对，两列排序口径不同 → 10 张卡的来源全部错位；只能写脚本按 ID 反向清理重插。教训：**按 ID 映射，别赌排序**。
3. **CLI 追加语义**：`update --append-to <章节>` 是「插在章节标题之后」（连续追加倒序堆叠），`--stdin` 是「追加到文件末尾」——都不是替换。
4. **自动挂链退化**：按正文 2-gram 相似度给 42 张新卡自动找 hub，38 张挂到跨类别的无关条目（少数高被引条目吸走大部分链接），产出 84 行噪音（双向写入，旧卡上也有）。修法：脚本按 category 过滤删除跨类别链接，再「按 category 限定候选挂本类别 hub」重挂 27 张。
5. **幂等守卫救过一次**：脚本中途崩（worker 输出的 `evidence` 是 list 触发 `AttributeError`），重跑时靠「先取现有标题集合，命中即 skip」没有产生重复卡。
6. **碎片文件清理**：全库扫「无卡片头或缺 `:ID:`」的文件，发现 1 个只剩 `** 相关链接` 的碎片（在索引里是 `id=<日期> / title=unknown` 的假条目）——`trash-put` 移出后重扫确认无同类。

## 本轮顺带落地的流程改进（回写进工具，而非只写进卡片）

抽取工具（agenote）本轮被改了三处，都是这次回顾暴露出来的：

- extract 落盘前过滤 harness 元消息（复用 reconcile 已有的 `is_noise_fact`，口径统一），报告新增 `noise_filtered` 计数——重抽 14 天后语料 3.4MB → 1.9MB
- lint 与 fingerprint 构建器口径不一致（构建器在 `tech == category` 时按设计省略该段，lint 却按固定 5 段判定）→ 误报 926 处降到 433
- `search` 的位置参数改 `nargs="+"`，裸多关键词不再报 `unrecognized arguments`

教训：**回顾流程里反复出现的摩擦，应当回写进工具本身**，否则下次还要绕。
