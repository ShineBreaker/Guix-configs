# 文档结构样式（标题 / 段落 / 句子 / 目录）

源：文档结构样式/ 四节。

## 标题

### 层级

- 标题最多不超过四级。
- **从一级开始递增使用，禁止跳级**：一级下不能直接三级；二级下不能直接四级。
- 一级 = 文章标题；二级 = 正文部分标题；三级 = 二级下的小标题；四级 = 三级下的小标题。
- 若无特殊需要，不建议用四级标题；三级标题下有并列性内容且篇幅不长时，**用列表（list）代替四级标题**（上游配图 headings-or-lists）。

### 描述

标题描述的五种模式：

| 模式 | 例 |
| --- | --- |
| 名词词组 | 「…概述」「…背景」「…原理」 |
| 主题词 + 动词 | 「A 工具安装」「A 工具部署」「A 工具配置」 |
| 动词 + 主题词 | 「配置 MySQL 数据库」 |
| 定语 + 主题词 | 「A 工具的安装」「A 工具的架构」 |
| 介词 + 定语 + 主题词 | 「对机器配置的要求」 |

设计原则：

- 能概括反映本章节中心内容
- 简洁扼要、涵义明确
- 同级别标题尽量使用相同结构
- 描述**操作任务**时建议「动词 + 主题词」，不建议名词词组

### 注意事项

- 下级标题禁止重复上一级标题的内容
- 不建议标题以标点符号（句号、问号）结尾
- 不建议在标题中解释缩略语
- 标题之间应有引导介绍性句子：一级与二级之间应有引言，二级与三级之间应有正文
- 避免孤立编号（同级标题只有一个）；正文不要有孤立的三级、四级标题
- 项目列表是最小编号单位，**列表下禁止嵌套任何级别的标题**

## 段落

- 一个段落只能有一个主题 / 一个中心句子。
- 中心句子建议放段首，对全段概述；后续句子为核心句服务。
- 段落长度建议 50～200 字，尽量不超过 250 字（上游按 Word 字数统计）。
- 一个段落里避免只有一个句子。
- 句子长时避免「一逗到底」，合理断句。
- 段落之间设合适间距。
- 语气用陈述和肯定，避免感叹语气。
- **技术文档段落开头不建议缩进，顶格开始。**
- 技术描述类主题遵循「先图表，后句子」，不要单一用段落陈述主题。

## 句子

- 句子以句号结尾（句号表示意思已完成）。
- 一个句子建议不超过 100 字，避免长句。
- 使用简单句和并列句，避免复合句。
- 善于断句，避免「一逗到底」。

上游反例（DM binlog position 复合句，一逗到底）与改法要点：

- 【错误】多个分句串成一长句：DM 需保存 binlog position → MySQL binlog position 用 uint32 → 超 4G 溢出 → 存错 position → 重启后重新解析 → 出现错误。
- 【分析】复合句 + 一逗到底增加理解整体句群含义的难度。
- 【修改】在适当处断句，添加「这」「其」等代词，合理切分句与句的逻辑。上游改写为三句：溢出原因一句；「这会导致……」承接；重启场景一句收尾。

## 目录

- 文档目录可**通过各级标题自动生成**，帮用户快速浏览全文结构和定位章节。
- 一本技术手册**必须提供总目录**（含所有章节及附录）；安装手册等还需图目录、表目录。
- 网页端技术手册两侧配导航栏：**全手册导航栏 = 总目录**，**页内导航栏 = 单篇文档目录**（上游示例为 PingCAP 文档站）。
- 右侧导航栏能显示哪些标题层级，**由文档框架决定**：Docusaurus 正文不限制级别，但右侧导航只支持二级（##）和三级（###），一级（#）和四级（####）不出现。
- 因此建议**根据文档框架自定义标题层级**：若右侧导航无法显示一级标题，就把文档中的一级标题定义为 ##、二级定义为 ###，以此类推。
