# 把机械规范嵌进已有格式化器

写独立脚本（SKILL.md §1-§5）只在宿主没有格式化器时是对的。本文件覆盖另一半：
用户点名「补到 X 里」/「做成 lint 和 formatter」时怎么扩展宿主，以及宿主之外
已有一个同类工具时怎么处理重叠。

## 1. 落点决策

| 情形 | 动作 |
| --- | --- |
| 用户点名某个宿主（「补到 orgfmt 里」） | 扩展宿主。不另起工具 |
| 宿主已有「按块状态迭代行」机制，且同时识别两种格式的块 | 规则写一次，两种格式共用 |
| 宿主没有这种机制 | 先加机制再写规则；不要写两份规则 |
| 已有另一个工具做了同类事 | 出能力矩阵，对齐重叠行，不合并代码库 |

另起工具的真实代价不是重复劳动，是**口径漂移**：同一条规则在 A 工具转、在 B
工具不转，用户交替使用拿到不同结果，且没人发现。

## 2. 阶段插入位置

只改**行内容**的规则，必须插在表格对齐之前——列宽按改后文本重算。插在对齐
之后，表格列宽会按改前文本算，下一轮再跑又变，永远不收敛。

## 3. 非正文行守卫表（按宿主格式枚举）

先扫一遍真实文件，列出全部非正文行种类，再写规则。漏一类的症状就是真实文件
上的一处误报——单测抓不到，因为单测的样本是你自己想的。

| 种类 | 例子 | 会被什么规则误伤 |
| --- | --- | --- |
| org 元数据行 | `DEADLINE: <2024-01-15 周一 +1w>`、`SCHEDULED:`、`CLOCK:` | repeat cookie 被当不规范缩略语 |
| org 关键字行 | `#+TITLE: x`、`#+BEGIN_SRC` | 被当正文补空格 |
| 带值的属性行 | `:EFFORT:   8h`、`:ID: 20260925-000000` | `8h` 被补成 `8 h` |
| 无值属性行 | `:PROPERTIES:`、`:END:` | 抽屉内被插空行（既有阶段 bug） |
| 行内公式 | `$x^2$`、`$$...$$` | 数字与单位规则动 LaTeX |
| 表格行 | `\| a \| b \|` | 补空格破坏对齐；省略号被当截断标记 |
| 配置项名后 | `[connection]段` | 中英间距误插 |
| 紧凑枚举后 | `0=disable省电` | 同上 |
| 行首标记后 | `- **标签**:变体`、`# `、`=verb=` | 同上 |

org 侧一条正则覆盖前三类：
`^\s*(DEADLINE|SCHEDULED|CLOSED|CLOCK|CLOG)\s*:|^\s*#\+\w+:`。
markdown 侧对应 front matter 与该正则不适用的部分，按实际格式补。

## 4. 自动修 vs 只报不改

判据只有一个：**改错会不会改变语义**。

- 机械可判、改了不改语义 → 自动修（全角空格、标点旁空格、中英间距、破折号、
  省略号、连续感叹号、序数词顿号、数值与单位）。
- 要读懂句子才能判 → 只报（的/地/得、顿号误用于分句、繁体用语、不规范缩略语）。
  输出带 `[待人工]` 前缀，让人一眼看出哪些必须自己看。

## 5. 繁体/异体字判定

- 单字判定不可用：行、化、文、表、面、相、作、本、位、能、方、成、出、新、
  分、明、上、同 等字两岸通用，凭单字判必然误伤。
- 词组级判定要**逐个核对繁简写法确实不同**才入表。已知繁简同形、必须排除的：
  修改、警告、伺服器、滑鼠、新增、排序、支援、同步、非同步、循序、功能表、
  工具列、核取。
- 漏网（单独混入的繁体字）由人工审校兜底；要更严可换 OpenCC，代价是引依赖。
  为一条 lint 项加依赖不划算时，把这个取舍写成 `ponytail:` 注释留在代码里。

## 6. 验证阶梯（每级都过，不能跳）

| 级 | 命令/动作 | 抓什么 |
| --- | --- | --- |
| 1 fixtures | 单测直调规则函数 | 规则本身写错 |
| 2 全量套件 | 跑仓库完整测试 | 改宿主共有代码时的回归（空行状态机、fence 识别） |
| 3 真实文件 | `--check` 打在有真实内容的仓库文件上 | 守卫漏项——只有这级能抓到 |
| 4 幂等 | 连跑两次比 md5 | 规则不收敛（表格列宽按改前算的典型症状） |
| 5 门禁 | 确认 `--check` 退出码=问题数 | 能否进 CI / pre-commit |

第 3 级最容易被跳过，也最值钱：非正文行守卫的漏项只在真实文件上暴露。

## 7. 与另一个工具重叠时

1. 构造一份同时含两类规则触发的样本（半角标点、括号、破折号、中英间距、单位、
   序数词、繁体词、缩略语各一行）。
2. 两个工具都跑 `--check`，逐条对照，出**能力矩阵**（谁做 / 谁不做 / 口径差异）。
3. 只修重叠行的口径差异——把一边已经打磨过的守卫条件（行首标记后、配置项名后、
   枚举值后）搬到另一边，而不是搬整份规则。
4. 不合并。两个工具服务不同宿主（仓库存量文档 vs org 结构化格式化）时，合并才是
   过度设计；在调用侧串起来（先 A 再 B）比搅进一个文件省事。
5. 把未覆盖清单写进汇报，别让用户以为全覆盖了。

## 8. 提交

用户仓库可能有 hook 限制提交形式（如只接受 `-m`）。用多个 `-m` 分段传正文，
每段一段；不要用 `-F -` 或临时文件，会被 hook 拒。精确 staging——工作区里
用户的未提交改动（README 等）不要 `git add` 进来，`git add` 前先 `git status`。
