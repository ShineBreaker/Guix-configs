# 拼写与语法（拼写 / 语法 / 文档质量检查工具）

源：拼写与语法/ 三节。

## 拼写

中文技术文档既有中文也可能含英文，须严格避免：

- **简体中文和繁体中文不能混用。**
- **禁止中英文错别字**（错字和别字均不可）：
  - 错字：把某字写错，该字是人为编造、无意义。例：MySQL 写成 MySOL。
  - 别字：字形近或音近但意思不同。例：cooperate 写成 corporate；authorization 写成 authentication。

英文大小写：

- 英文大小写不能写错：不写「mysql 数据库」，应写「MySQL 数据库」（详见 `references/naming.md` 的名称使用）。
- 中文句子夹用英文**单词或词组**时，无论位于句首/中间/末尾：**普通单词、词组必须小写**；**专有名词等英文中必须大写的保留大写**。例：「change 和 transform 意义不同。」「这个数据库有不错的 MySQL 兼容性。」
- 中文句子夹用完整**英文句子**时，无论位于句首/中间/末尾：**首字母保留大写**。例：「Follow your fear 是我的座右铭。」「他经常与人说“Never set a limit to yourself.”。」

## 语法

常见错误类型及改法：

**成分残缺**——缺必要成分。

- 错误：「在应用程序没有提供会话保持的功能下，HAProxy 可以提供该项功能。」
- 建议：「在应用程序没有提供会话保持功能的情况下，HAProxy 可以提供该项功能。」

**搭配不当**——主语谓语不对应。

- 错误：「HAProxy 是由……Willy Tarreau 于 2000 年编写，并仍然负责该项目的维护，该在开源社区提供免费和版本迭代。」（「并仍然负责」的主语变成 HAProxy）
- 建议：「HAProxy 是由……Willy Tarreau 于 2000 年编写，他现在仍然负责该项目的维护，并在开源社区免费提供版本迭代。」

**用词不当——倍数表达**（高频陷阱）：

- **数值增加必须明确用「增加了」或「增加到」，不能只用「增加」**：「了」表增量，「到」表定量。
  - 错误：「增加两倍」。正确：「增加了两倍」（过去为一，现在为三）；「增加到过去的两倍」（过去为一，现在为二）。
- **数值减少必须明确用「降低了」或「降低到」**。
  - 错误：「降低 80%」。正确：「降低了 80%」（原一百今二十）；「降低到 80%」（原一百今八十）。
- **不能用「降低 N 倍」「减少 N 倍」**，要用「降低百分之几」「减少百分之几」。

**成分多余**——冗余表述。

- 错误：「根据官方建议，目前稳定版本的 HAProxy 为稳定版 2.0 特性。」
- 建议：「官方目前建议使用 HAProxy 稳定版本 2.0。」

**句式杂糅**——多谓主纠缠、需断句并明确主语。

- 错误：DM-master 长句中 etcd 集群、元数据存储、leader 选举、服务提供四个动作全挤进一句。
- 建议：拆成四句，每句一个明确主语：「……组成集群。」「该 DM-master 集群用于存储……。」「该 leader 节点用于提供……。」「因此，若可用的 DM-master 节点数超过部署节点的半数，即可正常提供服务。」

## 文档质量检查工具

成熟的文档工作者应配置编辑器做自动拼写和语法检查。上游推荐：

- Grammarly（grammarly.com/grammar-check）
- VS Code 插件：Code Spell Checker、Markdownlint
- LanguageTool（languagetool.org）
- Vale（github.com/errata-ai/vale）
