* 配置域总览
:PROPERTIES:
:CUSTOM_ID: overview
:END:

本文档 =emacs.org= 是整个 Emacs 配置的唯一修改源。所有配置代码通过 =scripts/configctl tangle= 拼合生成最终的 =main.el= ，供 Emacs 启动时加载。

#+begin_note
*给接手维护者的快速指引*
- *只修改本文件* ：不要直接改动 =main.el= 。手动写进 =main.el= 的内容会在下次执行 tangle 时被直接覆盖。
- *严格按顺序加载* ：全部配置划分为 8 个核心域，按文档从上到下的顺序依次执行。前面的模块定义基础变量与辅助函数，后面的模块才能正常调用。
- *日常验证流程* ：修改文档后，先在终端执行 =scripts/configctl check= 检查语法与依赖结构，再运行 =scripts/configctl tangle= 生成配置。
#+end_note

** 常用修改入口速查

- 调整字体大小或透明度：前往 [[#theme-fonts][主题与字体]] ，修改 =custom:default-font-height= 与 =custom:frame-background-opacity= 。
- 增加或修改快捷键：属于具体功能的按键直接在其所在模块用 =custom/bind= 注册；通用全局键前往 [[#keys-completion][键位与补全]] 。
- 添加或调整编程语言：前往 [[#programming-tools][语言能力表]] ，在 =custom:language-capabilities= 表格中修改或添加。
- 调整 Org 笔记路径：前往 [[#bootstrap-paths][路径常量]] ，修改 =custom:org-directory= 。

* 启动与基础设施
:PROPERTIES:
:CUSTOM_ID: startup
:END:

本域是 Emacs 启动时最先执行的底层部分，主要完成四件事：
- 调优启动期垃圾回收，消除启动卡顿。
- 定义笔记目录与外部命令，把 Guix 工具链路径加入环境变量。
- 提供统一的快捷键注册函数 =custom/bind= ，自动同步 Which-key 提示与帮助文档。
- 规范文件存放位置，实现失焦自动保存与历史持久化。

** GC 与启动优化
:PROPERTIES:
:CUSTOM_ID: startup-gc
:END:

Emacs 在启动阶段需要加载并求值大量代码。如果保持默认的较小 GC 阈值（800KB），加载过程中会反复暂停回收垃圾，拖慢启动速度。

优化策略如下：
- *启动前调大阈值* ：启动时将 =gc-cons-threshold= 设为最大整数，并把 =gc-cons-percentage= 提高到 0.6，避免在读取配置期间触发垃圾回收。
- *启动后平稳复原* ：通过 =emacs-startup-hook= 钩子，在启动完成后把 =gc-cons-percentage= 调回稳态值 0.1，后续日常编辑交由 GCMH 空闲回收。
- *关闭字体缓存压缩* ：开启 =inhibit-compacting-font-caches= ，避免常驻后台的守护进程压缩字体缓存导致切换窗口时界面抖动。
- *关闭模式大小写折叠* ：将 =auto-mode-case-fold= 设为 nil，省去每次打开文件匹配模式时不必要的大小写转换。

#+begin_src emacs-lisp
;;; main.el --- custom-config 主配置(由 emacs.org tangle 生成) -*- lexical-binding: t; -*-

;; SPDX-FileCopyrightText: 2026 BrokenShine <xchai404@gmail.com>
;; SPDX-License-Identifier: MIT

(setq gc-cons-threshold most-positive-fixnum
      gc-cons-percentage 0.6
      inhibit-compacting-font-caches t
      auto-mode-case-fold nil)

(defun custom--reset-gc-percentage ()
  "启动完成后将 `gc-cons-percentage' 恢复为稳态值。"
  (setq gc-cons-percentage 0.1))

(add-hook 'emacs-startup-hook #'custom--reset-gc-percentage)

(message "[LOAD] 基础设施加载完成")
#+end_src

** 路径常量与外部命令声明
:PROPERTIES:
:CUSTOM_ID: bootstrap
:END:

在这里集中定义笔记路径与外部工具名称。

#+begin_note
*为什么外部命令只写命令名，而不写绝对路径？*
在 GNU Guix 操作系统中，每次系统升级后，安装在 =/gnu/store/= 里的软件包哈希值都会改变。如果将绝对路径硬编码到配置中，升级后旧路径就会失效。
这里只记录命令名称（例如 ="git"= ），让 Emacs 运行时通过 =exec-path= 动态查找，即使后台守护进程跨代系升级，也能稳定找到最新工具。
#+end_note

*** 外部命令声明
:PROPERTIES:
:CUSTOM_ID: bootstrap-executables
:END:

在检查可执行文件之前，先把 Guix profile 的 =bin= 目录与用户本地的 =~/.local/bin= 加入 Emacs 的 =exec-path= ，确保所有命令行工具立即可用。

#+begin_src emacs-lisp
;; exec-path 前置:daemon 启动与 batch-load main.el 的包启用条件、agenote 调用
;; 都经 `executable-find' 查询当前 `exec-path';配置只保存命令名,不缓存
;; store 绝对路径,跨 generation 后仍由当前 PATH 解析。
(let* ((guix-profile (or (getenv "GUIX_PROFILE")
                         (expand-file-name "~/.guix-profile")))
       (guix-bin (expand-file-name "bin" guix-profile))
       (local-bin (expand-file-name "~/.local/bin")))
  (when (file-directory-p guix-bin)
    (add-to-list 'exec-path guix-bin))
  (when (file-directory-p local-bin)
    (add-to-list 'exec-path local-bin)))

(defconst custom:executable-aspell   "aspell")
(defconst custom:executable-direnv   "direnv")
(defconst custom:executable-git      "git")
(defconst custom:executable-godot    "godot")
#+end_src

** Frame 生命周期与 daemon
:PROPERTIES:
:CUSTOM_ID: frame
:END:

Emacs 支持两种运行方式：普通独立窗口运行，以及守护进程模式（Daemon）。
在守护进程模式下，Emacs 启动时后台并没有显示器屏幕。如果启动时就去设置窗口大小、字体或透明度，就会导致错误。

因此，所有界面与渲染设置不能在启动时直接执行，而是统一挂载到 =after-make-frame-functions= 钩子。每当有客户端连接并创建新窗口时，再按需应用外观设置。如果是非守护进程独立启动，则直接在初始化完成时对当前首个窗口执行一次。

** 键位声明
:PROPERTIES:
:CUSTOM_ID: key-helper
:END:

为了统一管理快捷键，本配置封装了 =custom/bind= 函数，推荐在配置各个功能模块时优先使用它，而不是直接调用 =keymap-global-set= 。

#+begin_tip
*custom/bind 的优势*
1. *一处绑定，多处生效* ：绑定按键的同时，自动为 Which-key 注册中文提示，并把按键加入快捷键帮助手册。
2. *防重复声明* ：如果同一个按键在不同地方被不小心重复绑定，会自动报错中断，避免按键冲突。
3. *调用格式* ：=(custom/bind "快捷键" #'命令 "中文说明" "分组名称")= 。

*自助查询与定制*
- *查某个键现在做什么* ：按 =C-h k= 再按那个键（=describe-key=）。
- *查命令与键位总表* ：=C-h f custom/bind= 看声明格式；=C-h v custom:binding-spec= 列出全部已声明键位。
- *改键* ：在对应功能模块找到 =(custom/bind "..." ...)= 行，改键串或换命令；键串语法见 =C-h f key-valid-p= ，功能键须写为 =<f12>= 而非 ="F12"= 。
- *只分组不绑键* ：=custom/declare-binding-group= 是 =custom/bind= 的特例（=:prefix t=），只注册 Which-key 分组名、不绑定命令。
- *命名约定* ：=custom:= 前缀为配置变量，=custom/= 为命令与函数，=custom--= （含 =custom/模块--名称= ）为内部实现细节——双分隔符开头表示不建议直接调用，本配置内部符号统一用 =--= 。
#+end_tip

#+begin_src emacs-lisp
(defvar custom:binding-spec nil
  "本地声明式键位表。")

(defvar custom--pending-wk-descs nil
  "Which-key 加载前暂存的全局键位描述。")

(defun custom/binding--record (entry)
  "把 ENTRY 追加到 binding spec，并拒绝重复 key/mode。"
  (let ((key (plist-get entry :key))
        (mode (or (plist-get entry :mode) 'global)))
    (when (seq-find
           (lambda (existing)
             (and (equal key (plist-get existing :key))
                  (eq mode (or (plist-get existing :mode) 'global))))
           custom:binding-spec)
      (error "重复键位声明: %s (%s)" key mode))
    (setq custom:binding-spec
          (append custom:binding-spec (list entry)))))

(defun custom/binding--register-which-key (key description)
  "为 KEY 注册 DESCRIPTION;which-key 未加载时暂存待注册。"
  (if (featurep 'which-key)
      (which-key-add-key-based-replacements key description)
    (push (cons key description) custom--pending-wk-descs)))

(defun custom/bind (key target description group &rest properties)
  "声明并绑定全局 KEY 到 TARGET。
DESCRIPTION、GROUP 与 PROPERTIES 同时供 Which-key 和帮助使用。"
  (let ((entry (append (list :key key
                             :command target
                             :description description
                             :group group)
                       properties)))
    (custom/binding--record entry)
    (unless (plist-get entry :prefix)
      (keymap-global-set key target))
    (custom/binding--register-which-key key description)
    entry))

(defun custom/declare-binding-group (key description)
  "声明 Which-key 展示的中间分组 KEY。"
  (custom/bind key nil description nil :prefix t))

(defun custom/register-pending-wk-descs ()
  "把暂存的全局键位描述注册到 Which-key。"
  (dolist (entry (nreverse custom--pending-wk-descs))
    (which-key-add-key-based-replacements (car entry) (cdr entry)))
  (setq custom--pending-wk-descs nil))

(defun custom/binding-help-sections ()
  "从 `custom:binding-spec' 生成帮助分组。
返回 ((GROUP . ((KEY . DESCRIPTION) ...)) ...):分组按首次出现顺序,
组内条目按声明顺序;前缀声明条目(:group 为 nil)不分组。"
  (let* ((declared-groups (mapcar (lambda (entry) (plist-get entry :group))
                                  custom:binding-spec))
         (groups (delete-dups (remq nil declared-groups))))
    (mapcar
     (lambda (group)
       (cons group
             (mapcar (lambda (entry)
                       (cons (plist-get entry :key)
                             (plist-get entry :description)))
                     (seq-filter (lambda (entry)
                                   (equal (plist-get entry :group) group))
                                 custom:binding-spec))))
     groups)))
#+end_src

** 包管理与加载策略
:PROPERTIES:
:CUSTOM_ID: package-loading
:END:

本配置使用的全部第三方插件由系统的 Guix profile 安装和管理。
启动时环境变量 =EMACSLOADPATH= 已经由系统环境注入，配置中可以直接使用 =use-package= 或 =require= ，无需联网从 MELPA 重新下载（所有包声明默认无需指定 =:ensure t= ）。

另外，原生编译（Native-compilation）生成的编译缓存通过 =startup-redirect-eln-cache= 重定向到 =var/eln-cache/= ，避免生成的大量缓存文件弄脏配置根目录。

#+begin_src emacs-lisp
(require 'use-package)

;; native-comp 的 eln 缓存重定向到 var/,避免污染配置根目录(Emacs 29+)。
(startup-redirect-eln-cache
 (expand-file-name "var/eln-cache/" user-emacs-directory))

;; agenote 知识库集成（适配层 + knowledge + health + 键位 map）。
;; 由 Guix profile 提供 emacs-agenote 包;路径常量对齐本仓库的 org 根目录。
;; :defer t——agenote-knowledge/agenote-health 的全部交互命令均带 autoload,
;; 首个 C-c o k 键触发加载;(require 'agenote) 由被加载方声明,:custom 经
;; eval-after-load 应用。
(use-package agenote
  :ensure nil
  :defer t
  :custom
  (agenote-org-directory custom:org-directory)
  (agenote-experiences-directory custom:org-knowledge-directory)
  (agenote-inbox-file custom:org-inbox-file))
#+end_src

** 基础行为设置
:PROPERTIES:
:CUSTOM_ID: core-behavior
:END:

这里集中配置 Emacs 的核心运行机制与文件安全保护策略：

- *空闲垃圾回收 (GCMH)* ：在持续敲击键盘输入代码时暂停 GC，直到停下键盘进入空闲状态时才执行清理，彻底杜绝打字过程中的微卡顿。
- *配置目录隔离 (no-littering)* ：自动把临时文件、自动备份、自动保存等分散文件统一重定向到 =var/= ，把 =custom.el= 放入 =etc/= ，保持根目录清爽。
- *输入与文件历史* ：启用 =savehist-mode= 记住输入命令与搜索历史，启用 =recentf-mode= 记住最近打开过的 300 个文件。
- *失焦自动保存* ：切换离开 Emacs 窗口 1 秒后，自动在后台静默保存修改过的本地文件缓冲区，不再需要频繁手动按 =C-x C-s= 。为了确保安全，该机制会自动跳过远程文件（TRAMP）与只读缓冲区。
- *陈旧 auto-save 异步处理* ：如果 Emacs 异常退出留下了陈旧的自动保存文件，打开文件时默认会强行停顿 1 秒警告。这里改为后台异步处理：内容完全相同的文件直接安全移入回收站，内容不同的则提示用户按需恢复，完全消除打开文件时的停顿。

#+begin_src emacs-lisp
(use-package gcmh
  :demand t
  :custom
  (gcmh-idle-delay 'auto)
  (gcmh-auto-idle-delay-factor 10)
  (gcmh-high-cons-threshold (* 32 1024 1024))
  :config
  (gcmh-mode 1))

(setq read-process-output-max (* 4 1024 1024)
      process-adaptive-read-buffering nil
      fast-but-imprecise-scrolling t)

(setq inhibit-startup-screen t
      initial-scratch-message nil
      ring-bell-function 'ignore
      confirm-kill-processes nil
      use-dialog-box nil
      use-file-dialog nil)

(use-package no-littering
  :demand t
  :config
  (setq backup-directory-alist
        `((".*" . ,(no-littering-expand-var-file-name "backup/"))))
  (setq auto-save-file-name-transforms
        `((".*" ,(no-littering-expand-var-file-name "auto-save/") t)))
  (setq custom-file (no-littering-expand-etc-file-name "custom.el"))
  (when (file-exists-p custom-file)
    (load custom-file t)))

(savehist-mode 1)

(use-package recentf
  :demand t
  :custom
  (recentf-max-saved-items 300)
  ;; Emacs 31:daemon 长驻下定期自动保存,异常死亡不丢历史
  ;; (默认只在 kill-emacs 时写)。列表仅在开合文件时变化,5s 属高频空转。
  (recentf-autosave-interval 300)
  ;; autosave 每次写盘都会在 echo area 打 "Wrote ...";上游 31.1 起默认关闭。
  (recentf-show-messages nil)
  :config
  (recentf-mode 1))

(defconst custom:focus-save-idle-delay 1
  "失焦后保存用户文件 buffer 前等待的空闲秒数。")

(defvar custom--focus-save-timer nil
  "失焦保存的 pending idle timer。")

(defun custom/user-file-buffer-p ()
  "当前 buffer 是否为正常访问的、可保存的本地用户文件 buffer。"
  (and buffer-file-name
       buffer-file-truename
       (buffer-modified-p)
       (not buffer-read-only)
       (not (buffer-base-buffer))
       (not (file-remote-p buffer-file-name))))

(defun custom/save-user-file-buffers ()
  "保存已修改的本地用户文件 buffer，不触碰内部或远程 buffer。"
  (setq custom--focus-save-timer nil)
  (save-some-buffers t #'custom/user-file-buffer-p))

(defun custom/schedule-focus-save ()
  "根据当前焦点状态安排或取消空闲保存。
任一存活 frame 已聚焦或焦点状态未知时不保存。"
  (when (timerp custom--focus-save-timer)
    (cancel-timer custom--focus-save-timer)
    (setq custom--focus-save-timer nil))
  (unless (seq-some #'frame-focus-state (frame-list))
    (setq custom--focus-save-timer
          (run-with-idle-timer custom:focus-save-idle-delay nil
                               #'custom/save-user-file-buffers))))

;; `add-function' 与 `add-hook' 的区别:hook 是「某事件发生时依次运行的
;; 函数列表」,而 `after-focus-change-function' 这类「函数变量」只装得下
;; 一个函数;`add-function' 给它的当前值套一层组合(:after = 原函数跑完
;; 再跑),不会把别人装进去的函数顶掉。
;; C-h v after-focus-change-function 可查看它当前装的是什么。
(add-function :after after-focus-change-function #'custom/schedule-focus-save)

;; 陈旧 auto-save 文件(#file# 比源文件新,多为 daemon 异常退出残留)会让
;; after-find-file 在打开文件时 sit-for 1 秒警告;该调用位于
;; initial-buffer-choice 同步路径上(dashboard 渲染 agenda 重开文件),
;; 表现为 emacsclient 打开卡 1 秒。改为不阻塞:检测到陈旧 auto-save 时
;; 局部跳过 sit-for(警告消息仍显示)、记入待审列表,空闲时逐个处理——
;; 内容与源文件相同的直接移入回收站,不同的(可能含未保存修改)询问用户。
(defvar custom--stale-auto-saves nil
  "after-find-file 检测到的陈旧 auto-save 待审列表,(auto-save . source) 对。")

(defvar custom--stale-auto-save-timer nil
  "处理待审 auto-save 文件的 pending timer。")

(defun custom--defer-auto-save-warning (orig &rest args)
  "after-find-file 的 :around advice:auto-save 警告不阻塞,改为延迟处理。
auto-save 文件比源文件新时把 sit-for 局部绑成 no-op 并记入
`custom--stale-auto-saves' 由定时器处理;其余情况原样透传。
不用 idle timer:daemon 无输入时 idle 恒真,reschedule 会 tight-loop
饿死 server;run-at-time 是绝对时间,不受 idle 状态影响。"
  (let* ((auto-save (and (not noninteractive)
                         buffer-file-name
                         (or buffer-auto-save-file-name
                             (make-auto-save-file-name))))
         (stale (and auto-save
                     (file-newer-than-file-p auto-save buffer-file-name))))
    (when stale
      (push (cons auto-save buffer-file-name) custom--stale-auto-saves)
      (unless custom--stale-auto-save-timer
        (setq custom--stale-auto-save-timer
              (run-at-time 2 nil #'custom--review-stale-auto-saves))))
    ;; `cl-letf' 在 let 作用域内临时替换某个函数的定义,退出后自动恢复:
    ;; 这里把 `sit-for' 换成 no-op,让 `after-find-file' 内部那 1 秒停顿
    ;; 「消失」,而它发出的警告消息照旧显示。本函数是 `after-find-file'
    ;; 的 :around advice(给原函数套一层壳,ORIG 即原函数);
    ;; C-h f custom--defer-auto-save-warning、C-h f cl-letf 可查。
    (cl-letf (((symbol-function 'sit-for)
               (if stale #'ignore (symbol-function 'sit-for))))
      (apply orig args))))

(defun custom--files-content-equal-p (file1 file2)
  "FILE1 与 FILE2 内容是否逐字节相同。"
  (and (file-exists-p file1) (file-exists-p file2)
       (equal (with-temp-buffer (insert-file-contents-literally file1)
                                (buffer-string))
              (with-temp-buffer (insert-file-contents-literally file2)
                                (buffer-string)))))

(defun custom--review-one-stale-auto-save (auto-save source)
  "审查单个陈旧 auto-save 文件 AUTO-SAVE,其源文件为 SOURCE。
内容与源文件相同则移入回收站;不同则询问是否删除(可能含未保存修改,
拒绝时保留并提示 recover-this-file)。AUTO-SAVE 已不存在时什么也不做。"
  (when (file-exists-p auto-save)
    (condition-case err
        (cond
         ((custom--files-content-equal-p auto-save source)
          (move-file-to-trash auto-save)
          (message "[auto-save] 已清理与源文件相同的陈旧文件: %s"
                   (file-name-nondirectory source)))
         ((y-or-n-p
           (format "%s 的陈旧 auto-save 与源文件不同(可能含未保存修改),删除? "
                   (file-name-nondirectory source)))
          (move-file-to-trash auto-save))
         (t
          (message "[auto-save] 已保留 %s,需要时 M-x recover-this-file"
                   auto-save)))
      (error
       (message "[auto-save] 处理 %s 失败: %s"
                auto-save (error-message-string err))))))

(defun custom--review-stale-auto-saves ()
  "空闲时处理 `custom--stale-auto-saves' 中的陈旧 auto-save 文件。
每个条目交 `custom--review-one-stale-auto-save' 逐个审查。无 client
frame 或 minibuffer 占用时顺延——daemon 哑 frame 上的 minibuffer 提示
会阻塞 server,必须等真实 client 就绪。"
  (let ((client-frame (seq-find (lambda (f) (frame-parameter f 'client))
                                (frame-list))))
    (if (or (not client-frame) (active-minibuffer-window))
        (setq custom--stale-auto-save-timer
              (run-at-time 2 nil #'custom--review-stale-auto-saves))
      (setq custom--stale-auto-save-timer nil)
      (with-selected-frame client-frame
        (let ((pending custom--stale-auto-saves))
          (setq custom--stale-auto-saves nil)
          (dolist (entry pending)
            (custom--review-one-stale-auto-save (car entry) (cdr entry))))))))

(advice-add 'after-find-file :around #'custom--defer-auto-save-warning)

(unless (or (daemonp) noninteractive)
  (server-mode 1))
#+end_src

** 右键菜单本地化
:PROPERTIES:
:CUSTOM_ID: context-menu-i18n
:END:

右键点击或按下 Shift+<f10> 弹出的上下文菜单，在 Emacs 内部由 keymap 结构表示。
本节通过递归遍历 keymap，在菜单绘制前将所有已登记的英文字符串替换为中文。对于未在翻译表中收录的项，则原样保留英文，不会引发错误。

同时挂载钩子到 =activate-menubar-hook= 与 =menu-bar-keymap= ，确保顶部菜单栏以及后续懒加载模式的菜单项也能自动完成中文转换。

#+begin_src emacs-lisp
(defun custom/context-menu--translate-string (string)
  "翻译 STRING；未登记时返回原字符串。"
  (if-let* ((translation
             (cdr (assoc (substring-no-properties string)
                         custom:context-menu-label-translations))))
      (apply #'propertize translation (text-properties-at 0 string))
    string))

(defun custom/context-menu--translate-object (object)
  "递归翻译 OBJECT 中的字符串。"
  (cond
   ((stringp object)
    (custom/context-menu--translate-string object))
   ((consp object)
    (mapcar #'custom/context-menu--translate-object object))
   (t object)))

(defun custom/context-menu--translate-menu-item (item)
  "翻译菜单项 ITEM 的标题和子菜单。"
  (when (and (consp item) (eq (car item) 'menu-item))
    ;; menu-item 形态: (menu-item LABEL BINDING . PROPS)
    ;;   LABEL  显示文字(字符串)   BINDING 键或子 keymap
    ;;   PROPS  :help 等属性 plist
    ;; 详见 (info "(elisp) Extended Menu Items")
    (let ((label-cell (cdr item))
          (binding (nth 2 item))
          (properties (nthcdr 3 item)))
      (when label-cell
        (setcar label-cell
                (custom/context-menu--translate-object (car label-cell))))
      (when (keymapp binding)
        (custom/context-menu--translate-keymap binding))
      (while (consp properties)
        (when (and (eq (car properties) :help)
                   (consp (cdr properties)))
          (setcar (cdr properties)
                  (custom/context-menu--translate-object (cadr properties))))
        (setq properties (cddr properties))))))

(defun custom/context-menu--translate-binding (_event binding)
  "翻译 keymap 中的一个条目 BINDING(EVENT 是 `map-keymap' 回调位,未使用)。"
  (cond
   ((and (consp binding) (eq (car binding) 'menu-item))
    (custom/context-menu--translate-menu-item binding))
   ;; (标题 . 子keymap) 形态:Geiser 的 (cons "Run" keymap) 子菜单即此形,
   ;; 标题在 car,递归子表。
   ((and (consp binding) (stringp (car binding))
         (keymapp (cdr binding)))
    (setcar binding
            (custom/context-menu--translate-string (car binding)))
    (custom/context-menu--translate-keymap (cdr binding)))
   ((keymapp binding)
    (custom/context-menu--translate-keymap binding))))

(defun custom/context-menu--translate-keymap (keymap)
  "递归翻译 KEYMAP 内的菜单标题。"
  (when (keymapp keymap)
    ;; keymapp 对符号型间接 keymap 也返回 t(如 menu-bar 的
    ;; describe-chinese-environment-map):car/cdr 前须先判 consp;
    ;; consp 下的 'keymap 头则由 keymapp 蕴含,无需再查。
    (when (and (consp keymap)
               (stringp (cadr keymap)))
      (setcar (cdr keymap)
              (custom/context-menu--translate-string (cadr keymap))))
    (map-keymap #'custom/context-menu--translate-binding keymap))
  keymap)

(defun custom/context-menu-translate (menu)
  "翻译菜单 KEYMAP 形态的 MENU（`context-menu-map' 与 `menu-bar-keymap' 共用）。"
  (custom/context-menu--translate-keymap menu))

;; context-menu-map 为 Emacs 28+ 内置,直接挂翻译 advice。
(unless (advice-member-p #'custom/context-menu-translate #'context-menu-map)
  (advice-add 'context-menu-map :filter-return #'custom/context-menu-translate))

;; 菜单栏翻译:启动时将 `global-map' 的 [menu-bar] 原地翻一次(覆盖 GUI 菜单栏
;; 的全局项);`menu-bar-keymap' 是 TTY 文本菜单与取用菜单栏的共同入口,再挂
;; advice 每次取用时翻一遍,连带覆盖懒加载包(ispell、Geiser 等)与 minor-mode
;; 菜单栏,无需逐包特判。translate-keymap 未命中原样返回且原地幂等。
(custom/context-menu--translate-keymap
 (lookup-key global-map [menu-bar]))

(unless (advice-member-p #'custom/context-menu-translate #'menu-bar-keymap)
  (advice-add 'menu-bar-keymap :filter-return #'custom/context-menu-translate))

;; GUI 菜单栏由 C 侧 `accelerate-menu' 在点击时直接读 keymap,不经
;; `menu-bar-keymap' advice:启动期一次性翻译之后才注册的懒加载条目
;; (envrc、so-long 等)在纯 GUI 会话里会保持英文。`activate-menubar-hook'
;; 在菜单栏每次实际展开前运行,把 [menu-bar] 子树再原地翻一遍,未命中
;; 原样返回,成本仅为一次 keymap 遍历。
(defun custom/context-menu--translate-menubar-on-activate ()
  "菜单栏展开前重翻 `global-map' 的 [menu-bar] 子树,兜住懒加载条目。"
  (custom/context-menu--translate-keymap
   (lookup-key global-map [menu-bar])))

(add-hook 'activate-menubar-hook
          #'custom/context-menu--translate-menubar-on-activate)

(with-eval-after-load 'magit-section
  (unless (advice-member-p #'custom/context-menu--translate-string
                           #'magit-menu-format-desc)
    (advice-add 'magit-menu-format-desc :filter-return
                #'custom/context-menu--translate-string)))

** Modeline
:PROPERTIES:
:CUSTOM_ID: modeline
:END:

不渲染每个窗口底部的 mode-line（=mode-line-format= 置 nil，每个窗口因此多出一行），
状态信息改由屏幕底部的一行承载：=minibuffer-line= 把 =format-mode-line= 的结果写入
Emacs 内部 buffer = *Minibuf-0*=，minibuffer 空闲时该 buffer 的内容即 echo area 的显示。

- *渲染* ：格式串与 =mode-line-format= 同构，=format-mode-line= 以选中窗口的 buffer 求值；
  右对齐需在 =:eval= 中手工补空格，=mode-line-format-right-align= 在 echo area 中无效。
  两条实测约束：格式串里首个带 face 的元素会把该 face 立为整行基础 face，故图标在格式串
  之外拼接并去掉属性；=mode-line-modified= 与 =mode-line-position= 的值带 Emacs 31 的
  =mode-line-elt-no= 属性，直接渲染得到 =*invalid*=，左段改用 =%l=/=%c= 字面量构造。
- *刷新* ：上游 timer 默认 60 秒才刷新一次，行号与修改标志会严重滞后，故实时性由
  =post-command-hook= 驱动，另用 idle timer 兜底异步变化（Flymake 报告、VC 状态），
  渲染结果与 buffer 内容一致时不重写，避免 echo area 反复重绘。
- *短消息* ：Eglot 连接、保存、缓冲区边界等短消息由 =set-message-functions= 末位接管，
  并入左半后右半的项目、VC、时间与电量保持可见；超过 echo area 一半宽度的消息与
  minibuffer 活动期交回 Emacs 默认显示（占满整行）。撤销时机与 echo area 一致
  （下一个输入事件），并额外在 4 秒空闲后撤下，避免状态行长期只剩消息。
- *信息源* ：VC、Flymake、Eglot、which-func 与时间电量分别由 =vc-mode= 、
  =flymake-mode-line-counters= 、=mode-line-misc-info= 等既有组件提供，状态行只做渲染。
- *固有取舍* ：整行消息与 minibuffer 输入期间状态行不可见；daemon 下多个 client 共享
  同一份内容（= *Minibuf-0*= 是全局 buffer）。

#+begin_src emacs-lisp
(setq-default mode-line-format nil)

;; nerd-icons 可用性只看包是否加载,不查 display 类型:TTY 终端已安装
;; Nerd Font,字形以普通文字渲染(见 GUI/TTY 混合 daemon 约束)。
(defvar custom:nerd-icons-available
  (require 'nerd-icons nil t)
  "nerd-icons 包是否已加载;图标渲染的统一守卫变量。")

(defconst custom/modeline--left-format
  '((:eval (if (buffer-modified-p) "**" "--"))
    " "
    (:eval (if buffer-file-name
               (file-name-nondirectory buffer-file-name)
             (buffer-name)))
    " L%l:%c "
    (:eval (when (bound-and-true-p flymake-mode)
             (format-mode-line flymake-mode-line-counters)))))

(defconst custom/modeline--right-format
  '((project-mode-line project-mode-line-format) " "
    (vc-mode vc-mode) " "
    (:eval (format-mode-line mode-line-misc-info))))

(defvar custom/modeline--message nil
  "当前并入状态行左半的短消息;nil 表示左半显示常规信息。")

(defvar custom/modeline--rendering nil
  "状态行渲染期标志;渲染途中求值的组件若发消息,退化为整行显示以避免递归。")

(defun custom/modeline--render ()
  "渲染状态行:左段在前,右段贴窗口右缘。
左段在有待显示的短消息时由消息顶替(见 `custom/modeline--handle-message'),右段不变。
图标在格式串之外拼接:format-mode-line 会把首个带 face 的元素的 face 当成
整行基础 face,图标字体的 (:family \"Symbols Nerd Font Mono\") 一旦进入格式串,
GUI 下整行都用图标字体渲染,ASCII 全成 tofu 方块;去属性后由默认字体渲染,
而默认字体本身带 Nerd Font 图标字形。"
  (let* ((width (window-total-width (minibuffer-window)))
         (left (or custom/modeline--message
                   (concat
                    (when custom:nerd-icons-available
                      (concat (substring-no-properties (nerd-icons-icon-for-buffer)) " "))
                    (format-mode-line custom/modeline--left-format nil (selected-window)))))
         (right (format-mode-line custom/modeline--right-format nil (selected-window)))
         (pad (max 1 (- width (string-width left) (string-width right)))))
    (concat left (make-string pad ?\s) right)))

(defun custom/modeline-refresh ()
  "把状态行写入 \" *Minibuf-0*\";内容不变则跳过,避免 echo area 反复重绘。
echo area 被消息或 minibuffer 输入占用时跳过,结束后由 post-command 恢复。
渲染期内置 `custom/modeline--rendering',使 VC/Eglot 等组件在求值途中发出的
消息退化为整行显示,不至于递归回本模块。"
  (unless (active-minibuffer-window)
    (let ((custom/modeline--rendering t)
          (text (format-mode-line minibuffer-line-format 'minibuffer-line (selected-window))))
      (with-current-buffer " *Minibuf-0*"
        (unless (equal (buffer-string) text)
          (erase-buffer)
          (insert text))))))

(use-package minibuffer-line
  ;; 上游 timer 每 60 秒才刷新,只作兜底;实时刷新由下方 hook 驱动。
  :custom (minibuffer-line-refresh-interval 30)
  :config
  ;; 该 face 继承 mode-line-inactive;本配置清 box 的 face 表只覆盖 TTY 路径,
  ;; GUI 下 box 仍有值,不清理则整行每个字符各画一个边框。
  (set-face-attribute 'minibuffer-line nil :box nil)
  (setq minibuffer-line-format '((:eval (custom/modeline--render))))
  (minibuffer-line-mode 1)
  (add-hook 'post-command-hook #'custom/modeline-refresh)
  (run-with-idle-timer 1 t #'custom/modeline-refresh))

;; 短消息并入状态行左半:Eglot 连接、保存、缓冲区边界等提示不再占满整行,
;; 右半的项目/VC/时间保持不变。注册在 `set-message-functions' 末位——首位必须
;; 留给 `inhibit-message'(`inhibit-message-regexps' 生效依赖它排在最前),而
;; `set-minibuffer-message' 在没有活动 minibuffer 时返回 nil,末位仍会被调用。
(defun custom/modeline--handle-message (text)
  "把短消息 TEXT 并入状态行左半,返回 t 表示已接管。
多行消息、超过 echo area 一半宽度的消息、minibuffer 活动期与渲染期返回 nil,
交回 Emacs 默认的整行显示。"
  (when (and (not custom/modeline--rendering)
             (not (active-minibuffer-window))
             (not (string-search "\n" text))
             (<= (string-width text) (/ (window-total-width (minibuffer-window)) 2)))

** Tab-line
:PROPERTIES:
:CUSTOM_ID: tab-line
:END:

基于 Emacs 内置的 =tab-line= 构建轻量且稳定的文件标签栏。

#+begin_note
*为什么不直接用 Emacs 默认的 tab-line？*
Emacs 原生 tab-line 会把当前窗口模式下的所有缓冲区（包括 Scratch、内部日志、补全列表、终端等）全部摆在标签栏里，不仅视觉杂乱，在多窗口分屏时还会互相干扰。
这里的定制方案实现了一套类似现代化 IDE 的标签栏逻辑：
1. *只对文件生效* ：通过白名单过滤，只给真正关联本地文件的缓冲区显示标签。终端、帮助、Scratch 与 Dashboard 等窗口不绘制标签栏。
2. *多客户端独立隔离* ：在 Emacs 守护进程架构下，每个连接进来的窗口（Frame）独立维护一份打开的文件标签序列，互不干扰。
3. *清晰的追加顺序* ：新打开的文件按顺序追加在右侧末尾。支持鼠标点击关闭、快捷键（=C-<tab>= / =C-S-<tab>=）循环切换，以及按键连续重排。
#+end_note

*** Per-frame 缓冲区跟踪
:PROPERTIES:
:CUSTOM_ID: tab-line-tracking
:END:

每个图形或终端窗口（Frame）拥有私有的标签列表，保存在窗口参数 =custom--frame-tab-buffers= 中。

生命周期流转说明：
- *打开并显示文件* ：由 =window-buffer-change-functions= 统一捕获，首次显示时追加到该窗口标签列表尾部并去重。
- *关闭文件缓冲区* ：当缓冲区被彻底杀死（kill）时，从所有 Frame 的标签列表中统一移除。
- *关闭窗口* ：Frame 被销毁时自动丢弃该 Frame 关联的标签列表。
- *切换项目* ：切换工程时清空当前窗口的标签列表，避免上一工程的遗留文件干扰视线。

#+begin_src emacs-lisp
(defun custom--tabs-get-frame-buffer-list (&optional frame)
  "返回 FRAME 的标签缓冲区列表。"
  (frame-parameter (or frame (selected-frame)) 'custom--frame-tab-buffers))

(defun custom--tabs-set-frame-buffer-list (buffers &optional frame)
  "设置 FRAME 的标签缓冲区列表为 BUFFERS。"
  (set-frame-parameter (or frame (selected-frame)) 'custom--frame-tab-buffers buffers))
#+end_src

注册与注销采用对称设计：注册仅在尾部追加（保持稳定顺序），注销负责安全移除，不直接对编辑窗口产生副作用。

#+begin_src emacs-lisp
(defun custom--tabs-should-track-p (buffer)
  "BUFFER 是否应进入标签列表:关联文件、存活、非 minibuffer。
`custom/tab-visible-p' 已含存活检查,此处只补 minibuffer 排除。"
  (and (custom/tab-visible-p buffer)
       (not (minibufferp buffer))))

(defun custom--tabs-register-buffer (buffer &optional frame)
  "将 BUFFER 注册到 FRAME 的标签列表尾部(去重)。"
  (let* ((target-frame (or frame (selected-frame)))
         (buffers (custom--tabs-get-frame-buffer-list target-frame)))
    (unless (memq buffer buffers)
      (custom--tabs-set-frame-buffer-list
       (append buffers (list buffer))
       target-frame))))

(defun custom--tabs-unregister-buffer (buffer &optional frame)
  "从 FRAME 的标签列表中移除 BUFFER。"
  (let* ((target-frame (or frame (selected-frame)))
         (buffers (custom--tabs-get-frame-buffer-list target-frame)))
    (when (memq buffer buffers)
      (custom--tabs-set-frame-buffer-list
       (delq buffer buffers)
       target-frame))))
#+end_src

通过 =window-buffer-change-functions= 捕获窗口内缓冲区的切换事件，将符合条件的文件加入标签列表。

#+begin_src emacs-lisp
(defun custom--tabs-on-window-buffer-change (frame-or-window)
  "缓冲区变更时,把新缓冲区注册到对应 frame。
FRAME-OR-WINDOW 可以是 frame(全局 hook)或 window(buffer-local hook)。
这是标签列表的唯一注册入口,不依赖 find-file-hook / server-switch-hook。"
  (cond
   ((frame-live-p frame-or-window)
    (walk-windows
     (lambda (window)
       (let ((buffer (window-buffer window)))
         (when (custom--tabs-should-track-p buffer)
           (custom--tabs-register-buffer buffer frame-or-window))))
     'no-mini frame-or-window))
   ((window-live-p frame-or-window)
    (let ((buffer (window-buffer frame-or-window))
          (frame (window-frame frame-or-window)))
      (when (custom--tabs-should-track-p buffer)
        (custom--tabs-register-buffer buffer frame))))))
#+end_src

*** 标签渲染
:PROPERTIES:
:CUSTOM_ID: tab-line-render

本节实现标签具体的文本格式化：
- *文件图标* ：若系统可用 Nerd Font 图标，根据文件类型自动在左侧渲染对应图标。
- *修改提示* ：当文件内容有修改未保存时，在标签名右侧追加实心圆点标记（=●=）。

(defun custom/tab-line-tabs ()
  "返回当前窗口标签栏要展示的 buffer 列表。"
  (or (custom--tabs-frame-buffers (selected-window))
      (list (current-buffer))))

(defun custom/tab-line-tab-name (buffer &optional _buffers)
  "生成 BUFFER 的标签名(图标 + 名称 + 修改标记)。"
  (with-current-buffer buffer
    (let ((key (list (buffer-name) buffer-file-name major-mode
                     (buffer-modified-p))))
      (if (equal key (car-safe custom/tab-line--name-cache))
          (cdr custom/tab-line--name-cache)
        (let* ((name (truncate-string-to-width
                      (buffer-name)
                      custom:tabs-name-max-width 0 nil t))
               (icon (when custom:nerd-icons-available
                       (nerd-icons-icon-for-buffer)))

                                (not (string-empty-p icon)))
                           (concat icon " ")
                         ""))
               (suffix (if (buffer-modified-p) " ●" ""))
               (label (concat prefix name suffix)))
          (setq custom/tab-line--name-cache (cons key label))
          label)))))

  "以接近 IDE 的样式格式化 TAB。

*** 按钮与 Face
:PROPERTIES:
:CUSTOM_ID: tab-line-faces
:END:

标签栏各个状态的外观完全基于 Emacs 预置语义 Face 继承：
- *当前标签* ：继承自 =mode-line= 的前景色与半粗体，形成鲜明对照。
- *非当前标签* ：继承自 =shadow= ，作为弱化的背景标签。
- *标签之间* ：不加任何分隔符。两块底色（=mode-line= 系与 =shadow= 系）本身已经把
  选中态与非选中态分开，再插竖线只会往 chrome 里堆多余元素。
  需要分隔线的是 *buffer（窗口面板）之间* ，那是 window divider 的职责，见
  [[#mixed-gui-tty-constraints][GUI/TTY 混合 daemon 约束]]。
- *标签栏下缘的横线* ：整条标签栏（标签、间隙与滚动按钮）共用一条细线，位置取文本下缘，
  即标签栏与正文的分界。颜色由主题 =border= 向正文底色插值（=custom--mix-color= ），
  比纯 =border= 更淡，避免再次出现「一条黑线横在那里」的突兀感。
- *关闭按钮与滚动按钮* ：鼠标悬停时分别继承 =error= （警示红色）与 =mode-line-highlight= 。
- *终端适配* ：在终端（TTY）环境下，通过透明策略统一移除背景底色，避免破坏终端的半透明效果。

(defun custom--mix-color (front back weight)
  "把颜色 FRONT 按 WEIGHT 混入 BACK(0=纯 BACK)后返回 #RRGGBB。
只在 palette 的 #RRGGBB 字面量上按通道插值:不用 `color-values',后者的
取值依赖显示帧,而本函数在 daemon 启动期(尚无帧)就会被调用。"
  (cl-flet ((channel (hex start)
              (string-to-number (substring hex start (+ start 2)) 16)))
    (apply #'color-rgb-to-hex
           (append (cl-loop for start in '(1 3 5)
                            collect (/ (+ (* (channel front start) weight)
                                          (* (channel back start) (- 1 weight)))
                                       255.0))
                   '(2)))))

(defun custom/apply-tab-line-divider (&rest _)
  "按当前主题重算标签栏下缘的横线。
整条标签栏(标签、间隙与滚动按钮)共用一条贴文本下缘的细线,即标签栏与正文的
分界。下划线落在标签与填充空白两类 face 上故整行连续,不需要盒模型(盒线无法
只画单边);颜色在主题 `border' 与正文底色之间插值,比纯 `border' 更淡,避免
横线重新变得抢眼。
`enable-theme-functions' 上重算,明暗主题切换后颜色随之更新。palette 取不到
色时保留既有属性:TTY 侧另有例外表 pin 下划线语义(见
[[#mixed-gui-tty-constraints][GUI/TTY 混合 daemon 约束]]),不依赖本函数。"
  (when-let* ((border (custom/terminal-theme-color 'border))
              (bg (custom/terminal-theme-color 'bg-main)))
    (dolist (face '(tab-line tab-line-tab-current tab-line-tab-inactive
                    tab-line-highlight tab-line-close-highlight))
      (set-face-attribute face nil
                          :underline (list :color (custom--mix-color border bg 0.5)
                                           :position t)))))

(add-hook 'enable-theme-functions #'custom/apply-tab-line-divider)

定义标签栏的交互操作：
- *隐藏而非杀死* ：点击标签的关闭按钮（或执行 =custom/tabs-close-buffer= ）时，执行的是 =bury-buffer= 并从当前窗口列表中注销，保留缓冲区内容供最近文件或后续跳转使用。真正杀死文件缓冲区请使用全局快捷键 =C-x k= 。
- *快捷键切换* ：=custom/tabs-next= 与 =custom/tabs-previous= 负责在当前 Frame 的标签序列中循环跳转。
- *标签重排* ：=custom/tabs-move= 调整当前标签在列表中的顺序，并绑定了 =repeat-mode= ，按下快捷键后只需连按 =n= / =p= / =m= 即可持续切换或移动。

#+begin_src emacs-lisp
(defun custom--tabs-switch-to-buffer (buffer &optional window)
  "在 WINDOW 中切换到 BUFFER,并刷新标签显示。
调用方保证 BUFFER 存活:tabs-next/prev 的实参来自 kill-buffer-hook
即时清理的 frame 列表,close-buffer 的实参经 `custom--tabs-visible-other-p'
(内含 `custom/tab-visible-p' 的存活检查)过滤。"
  (let ((target-window (custom--tabs-target-window window))
        (switch-to-buffer-obey-display-actions nil))
    (with-selected-window target-window
      (switch-to-buffer buffer)
      (tab-line-force-update t))))

(defun custom/tabs-next (&optional arg)
  "切换到当前标签列表中的下一个标签。ARG 为步数。"
  (interactive "p")
  (let* ((target-window (custom--tabs-target-window))
         (buffers (custom--tabs-frame-buffers target-window))
         (current (window-buffer target-window))
         (position (seq-position buffers current))
         (step (or arg 1)))
    (when (and position buffers)
      (custom--tabs-switch-to-buffer
       (nth (mod (+ position step) (length buffers)) buffers)
       target-window))))

(defun custom/tabs-previous (&optional arg)
  "切换到当前标签列表中的上一个标签。ARG 为步数。"
  (interactive "p")
  (custom/tabs-next (- (or arg 1))))

(defun custom--tabs-visible-other-p (candidate target-buffer)
  "CANDIDATE 是否可作 TARGET-BUFFER 关闭后的接替标签:存活且可见且非自身。
`custom/tab-visible-p' 已含存活检查。"
  (and (custom/tab-visible-p candidate)
       (not (eq candidate target-buffer))))

(defun custom/tabs-close-buffer (&optional window buffer)
  "在 WINDOW 隐藏 BUFFER 的标签(bury + unregister,不 kill buffer)。
BUFFER 默认为 WINDOW 当前显示的 buffer:窗口 buffer 恒存活,显式
BUFFER 的唯一调用方 mouse 回调已先行存活检查,不再重复守卫。"
  (interactive)
  (let* ((target-window (custom--tabs-target-window window))
         (target-buffer (or buffer (window-buffer target-window)))
         (target-frame (window-frame target-window)))
    (custom--tabs-unregister-buffer target-buffer target-frame)
    (when (eq target-buffer (window-buffer target-window))
      (if-let* ((next (seq-find (lambda (candidate)
                                  (custom--tabs-visible-other-p
                                   candidate target-buffer))
                                (custom--tabs-get-frame-buffer-list target-frame))))
          (custom--tabs-switch-to-buffer next target-window)
        (with-selected-window target-window
          (bury-buffer target-buffer)
          (let ((fallback
                 (seq-find (lambda (candidate)
                             (not (eq candidate target-buffer)))
                           (buffer-list target-frame))))
            (when fallback
              (switch-to-buffer fallback))))))
    (tab-line-force-update t)))

(defun custom/tab-line-close-tab (tab)
  "鼠标关闭按钮回调:与键盘 close 走同一路径(语义对称)。"
  (interactive)
  (let ((buffer (if (bufferp tab) tab (current-buffer))))
    (when (buffer-live-p buffer)
      (custom/tabs-close-buffer (custom--tabs-target-window) buffer))))

;; 标签重排:官方 tab-line-move-tab-forward 带 tabs-function 守卫,只对
;; 内置 tab-line-tabs-fixed-window-buffers 生效,对本模块 frame 列表驱动
;; 的 custom/tab-line-tabs 是静默 no-op,故直接操作 frame 列表实现。
(defun custom/tabs-move (&optional arg)
  "把当前标签在 frame 标签列表中移动 ARG 位(正向后移,负值前移)。"
  (interactive "p")
  (let* ((frame (selected-frame))
         (buffers (custom--tabs-get-frame-buffer-list frame))
         (buffer (current-buffer))
         (pos (seq-position buffers buffer)))
    (when (and pos (> (length buffers) 1))
      (let* ((rest (delq buffer buffers))
             (new-pos (mod (+ pos (or arg 1)) (length buffers))))
        (custom--tabs-set-frame-buffer-list
         (append (seq-take rest new-pos)
                 (list buffer)
                 (seq-drop rest new-pos))
         frame)
        (tab-line-force-update t)))))

(defun custom/tabs-move-backward (&optional arg)
  "把当前标签在 frame 标签列表中前移 ARG 位。"
  (interactive "p")
  (custom/tabs-move (- (or arg 1))))

;; C-<tab> / C-x M-<right> 连按的 repeat 入口(repeat-mode 已全局启用):
;; 单键 n/p/m 连续切换与移动,不删上述修饰键镜像入口。
(defvar custom/tabs-repeat-map (make-sparse-keymap))
(dolist (pair '((?n . custom/tabs-next)
                (?p . custom/tabs-previous)
                (?m . custom/tabs-move)))
  (define-key custom/tabs-repeat-map (char-to-string (car pair)) (cdr pair))
  (put (cdr pair) 'repeat-map 'custom/tabs-repeat-map))

(defun custom/git-repo-root (&optional file)
  "返回 FILE 所在 Git 仓库根目录(vc 内置 rev-parse,worktree/submodule 安全)。
不能改用 `vc-backend' 做类型判定:它只回答「对象是否被注册」,对目录恒 nil,

(defun custom/git--run (&rest args)

定义窗口弹出与路由的基础辅助函数：
- =custom/register-side-window= ：把匹配正则表达式的窗口固定挂载到底部、左侧或右侧侧边栏。
- =custom/display-buffer-in-main-window= ：定位当前窗口树中最上方的主编辑窗口并展示内容（用于编辑提交日志等）。
- =custom/display-or-focus= ：目标缓冲区若已在某个窗口中显示则直接聚焦，否则新建窗口，防止无休止地产生新的分屏。

#+begin_src emacs-lisp
(defun custom/register-side-window (regex side size)
  "把 REGEX 匹配的 buffer 路由到 SIDE 边的 side-window，占用 SIZE 比例。

REGEX : buffer-name 匹配字符串正则
SIDE  : bottom / right / left / top（符号）
SIZE  : 0~1 浮点比例

规则追加到 `display-buffer-alist' 末尾。顺序敏感：更具体的规则应先注册。"
  (add-to-list 'display-buffer-alist
               `(,regex
                 (display-buffer-in-side-window)
                 (side . ,side)
                 (window-height . ,size))
               t))

(defun custom--window-above-p (a b)
  "窗口 A 是否在 B 的上方(y 相同则比 x,左在前)。"
  ;; `window-edges' 返回 (LEFT TOP RIGHT BOTTOM):第 2 项是上边缘的行坐标
  ;; (Y 越小越靠上),第 1 项是左边缘;三个可选参数的含义见
  ;; C-h f window-edges。
  (let ((ea (window-edges a nil t t))
        (eb (window-edges b nil t t)))
    (or (< (nth 1 ea) (nth 1 eb))
        (and (= (nth 1 ea) (nth 1 eb))
             (< (nth 0 ea) (nth 0 eb))))))

(defun custom/display-buffer-in-main-window (buffer &optional _alist)
  "把 BUFFER 显示在「主编辑窗口」并选中。
主编辑窗口 = 当前 frame 内最靠上（y 坐标最小）的非 side-window 窗口。
保证无论光标当前在哪个窗口（如底部 magit），COMMIT_EDITMSG
都稳定落到上方编辑窗口，与「上编辑 + 下 magit」布局一致。

若无候选（如 frame 只剩 side-window），退化为 `display-buffer-pop-up-window'。

同时用作 `display-buffer-alist' 的 action 函数（参数 ALIST 被忽略）和
`server-window' 的值（server.el 调用时只传 buffer 一个参数）。"
  (let* ((frame (selected-frame))
         (candidates
          (seq-remove
           (lambda (w) (window-parameter w 'window-side))
           (window-list frame 'no-minibuf (frame-first-window frame))))
         (target (car (sort candidates #'custom--window-above-p))))
    (cond ((window-live-p target)
           (set-window-buffer target buffer)
           (select-window target)
           target)
          (t (display-buffer buffer '(display-buffer-pop-up-window))))))

(defun custom/display-or-focus (buffer action &optional select)
  "有则聚焦，无则按 ACTION 创建。
BUFFER 已在某窗口显示时，聚焦该窗口（SELECT 非 nil）；否则把 ACTION 绑定为
`display-buffer-overriding-action' 创建——它的优先级高于 `display-buffer-alist',
只影响本次调用，绕过 side-window 规则的同时不屏蔽其他包注册的路由。"
  (when (buffer-live-p buffer)
    (if-let* ((win (get-buffer-window buffer)))
        (when select (select-window win))
      (let ((display-buffer-overriding-action action))
        (display-buffer buffer)))))

*** GUI/TTY 混合 daemon 约束
:PROPERTIES:
:CUSTOM_ID: mixed-gui-tty-constraints
:END:

在日常使用中，同一个 Emacs 后台守护进程可能同时被图形界面（GUI）和终端命令行（=emacsclient -t=）连接。两者的显示机制有明显区别：

- *图形窗口 (GUI)* ：支持像素级透明度、原生矢量字体缩放与细条光标。
- *终端窗口 (TTY)* ：终端模拟器（如 Foot）自身已配置了透明背景。如果 Emacs 为所有文本强行绘制背景色，就会遮盖终端原生的透明效果，形成实色色块。

为了兼顾两端，本配置采取分流处理：
1. GUI 窗口直接应用 =custom:frame-background-opacity= 的透明度与字号。
2. 终端客户端连接时，调用 =custom/apply-terminal-faces= 清除各个样式的背景底色（设为 =unspecified= ），让终端原生透明效果直接透出；同时通过粗体与下划线增强选区、搜索匹配的高亮显示。

#+attr_org: :width 75
| 设置/包          | daemon 启动期陷阱              | TTY 行为                     | 处理方式                                          |
|------------------+--------------------------------+------------------------------+---------------------------------------------------|
| 光标类型         | =setq-default= 是全局副作用    | 后创 TTY frame 污染 GUI      | 用 =set-frame-parameter 'cursor-type=             |
| pixel-scroll     | 同上                           | 退化为行级滚动               | 无条件启用(GUI client 需要)                       |
| diff-hl(TTY)     | 无 fringe,fringe 指示器不可见  | 改用 margin                  | 上游 fallback 按 overlay 分流;勿启全局 margin mode|
| fringe 宽度      | 行号函数若清零 fringe          | —                            | 禁止在行号函数清零 fringe(详见下表)               |
| Modus 主题       | =(display-graphic-p)= 永远 nil | daemon/真彩 TTY 共用 palette | daemon 预载；standalone 真彩 TTY 也加载主题       |
| TTY 配色         | 无 alpha 通道                  | 主题前景 + 全 face 透明      | 清背景与反色，不覆盖主题前景                      |
| Nerd Font 图标   | =(display-graphic-p)= 永远 nil | 字形以文字渲染               | 守卫用 =custom:nerd-icons-available=,不查 display |
| buffer 分隔线    | =window-divider-mode= 是全局的 | 分隔线为图形终端特性         | 宽度写 per-frame 的 =right/bottom-divider-width=  |

=window-divider-mode= 那一行的陷阱值单独说明：它是全局 mode，启用时经 =window-divider-mode-apply= 用 =modify-all-frames-parameters= 把同一个宽度写进**所有** frame。旧配置因此在 TTY 分支调 =window-divider-mode -1= 兜底，结果是任何一个 =emacsclient -t= 连上来都顺手把 GUI frame 的分隔线一起清零，GUI 侧从此再也见不到分隔线。现在宽度直接按 =custom/apply-frame-appearance= 的 GUI/TTY 分支写进 frame 参数（GUI 1px，TTY 0），两个显示类型互不干扰。

分隔线本身是**buffer（窗口面板）之间**的那条细线。左右并排的面板原本靠 Emacs 默认的 1px =vertical-border= 分开，上下叠放的却什么都没有；改用分隔线后两个方向统一成同一条线（=vertical-border= 只在 TTY 侧继续生效）。宽度取 1px，颜色取主题 =border= 向正文底色按 0.65 插值（比标签栏下缘的 0.5 深一档，抵消抗锯齿的冲淡），渲染后与标签栏那条横线同一档浅色。

TTY 背景透明由 =custom/apply-terminal-faces= 实现。daemon 中 TTY 会继承全局主题，延迟加载的包也会继续定义带背景的 face，故不能维护有限清单，只能全量改写：

+ *全量清背景* ：恢复 TTY frame 的透明背景参数，对全部命名 face 统一设 =:background unspecified= 与 =:inverse-video nil=，fringe 与行号 gutter 不绘制主题底色。
+ *选择性恢复* ：=hl-line= 恢复主题 palette 的 =bg-dim= 背景；=org-block= 族恢复 =bg-inactive= 中性面板（终端无 fringe，靠这块底色给代码块成组）；选区、搜索、补全等状态仍用粗体和下划线区分。
+ *半透明配合* ：Foot 的 =alpha-mode=all= 让这块独立 RGB 背景同样应用终端 =alpha=0.88=，当前行是半透明色块而非实色或横线。
+ *自动重施* ：主题启用和 Lisp 文件加载后自动重刷，主题修改的 frame 参数与后出现的 face 都遵守透明策略；=early-init.el= 与 =window-system-default-frame-alist= 在 main.el 之前注入初始终端参数，避免启动闪屏。
+ *生效边界* ：只在真实 TTY 会话（非 batch、≥8 色）下生效，batch/GUI 为 no-op。

行号设置函数 =custom/setup-file-line-numbers= 故意不调 =(set-window-fringes ... 0)= ——=diff-hl= 和 =flymake= 的 fringe 指示器(=flymake-fringe-indicator-position= 设为 =left-fringe=)依赖 fringe 宽度,清零会让它们全部消失。

(defun custom/terminal-theme-color (key)
  "返回当前 Modus 主题 palette 中 KEY 对应的颜色,失败时返回 nil。
`modus-themes-get-color-value' 对未知键返回 `unspecified' 而非抛错,故

(defun custom/apply-terminal-faces (&optional frame)
  "让 TTY FRAME 的所有命名 face 使用终端透明背景。
清除背景与反色后，为 `hl-line' 恢复主题的柔和背景，为代码块恢复 `bg-inactive'
面板，并用
`custom:terminal-face-emphasis' 补充其余非颜色交互语义；所有前景色继续由
当前主题提供。Foot 需使用 alpha-mode=all 才能让 hl-line 背景半透明。
仅在真实 TTY（非 batch、至少 8 色）下生效；GUI 为 no-op。"
  (condition-case err
      (when (and (not noninteractive)
                 (not (display-graphic-p frame))
                 (>= (display-color-cells frame) 8))
        (let ((tty (or frame (selected-frame)))
              (hl-line-background (custom/terminal-theme-color 'bg-dim)))
          (with-selected-frame tty
            (dolist (parameter custom:terminal-frame-parameters)
              ;; 主题在启动后接管 foreground-color;只有初始 frame
              ;; defaults 用 unspecified-fg 避免 pre-theme 闪屏。
              (unless (eq (car parameter) 'foreground-color)
                (set-frame-parameter tty (car parameter) (cdr parameter))))
            (dolist (face (face-list))
              (set-face-attribute face tty
                                  :background 'unspecified
                                  :inverse-video nil))
            (dolist (entry custom:terminal-face-emphasis)
              (when (facep (car entry))
                (apply #'set-face-attribute
                       (car entry) tty (cdr entry))))
            (when (and hl-line-background (facep 'hl-line))
              (set-face-attribute 'hl-line tty
                                  :background hl-line-background
                                  :underline nil
                                  :extend t))
            (when-let* ((block-background
                         (custom/terminal-theme-color 'bg-inactive)))
              (dolist (face custom:terminal-block-faces)
                (when (facep face)
                  (set-face-attribute face tty
                                      :background block-background
                                      :extend t)))))))
    (error
     (message "custom/apply-terminal-faces: %s" (error-message-string err)))))

(defvar custom--tty-face-count 0
  "上次 TTY 刷新时的 face 总数;只有加载了定义新 face 的文件后才需要重刷。")

(defun custom/refresh-terminal-faces (&rest _)
  "重新对所有存活 TTY frame 应用透明背景策略。"
  (unless noninteractive
    (setq custom--tty-face-count (length (face-list)))
    (dolist (frame (frame-list))
      (unless (display-graphic-p frame)
        (custom/apply-terminal-faces frame)))))

(defun custom/refresh-terminal-faces-after-load (_file)
  "包加载引入新 face 时刷新所有 TTY frame。
多数 `load'/`require' 不定义 face,用 face 计数避免每次全量重刷。"
  (when (< custom--tty-face-count (length (face-list)))
    (custom/refresh-terminal-faces)))

(add-hook 'enable-theme-functions #'custom/refresh-terminal-faces)
(add-hook 'after-load-functions #'custom/refresh-terminal-faces-after-load)

(defun custom/apply-frame-appearance (&optional frame)
  "为 FRAME 应用所有 display-dependent 外观设置。
+ GUI: 字体高度、透明度、buffer 之间分隔线的宽度
+ TTY: 背景透明（清遮挡终端背景的 face 背景）、分隔线宽度清零。
  真彩 TTY 的前景色继续使用当前主题 palette。"
  (condition-case err
      (with-selected-frame (or frame (selected-frame))
        (let ((graphic-p (display-graphic-p)))
          (set-frame-parameter nil 'cursor-type (if graphic-p 'bar 'box))
          (cond (graphic-p
                 (set-face-attribute 'default nil :height custom:default-font-height)
                 (set-frame-parameter nil 'alpha-background custom:frame-background-opacity)
                 (set-frame-parameter nil 'right-divider-width 1)
                 (set-frame-parameter nil 'bottom-divider-width 1))
                (t
                 ;; 分隔线只在图形终端绘制。TTY 侧显式置 0,让 frame 参数与显示类型保持
                 ;; 一致(实测:TTY 上 0 与 1 渲染完全相同,窗口列数与 `vertical-border'
                 ;; 都不受宽度影响,清零不是为了修渲染)。
                 (set-frame-parameter nil 'right-divider-width 0)
                 (set-frame-parameter nil 'bottom-divider-width 0)
                 (custom/apply-terminal-faces)
                 ;; TTY 鼠标事件接收:GUI 下 xterm-mouse 是 no-op,收进 per-frame
                 ;; 分支与周边 TTY 逻辑约定一致,而非启动期全局裸调用。
                 (xterm-mouse-mode 1)))
          (force-mode-line-update t)))
    (error
     (message "custom/apply-frame-appearance: %s" (error-message-string err)))))

(add-hook 'after-make-frame-functions #'custom/apply-frame-appearance)
(unless (daemonp)
  (funcall #'custom/apply-frame-appearance (selected-frame)))

;; buffer（窗口面板）之间的分隔线。
;;
;; 左右并排的面板本来就有 1px 的 `vertical-border' 竖线,但上下叠放的两块面板之间
;; 什么都没有,两块底色直接相接 —— 这是「buffer 之间缺一条分隔线」缺的那一半。
;;
;; 宽度写进 per-frame 参数而非 `window-divider-mode':后者是全局 mode,
;; `window-divider-mode-apply' 用 `modify-all-frames-parameters' 给所有 frame 写同一
;; 个宽度,于是任何一个 TTY client 连上来都会把 GUI frame 的分隔线一起清零。宽度按
;; 显示类型分流到 frame 参数后,GUI 与 TTY 互不干扰（分流点在
;; `custom/apply-frame-appearance'）。
;;
;; 宽度 1px(Emacs frame 像素)。本机 frame 像素≈0.87 逻辑像素,1px 渲染成约 1.75
;; 设备像素的细线:看得见,又不至于在面板边界上拉出一条抢眼的粗线。
(setopt window-divider-default-places t
        window-divider-default-right-width 1
        window-divider-default-bottom-width 1)

(defun custom/apply-window-divider (&rest _)
  "按当前主题重算 buffer 之间分隔线的颜色。
颜色取主题 `border' 向正文底色插值,而不用纯 `border':纯色与正文的明度差太大,
一条横贯窗口的深色线会很扎眼。
插值权重 0.65(标签栏下缘那条横线是 0.5):1px 的宽度在分数缩放下会被抗锯齿摊
到约 1.75 设备像素、平均覆盖度约八成,颜色相应被冲淡两成;预先加深一点,渲染
后两者才落在同一档浅色上,不会一个重一个轻。
`enable-theme-functions' 上重算,明暗主题切换后随之更新。"
  (when-let* ((border (custom/terminal-theme-color 'border))
              (bg (custom/terminal-theme-color 'bg-main)))
    (set-face-attribute 'window-divider nil
                        :foreground (custom--mix-color border bg 0.65))))

(add-hook 'enable-theme-functions #'custom/apply-window-divider)

** 窗口与面板布局
:PROPERTIES:
:CUSTOM_ID: window-layout
:END:

通过 =display-buffer-alist= 统一规范各类辅助面板与工具窗口的弹出位置，让工作区布局保持整洁：
- *底部工具面板* ：
  - Magit 版本控制：固定在窗口底部，占用 40% 高度。
  - Ghostel 内置终端：固定在窗口底部，占用 33% 高度。
  - 帮助窗口（=*Help*=）：固定在窗口底部，占用 40% 高度。
  - 编译输出（=*compilation*=）与 Flymake 代码诊断：固定在窗口底部，占用 30% 到 33% 高度。
  - 全文搜索结果（=*grep*= / =*xref*=）：固定在窗口底部，占用 40% 高度。
- *提交信息编辑* ：通过 =server-window= 路由，保证 Git 提交信息（=COMMIT_EDITMSG=）始终在上方主编辑窗口打开，与下方的 Magit 状态面板互不冲突。
- *快捷退出* ：在上述只读辅助窗口中按下 =q= ，直接清理并杀死缓冲区，不再在后台堆积无用窗口。

#+begin_src emacs-lisp

  "FRAME（默认 selected-frame）是否可呈现主题的完整前景 palette。"
  (with-selected-frame (or frame (selected-frame))
    (or (display-graphic-p)
        (and (not noninteractive)
             (>= (display-color-cells) 256)))))

(defun custom/color-scheme-init ()
  "初始化颜色方案适配：读取 Darkman D-Bus 模式并应用主题、注册监听器。

  (let ((initial-mode (or (custom/color-scheme-get-from-dbus)

  "在 FRAME 可用时补齐与主题相关的 frame 初始化。

      (if (not custom/color-scheme--initialized)
          (custom/color-scheme-init)
        (custom/color-scheme--load-theme-if-needed
         (custom/color-scheme--theme-for-mode
          custom/color-scheme-current-mode))))))

(custom/color-scheme-init)

** DWIM 智能编辑函数
:PROPERTIES:
:CUSTOM_ID: editing-dwim
:END:

所谓 DWIM 即「按我的意图操作」（Do What I Mean），这些函数会根据当前是否有选区、光标所在上下文自动选择最合适的操作：

- =custom/copy-dwim= ：有选区时复制选区，没有选区时自动复制当前整行（类似现代代码编辑器的习惯）。
- =custom/cut-dwim= ：有选区时剪切选区，没有选区时剪切当前整行。
- =custom/rename-dwim= ：如果当前文件已开启 LSP，则调用 LSP 进行项目级重命名；普通文件则重命名该文件本身。
- =delete-selection-mode= ：选中文字后输入任何字符或执行粘贴，自动覆盖替换选中的内容。

#+begin_src emacs-lisp
(defun custom/copy-dwim ()
  "智能复制:有选区时复制选区,否则复制当前行。"
  (interactive)
  (cond
   ((use-region-p)
    (kill-ring-save (region-beginning) (region-end))
    (deactivate-mark)
    (message "已复制选区"))
   (t
    (kill-ring-save (line-beginning-position) (line-beginning-position 2))
    (message "已复制当前行"))))

*** 关闭文件历史
实现类似浏览器「Ctrl+Shift+T」的误关恢复功能：
系统会自动记录最近关闭的 20 个本地文件路径，按下 =C-S-t= （或终端下的 =C-x T= ）即可按倒序重新打开最近关闭的文件。
该机制会自动忽略内部隐藏缓冲区与自动保存临时文件，守护进程常驻也不会累积垃圾。

#+begin_src emacs-lisp
(defconst custom:closed-files-max 20
  "关闭文件历史长度上限。")

(defvar custom--closed-files nil
  "最近关闭的文件名列表,最新在前。")

(defun custom--on-kill-buffer ()
  "把刚关闭的文件缓冲区记入关闭历史。
排除内部 I/O 路径:库代码常以 `find-file-noselect' + `kill-buffer'
静默读写文件(如 `customize-dirlocals' 读 .dir-locals.el),只判
`buffer-file-name' 会把它们收进历史。过滤规则:隐藏名(\" \"前缀)
buffer、no-littering var/ 数据目录(recentf/custom.el 等落点)与
备份/自动保存文件(#...#、~ 结尾)一律不记。"
  (when-let* ((file (buffer-file-name)))
    (unless (or (string-prefix-p " " (buffer-name))
                (file-in-directory-p
                 file (expand-file-name "var" user-emacs-directory))
                (string-match-p "\\`\\.?#\\|~\\'" (file-name-nondirectory file)))
      (setq custom--closed-files
            (cons file (delete file custom--closed-files)))
      (when (> (length custom--closed-files) custom:closed-files-max)
        (setq custom--closed-files
              (seq-take custom--closed-files custom:closed-files-max))))))

(add-hook 'kill-buffer-hook #'custom--on-kill-buffer)

(defun custom/reopen-closed-file ()
  "重新打开最近关闭且仍存在的文件。"
  (interactive)
  (let ((file (seq-find #'file-exists-p custom--closed-files)))
    (unless file
      (user-error "没有可重新打开的文件"))
    (setq custom--closed-files (delete file custom--closed-files))
    (find-file file)))
#+end_src

*** 语言能力表

所有编程语言的 Major mode、Tree-sitter 映射、LSP 服务端与格式化工具均通过 =custom:language-capabilities= 集中声明。

#+begin_tip
*如何添加或调整一门语言？*
当接手维护需要添加一种新语言或更换 LSP 服务端时，无需在配置各处寻找钩子，只需在 =custom:language-capabilities= 列表中追加或修改对应行即可：
- =:modes= ：该语言相关的 major-mode 列表（传统模式在前，ts-mode 在后）。
- =:ts-mode= ：对应的 Tree-sitter mode（若无对应的 ts 模式则填 nil）。
- =:server= ：LSP 服务器的启动命令行（例如 =("rust-analyzer")= ，若不启用 LSP 则填 nil）。
- =:formatter= ：Apheleia 格式化工具符号（例如 =prettier-typescript= ，显式禁用则填 nil）。
#+end_tip

字段定义一览：

#+attr_org: :width 70
| 字段       | 含义                                          | 派生消费者                                |
|------------+-----------------------------------------------+-------------------------------------------|
| =:modes=     | 生效的所有 major mode(传统 mode 在前,ts 在后) | =major-mode-remap-alist=、Apheleia mode-alist |
| =:ts-mode=   | Tree-sitter 对应 mode(nil = 无 ts 版本)       | =major-mode-remap-alist=                      |
| =:server=    | LSP server 启动命令(nil = 无 LSP)             | =eglot-server-programs=                       |
| =:formatter= | Apheleia formatter 符号(nil = 显式禁用)     | Apheleia mode-alist                       |

(defun custom/language--derive-eglot-programs ()
  "把 `custom:language-capabilities' 按 :server 展平为 eglot 条目。
同一 server 的多语言合并为 (MODE... . SERVER-CMD) 一条(:server 是命令行
列表,同命令的不同写法按 `equal' 视为同一 server);返回的 mode 列表是
新 cons,不与能力表共享结构。"
  (let (groups)
    (dolist (entry custom:language-capabilities)
      (let ((server (plist-get entry :server)))
        (when server
          (let ((existing (assoc server groups)))
            (if existing
                (setcdr existing
                        (append (cdr existing) (plist-get entry :modes)))
              (push (cons server (copy-tree (plist-get entry :modes)))
                    groups))))))
    (mapcar (lambda (group) (cons (cdr group) (car group)))
            (nreverse groups))))

#+begin_src emacs-lisp
;; org block 批量缩进(函数 formatter,协议同 apheleia-indent-lisp-buffer:
;; 在 scratch 拷贝上变换后回调)。org 无安全的整文件 formatter——pandoc
;; org round-trip 会破坏 tangle 转义(,*)与 drawer/keyword 顺序,正文缩进
;; 改变列表层级语义——需要格式化的只有 src block 内的代码:对每个 block
;; 取出内容,在临时 buffer 激活该语言的 major mode 缩进后写回。org 语言
;; 数据块(capture 模板)内容是 org 文本而非代码,跳过。不进 mode-alist:
;; C-c c f 保持「格式化当前代码文件」语义,入口为 C-c o f 的
;; custom/format-org-src-blocks,经 apheleia 跑以复用 RCS diff 对
;; point/滚动位置的保护。
(cl-defun custom--format-org-src-blocks
    (&key buffer scratch callback &allow-other-keys)
  "按各语言的 major mode 缩进 org BUFFER 中全部 src block 代码。
SCRATCH 为承载变换的临时 buffer,CALLBACK 在变换完成后调用。
块在 org 列表/大纲里的缩进由 #+begin_src 行的缩进决定:写回前
先整体 dedent 再按 mode 缩进,最后按 base 缩进平移回去,保证
列表内代码块的 org 层级语义不变。"
  (with-current-buffer scratch
    (funcall (buffer-local-value 'major-mode buffer))
    (let (regions)
      (org-element-map (org-element-parse-buffer) 'src-block
        (lambda (el)
          ;; `and-let*' = 逐个求值、任一为 nil 即整体返回 nil 的短路绑定串
          ;; (等价于嵌套 when-let);末尾 ((fboundp mode)) 是只判断不绑变量的条件。
          (and-let* ((value (org-element-property :value el))
                     (lang (org-element-property :language el))
                     (mode (and (not (equal lang "org"))
                                (org-src-get-lang-mode lang)))
                     ((fboundp mode)))
            ;; 31 起 org-element 不再提供 src-block 的
            ;; :contents-begin/:contents-end;:value 长度对含
            ;; 转义行(,* 与 ,#+)的块会少算,故只记 :post-affiliated
            ;; (#+begin_src 行首,已跳过 #+name: 等前置行)与元素 :end,
            ;; 内容区终点在替换时向前搜 #+end_src 行首取得。
            (push (list (org-element-property :post-affiliated el)
                        (org-element-property :end el)
                        mode)
                  regions))))
      ;; 从后往前替换,避免前面的写回使后续位置失效。
      (pcase-dolist (`(,beg ,el-end ,mode) regions)
        (goto-char beg)
        (let ((base-indent (current-indentation)))
          (forward-line 1)
          (let* ((cbeg (point))
                 ;; src block 体内的 #+end_src 字面量按 org 规则必须写成
                 ;; ,#+end_src(带逗号转义),首个顶格匹配即真正的块尾;
                 ;; 搜索上界取元素 :end,残缺块不会吞掉后文。
                 ;; save-excursion 保住 cbeg:search 会把 point 留在 match
                 ;; 末尾,后续 delete/insert 必须回到内容区起点。
                 (cend (save-excursion
                         (re-search-forward "^[ \t]*#\\+end_src" el-end t)
                         (line-beginning-position)))
                 (content (buffer-substring-no-properties cbeg cend)))
            (with-temp-buffer
              (insert content)
              ;; 先把 org 层缩进整体 dedent 到第 0 列,再按语言 mode
              ;; 从 0 基准重排;否则 org 缩进会作为初始缩进残留进结果。
              (when (> base-indent 0)
                (indent-rigidly (point-min) (point-max) (- base-indent)))
              (funcall mode)
              (indent-region (point-min) (point-max))
              (when (> base-indent 0)
                (let ((pad (make-string base-indent ?\s)))
                  (goto-char (point-min))
                  (while (not (eobp))
                    ;; 空行不补 pad,避免写回行尾空白。
                    (unless (looking-at-p "[ \t]*$")
                      (insert pad))
                    (forward-line 1))))
              (setq content (buffer-substring-no-properties (point-min) (point-max))))
            (delete-region cbeg cend)
            (insert content)))))
    (funcall callback)))

    (side . left) (window-width . 0.2))

(defun custom/dired--panel-setup (buffer)
  "对 BUFFER 应用面板定制:窄视图、header 路径与面板访问键。
所有 Dired buffer 共享 `dired-mode-map',面板 remap 必须落在 buffer
私有的 keymap copy 上,否则会污染其他 Dired buffer。"
  (with-current-buffer buffer
    (dired-hide-details-mode 1)
    (setq-local header-line-format 'default-directory)
    (use-local-map (copy-keymap dired-mode-map))
    (define-key (current-local-map) [remap dired-find-file]
                #'custom/dired-find-file-in-main)
    (define-key (current-local-map) [remap dired-up-directory]
                #'custom/dired-up-in-panel)
    (define-key (current-local-map) [mouse-2]

(defun custom/dired--panel-visit (filename)
  "面板访问语义:目录原地替换面板 buffer,文件进主编辑窗口。
FILENAME 须为绝对路径(`dired-get-file-for-visit' 对 =..= 返回
相对名,调用前展开)。目录不能走 `find-alternate-file':其内部
`switch-to-buffer' 会被 side-window 拒绝而把新 Dired 投到其他窗口,
故显式 `set-window-buffer' 替换面板窗口并 kill 旧面板 buffer;
`dired-noselect' 天然复用已存在的同目录 Dired buffer,不堆积。"
  (setq filename (expand-file-name filename))
  (if (not (file-directory-p filename))
      (custom/display-buffer-in-main-window (find-file-noselect filename))
    (let* ((old-buf (current-buffer))
           (new-buf (dired-noselect filename)))
      (unless (eq new-buf old-buf)
        (custom/dired--panel-setup new-buf)
        (set-window-buffer nil new-buf)
        (set-buffer new-buf)
        (kill-buffer old-buf)))))

(defun custom/org-capture--experience-file ()
  "生成经验卡片目标文件路径(人类域,从 `agenote fields --category' 拉分类)。"
  (custom--ensure-org-directories)
  (let* ((choices (or (condition-case nil
                          (split-string
                           (agenote-call-string 'human "fields" "--category")
                           "\n" t "[ \t]+")
                        (error nil))
                      '("emacs" "guix" "general" "gamedev" "devops"
                        "research" "tooling")))
         (cat (completing-read "经验卡类别: " choices nil t))
         (dir (expand-file-name (concat "experiences/" cat)
                                custom:org-directory)))
    (setq custom/org-capture--last-category cat)
    (unless (file-directory-p dir)
      (make-directory dir t))
    (expand-file-name (format "%s.org" (format-time-string "%Y%m%d-%H%M%S"))
                      dir)))

(defun custom/panels-toggle ()
  "一键开关三面板布局(左 Dired / 底终端 / 右 Agent)。

  (interactive)
  (let ((buffers (custom/visible-panel-buffers)))
    (if (seq-some #'get-buffer-window buffers)
        (dolist (buf buffers)
          (when-let* ((win (get-buffer-window buf)))
            (delete-window win)))
      (custom/panel-dired)
      (custom/open-terminal)
      (agent-shell)))
  (when-let* ((main (seq-find
                     (lambda (w) (not (window-parameter w 'window-side)))
                     (window-list (selected-frame)))))
    (select-window main)))

** Completion 框架
:PROPERTIES:
:CUSTOM_ID: completion
:END:

本配置完全基于 Emacs 30 与 31 原生内置的补全机制，不依赖任何第三方补全框架（如 Vertico 或 Corfu）。

#+begin_note
*纯内置补全架构的设计考量*
1. *Minibuffer 模糊匹配* ：Emacs 31 内置的 =*Completions*= 候选窗口默认支持随打随滤。配置开启 =flex= 模糊匹配，并按 =savehist= 记录的历史使用频率自动将高频命令排在前面。Minibuffer 内使用 =M-<up>= / =M-<down>= 快速上下挑选候选，按回车直接执行。
2. *行内幽灵文本 (Ghost-Text)* ：代码编辑区使用内置 =completion-preview-mode= 。打字时在光标右侧呈现灰色补全预览，按 =TAB= 直接接受，按 =M-n= / =M-p= 循环切换不同候选。相比下拉弹窗菜单，行内幽灵文本更加安静、不遮挡上下文代码。
3. *即开即用零延迟* ：不依赖复杂的外置插件，在图形窗口与命令行终端下体验高度一致。
#+end_note

*** Minibuffer 补全栈
:PROPERTIES:
:CUSTOM_ID: completion-minibuffer
:END:

配置内置 Minibuffer 的匹配算法与排序策略：
- 匹配样式：采用 =flex= （模糊匹配）配合 =basic= （前缀兜底）。例如输入 =mbl= 即可直接匹配 =magit-blame= 。
- 排序规则：采用 =historical= ，优先推荐近期输入过的命令。

#+begin_src emacs-lisp
;; 内置 *Completions*:Emacs 31 的即显 + 随打更新是默认行为,无需显式
;; 启用;此处只设定匹配样式与排序。flex 覆盖日常模糊输入,basic 兜底
;; 前缀与实体匹配。
(setq completion-styles '(flex basic)
      completions-sort 'historical)

;; completion-preview(Emacs 30 内置):打字时 ghost-text 行内补全预览,
;; 与 *Completions*(minibuffer 层)互补,capf 后端(eglot LSP)全部复用。
;; TAB 接受候选,M-n/M-p 循环候选,M-i 补全公共前缀(再按弹 *Completions*);
;; 预览激活时 M-f/M-<right> 逐词、C-M-f/C-M-<right> 逐表达式部分接受。
;; 循环与部分接受命令上游内置但默认键位被注释,此处显式接线;
;; remap 仅在预览激活的 buffer 生效,不影响普通词/表达式移动。
(use-package completion-preview
  :demand t
  :config
  (global-completion-preview-mode 1)
  (define-key completion-preview-active-mode-map (kbd "M-n")
              #'completion-preview-next-candidate)
  (define-key completion-preview-active-mode-map (kbd "M-p")
              #'completion-preview-prev-candidate)
  (define-key completion-preview-active-mode-map [remap forward-word]
              #'completion-preview-insert-word)
  (define-key completion-preview-active-mode-map [remap forward-sexp]
              #'completion-preview-insert-sexp))
#+end_src

** Guix 集成与 daemon 预热
:PROPERTIES:
:CUSTOM_ID: guix-daemon
:END:

在后台守护进程模式下运行时的预热优化：
- *为什么预热？* 后台守护进程在系统开机时静默启动，多花费一两秒对用户完全无感。但如果在日常打开 =emacsclient= 时才首次加载 Magit 或 Org-agenda，就会有明显的卡顿。
- *预热范围* ：在后台安全预加载常用交互库（Magit、Org-agenda、Org-capture、Org-roam、Apheleia、TRAMP），提前消除首次使用的冷启动耗时。重型后台子进程（如 LSP 或外部聊天）仍保持延迟按需加载。

#+begin_src emacs-lisp
(defconst custom:daemon-warmup-features
  '(org-agenda org-capture org-roam
               apheleia magit tramp)
  "daemon 启动阶段预载的常用交互 feature 白名单。")

(defun custom/daemon-warmup ()
  "同步预载 `custom:daemon-warmup-features'，让首个 client 直接复用。"
  (let ((gc-cons-threshold most-positive-fixnum)
        (gc-cons-percentage 0.6)
        failed)
    (dolist (feature custom:daemon-warmup-features)
      (condition-case err
          (unless (require feature nil t)
            (push (cons feature "未找到 feature") failed))
        (error
         (push (cons feature (error-message-string err)) failed))))
    (garbage-collect)
    (when failed
      (message "[custom-config] daemon 预热失败: %S" (nreverse failed)))
    (null failed)))
#+end_src

| 刷新   | =custom/dashboard--refresh-in-window=         | 在该窗口上下文里强制重渲染并装饰，resize 与 frame 就绪回调共用                 |
| 装饰   | =custom/dashboard--decorate-headings=         | 收集板块标题 overlay，倒序逐个装饰，最后整体居中                               |
| 步骤 1 | =custom/dashboard--replace-section-separator= | 板块尾第一段空行换分割线，并给板块内行加行间距                                 |
| 步骤 2 | =custom/dashboard--indent-heading=            | 标题行缩进 4 列，并把标题 overlay 拨回原位                                     |
| 步骤 3 | =custom/dashboard--suffix-heading-key=        | 快捷键右贴到标题行行尾，补齐到版心宽                                           |
| 收尾   | =custom/dashboard--center-groups=             | 板块区按版心统一前缀（块内左对齐），其余行按自身行宽各自居中                   |
| 跳过   | =custom/dashboard--refresh-if-stale=          | 窗口宽度与上次渲染一致时跳过一次全量重渲染                                     |

=dashboard-open= 渲染出来的只是普通文本，行首图标、缩进、分割线与居中全靠
渲染后的“装饰”补上，而装饰必须知道目标窗口的宽度，所以总在显示 dashboard
的窗口上下文里执行。三步的先后不能换：先量标题宽度，再缩进并挪 overlay，
最后才按版心宽把快捷键贴到行尾。

*** 按钮与图标

顶部四个按钮由数据表 =custom/dashboard--nav-buttons= 描述，每条是
=（ICON TITLE HELP COMMAND）= 四元组；图标统一经 =custom/dashboard-button-icon=
取 nerd-icons octicon。四个 =COMMAND= 都是具名 interactive 命令，可以单独
=M-x= 调用调试；而 widget 的 =:action= 回调以 =(widget event)= 两参调用，
所以这些命令用 =&rest= 兜底。增删按钮只改这张数据表。

*** 宽度自适应与防抖

- 版心宽 = =custom:dashboard-content-ratio= × 窗口正文宽（=custom/dashboard--content-width= ）；低于 =custom:dashboard-min-content-width= 的窗口不做全量渲染，保留上一次的可读内容。
- 拖拽 resize 时每个中间宽度都会触发 =window-size-change-functions= ，逐次全量渲染会卡住主循环；=custom/dashboard--on-resize= 只挂一个 0.3s 的 idle timer，静止后合并刷新一次。
- =custom/dashboard--rendered-width= 记住上次渲染宽度，宽度相符的事件（含同宽新 frame）零成本跳过；GUI daemon 首帧可能按哑 frame 的宽度渲染，=custom/dashboard--on-frame-make= 在 frame 就绪后比较宽度自愈。
- 自己试：改完比例 =M-x dashboard-open= 看效果；=C-h v custom:dashboard-content-ratio= 、=C-h v custom:dashboard-min-content-width= 查当前值与文档。

(defun custom/dashboard--compress-middle-dirs (abbrev)
  "把 ABBREV 的中间目录压为首字母,返回压缩后的完整路径。
首段(根或卷标)与末段(文件名)不压缩;隐藏目录(.x)保留点号取
第二个字符,空目录项原样保留。"
  (let* ((parts (split-string abbrev "/" t))
         (len (length parts))
         (head (car parts))
         (file (car (last parts)))
         (middle (cl-subseq parts 1 (1- len)))
         (compressed
          (seq-map
           (lambda (dir)
             (cond ((string-empty-p dir) dir)
                   ((string-prefix-p "." dir)
                    (if (> (length dir) 1)
                        (concat "." (substring dir 1 2))
                      dir))
                   (t (substring dir 0 1))))
           middle)))
    (concat head "/"
            (mapconcat #'identity compressed "/")
            "/" file)))

(defun custom/dashboard--truncate-to-width (path width)
  "PATH 超出 WIDTH 列时头部截断补 ...,WIDTH 不足 3 列则只留 ...。
截断按显示宽度计(CJK 字符占 2 列),取显示宽度不超过 WIDTH-3 的
最长前缀,保证结果连同 ... 不超宽;直接用 substring 按字符数截
会在 CJK 长文件名上 args-out-of-range,中断整个 dashboard 渲染。
未超宽时原样返回 PATH。"
  (if (<= (string-width path) width)
      path
    (if (<= width 3)
        "..."
      (let ((limit (- width 3))
            (chars 0)
            (cols 0))
        (catch 'exceed
          (dolist (ch (string-to-list path))
            (let ((w (char-width ch)))
              (when (> (+ cols w) limit)
                (throw 'exceed t))
              (setq cols (+ cols w)
                    chars (1+ chars)))))
        (concat (substring path 0 chars) "...")))))

(defun custom/dashboard--shorten-path (path _type)
  "dashboard-shorten-path 的替代:超版心的路径两级降级。
先压缩中间目录为首字母(隐藏目录以 . 开头,取其第二个字符),仍超
则头部 ... 截断。显示文本与真实路径经 plugin 的 path-alist 解耦,
缩短不影响点击跳转。_TYPE 是 dashboard 传入的展示类型,本实现不用
(下划线前缀表示占位)。"
  (let* ((abbrev (abbreviate-file-name path))
         (width (custom/dashboard--content-width))
         (parts (split-string abbrev "/" t))
         (p (if (<= (length parts) 3)
                abbrev
              (custom/dashboard--compress-middle-dirs abbrev))))
    (custom/dashboard--truncate-to-width p width)))

(defun custom/dashboard--dashboard-window ()
  "返回 client frame 中显示 dashboard 的窗口,无则 nil。
必须过滤掉 daemon 的 initial frame(它没有 'client 参数):switch-to-buffer
会把 dashboard 泄漏到那个超宽的哑 frame 上,误选它版心宽度就错了。"
  (car (seq-filter
        (lambda (w)
          (frame-parameter (window-frame w) 'client))
        (get-buffer-window-list dashboard-buffer-name nil 0))))

(defun custom/dashboard--refresh-in-window (&optional win)
  "在显示 dashboard 的窗口 WIN 上下文里强制重渲染并装饰。
WIN 缺省重新定位 dashboard 窗口;调用方已持有时透传,避免二次
get-buffer-window 查询。渲染与装饰都必须以该窗口为 selected:版心、
路径缩短和居中前缀的宽度全部取自这里,别的 frame 上下文算出来
是错的。"
  (when-let* ((win (or win (custom/dashboard--dashboard-window))))
    (with-selected-window win
      (setq custom/dashboard--rendered-width (window-body-width win))
      (dashboard-open)
      ;; dashboard-open 的 switch-to-buffer 可能切走 selected,
      ;; 装饰必须显式仍以目标窗口为准
      (custom/dashboard--decorate-headings win))))

(defun custom/dashboard--heading-overlays ()
  "收集 dashboard buffer 内有效的标题 overlay,按位置排序。
重渲染后旧 overlay 塌缩成空壳仍残留,按起止位置剔除。"
  (sort
   (seq-filter
    (lambda (ov)
      (and (eq (overlay-get ov 'face) 'dashboard-heading)
           (> (overlay-end ov) (overlay-start ov))))
    (overlays-in (point-min) (point-max)))
   (lambda (a b) (< (overlay-start a) (overlay-start b)))))

(defun custom/dashboard--replace-section-separator (ov separator)
  "把板块尾第一段空行换成 SEPARATOR,并为板块内行加行间距。
OV 是板块标题 overlay。板块边界 = 标题行后第一个空行:从标题行起
一遍扫描,顺手收集行范围;扫到空行即边界,走到 point-max 仍无
空行则整体跳过(末板块无分割线)。"
  (save-excursion
    (goto-char (overlay-start ov))
    (let ((lines '())
          blank)
      (while (and (not blank) (< (point) (point-max)))
        (let ((beg (line-beginning-position))
              (end (line-end-position)))
          (if (= end beg)
              (setq blank t)
            (push (cons beg end) lines)
            (forward-line 1))))
      (when blank
        ;; 板块内标题与条目行统一行间距:不插空行,靠 GUI 行距
        ;; 拉开;标题行也在内,与首条目保持同一间距
        (dolist (line lines)
          (put-text-property (car line) (cdr line)
                             'line-spacing custom:dashboard-line-spacing))
        (delete-region (line-beginning-position) (line-end-position))
        (insert separator)))))

(defun custom/dashboard--indent-heading (ov)
  "标题行缩进 `custom:dashboard-heading-indent' 列,并把 OV 拨回原位。
heading overlay 是 front-advance:TTY 无 icon 时其起点恰在行首,行首
插入的缩进会被吞进 overlay(display 替换后消失)。记住原文本范围,
插入后把 overlay 拨回。缩进继承行首的 line-prefix,否则标题行脱离
板块整体缩进。"
  (goto-char (overlay-start ov))
  (let ((line-start (line-beginning-position))
        (off-s (- (overlay-start ov) (line-beginning-position)))
        (off-e (- (overlay-end ov) (line-beginning-position))))
    (goto-char line-start)
    (let ((prefix (get-text-property line-start 'line-prefix)))
      ;; 缩进是 display 行首字符,line-spacing 由它决定,须带上
      (insert (propertize
               (make-string custom:dashboard-heading-indent ?\s)
               'line-prefix prefix
               'line-spacing custom:dashboard-line-spacing))
      (move-overlay ov
                    (+ line-start custom:dashboard-heading-indent off-s)
                    (+ line-start custom:dashboard-heading-indent off-e)))))

(defun custom/dashboard--suffix-heading-key (ov key width icon-w)
  "把 KEY 右贴到标题行行尾,补齐到 WIDTH 版心宽(先扣掉 ICON-W 图标宽)。
OV 提供标题显示文本,用于折算已占用宽度;须在
`custom/dashboard--indent-heading' 之后调用,point 此时落在标题行。"
  (let* ((name (or (overlay-get ov 'display)
                   (buffer-substring-no-properties
                    (overlay-start ov) (overlay-end ov))))
         (used (+ custom:dashboard-heading-indent icon-w
                  (string-width name))))
    (goto-char (line-end-position))
    (insert (concat
             (make-string
              (max 1 (- width used (string-width key))) ?\s)
             (propertize key 'face 'font-lock-comment-face)))))

(defun custom/dashboard--decorate-section (ov key width icon-w separator)
  "装饰单个板块:OV 标题 overlay,KEY 右贴快捷键,WIDTH 版心宽。
SEPARATOR 是调用方按版心折算好的 propertized 分割线串。
含三步:板块尾空行换分割线、板块内行加行间距、标题行缩进+快捷键右贴。
倒序调用,前面的 insert 不影响后面 heading 的位置。"
  (custom/dashboard--replace-section-separator ov separator)
  ;; 标题行缩进 + 快捷键右贴到版心宽
  (custom/dashboard--indent-heading ov)
  (custom/dashboard--suffix-heading-key ov key width icon-w))

(defun custom/dashboard--center-line (body-width)
  "把当前行按自身行宽居中(行首加 align-to 前缀)。
行宽用插件的像素折算测量:string-width 会把 ─ ═ 等
ambiguous 字符按双列计,GUI 实际渲染单列,居中会偏;
dashboard-str-len 与插件原生 footer 居中同款公式。
行宽超过窗口时不加前缀:align-to 负值会把整行推出
屏幕左缘(内容只剩行尾残片),贴左至少完整可读;
align-to 表达式没有可用的 max 钳制(Emacs 31 静默
回退 0),只能在装饰时静态排除。"
  (let* ((beg (line-beginning-position))
         (end (line-end-position))
         (w (dashboard-str-len (buffer-substring-no-properties beg end))))
    (when (and (> w 0) (<= w body-width))
      (let ((p (propertize
                " " 'display
                `(space . (:align-to (- center ,(/ w 2)))))))
        (add-text-properties beg end
                             (list 'line-prefix p 'indent-prefix p))))))

(defun custom/dashboard--center-groups (ovs width window)
  "分组居中:先 remove 再改写——add-text-properties 不覆盖已有
属性,banner/Welcome/navigator/footer 都带插件自设的测量式
前缀。板块区(首板块标题行→末分割线行)统一版心前缀,整体
居中、块内左对齐;其余行(banner/Welcome/navigator/init-info/
footer)长短不一,逐行按自身行宽各自居中,整块左对齐会全贴
版心左缘。"
  (remove-text-properties (point-min) (point-max)
                          '(line-prefix nil indent-prefix nil))
  (let* ((sec-beg (save-excursion
                    (goto-char (overlay-start (car ovs)))
                    (line-beginning-position)))
         (sec-end (save-excursion
                    (goto-char (point-max))
                    (search-backward "─" nil t)
                    (line-end-position)))
         (block-prefix (propertize
                        " " 'display
                        `(space . (:align-to (- center ,(/ width 2))))))
         (body-width (window-body-width window)))
    (save-excursion
      (goto-char (point-min))
      (while (< (point) sec-beg)
        (custom/dashboard--center-line body-width)
        (forward-line 1))
      (add-text-properties sec-beg sec-end
                           `(line-prefix ,block-prefix
                                         indent-prefix ,block-prefix))
      (goto-char sec-end)
      (while (and (< (point) (point-max))
                  (progn (forward-line 1) t))
        (custom/dashboard--center-line body-width)))))

(defun custom/dashboard--decorate-headings (&optional window)
  "渲染后装饰标题行、右贴快捷键、行间距与板块分割线。
标题行与分割线都补齐到版心宽(=custom/dashboard--content-width= ),
板块内标题与条目行统一加 `custom:dashboard-line-spacing' 行间距,
分割线替换板块尾第一段空行。完成后分组居中:板块区按版心左缘统一
前缀,其余行逐行自身居中,理由见节首 prose;不先 remove 则插件/banner
自设的前缀不会被 add-text-properties 覆盖。定位走 heading overlay
(`dashboard-heading' face)而非 `dashboard--section-starts':渲染末尾的
page-separator 替换会使后者的绝对位置漂移。只从
`custom/dashboard--refresh-in-window' 调用,保证运行在正确窗口上下文。
三步拆分:`custom/dashboard--heading-overlays' 收集、
`custom/dashboard--decorate-section' 单板块装饰、
`custom/dashboard--center-groups' 分组居中。"
  (with-current-buffer (get-buffer dashboard-buffer-name)
    (let* ((width (custom/dashboard--content-width window))
           (icon-w (if (and (dashboard-display-icons-p)
                            dashboard-set-heading-icons)
                       2 0))
           ;; 分隔线每渲染只折算一次:同次渲染内 frame/字体不变,
           ;; ─ 为 East Asian ambiguous,按当前 frame 实测像素宽折算
           ;; 才能恰好铺满版心(各板块共用同一结果)
           (separator (propertize
                       (make-string
                        (max 1 (/ (* width (frame-char-width))
                                  (max 1 (string-pixel-width "─")))) ?─)
                       'face 'shadow))
           (ovs (custom/dashboard--heading-overlays))
           (inhibit-read-only t))
      ;; 倒序插入,前面的 insert 不影响后面 heading 的位置
      (let ((pairs (reverse (cl-mapcar #'cons ovs
                                       custom:dashboard-heading-keys))))
        (dolist (pair pairs)
          (when (cdr pair)
            (custom/dashboard--decorate-section
             (car pair) (cdr pair) width icon-w separator))))
      (custom/dashboard--center-groups ovs width window))))

(defun custom/dashboard--refresh-if-stale ()
  "目标窗口宽度与上次渲染不同时才重渲染 dashboard。
frame 就绪回调与 resize 合并刷新共用:全量渲染(item 生成 + agenda
扫描 + 装饰)成本高,宽度相符就跳过。窗口过窄(版心不足
custom:dashboard-min-content-width)时跳过且不记录宽度——极窄渲染
出来也是破碎的,保留上一次可读的内容,窗口拖宽后宽度仍不匹配,
自然触发重渲染。"
  (when-let* ((win (custom/dashboard--dashboard-window)))
    (and (>= (custom/dashboard--content-width win)
             custom:dashboard-min-content-width)
         (/= (window-body-width win)
             (or custom/dashboard--rendered-width 0))
         (custom/dashboard--refresh-in-window win))))

(defun custom/dashboard--on-frame-make (&rest _)
  "新 client frame 就绪后,渲染宽度不匹配才重渲染自愈。
initial-buffer-choice 阶段 selected window 可能仍是 daemon 旧 frame,
首帧版心会按错误宽度装饰且记录下错误宽度,本回调比较后自愈;宽度
相符(正常路径或同宽新帧)则零成本跳过。"
  (run-at-time 0 nil #'custom/dashboard--refresh-if-stale))

(defvar custom/dashboard--resize-timer nil
  "Resize 合并刷新的 pending idle timer,静止后触发一次。")

(defun custom/dashboard--on-resize-idle ()
  "Resize 静止后的合并刷新回调。"
  (setq custom/dashboard--resize-timer nil)
  (custom/dashboard--refresh-if-stale))

(defun custom/dashboard--on-resize (frame)
  "FRAME 尺寸变化时合并重渲染 dashboard,不逐事件全量渲染。
拖拽 resize 每个中间宽度一个事件,逐次渲染会把主循环卡死在连续
全量 item 生成上;只挂一个 idle timer,静止 0.3s 后按最终宽度刷
一次。daemon initial frame 的尺寸事件直接忽略(见
`custom/dashboard--dashboard-window')。"
  (when (and (frame-live-p frame)
             (frame-parameter frame 'client)
             (get-buffer-window dashboard-buffer-name frame))
    (unless custom/dashboard--resize-timer
      (setq custom/dashboard--resize-timer
            (run-with-idle-timer
             0.3 nil #'custom/dashboard--on-resize-idle)))))

;; 下面给 dashboard-get-agenda 套缓存,先认识 advice:
;; advice-add 是"给已有函数套一层包装"的机制,原函数与调用方都不用改;
;; C-h f dashboard-get-agenda 会显示 "This function is advised",点开看包装体。
;; 需要它的原因:dashboard-insert-section 宏对 list 参数求值 4 次,
;; agenda 的 org-map-entries 全量扫描因此被重复 4 次,是渲染耗时大头。
;; 想实验对比,移除包装后重开 dashboard,渲染会明显变慢:
;;   M-: (advice-remove 'dashboard-get-agenda
;;                      #'custom/dashboard--agenda-scan-once)
;; 重启 daemon 即恢复(配置每次加载都会重新 advice-add)。
(defvar custom/dashboard--agenda-once nil
  "单次渲染内的 agenda 结果请求级缓存。
仅渲染入口的 let 绑定内有效;跨渲染不缓存,数据新鲜度与插件原生
行为一致。")

(defun custom/dashboard--agenda-scan-once (orig &rest _)
  "dashboard-get-agenda 的 :around advice:单次渲染内只扫一次。
插件 \`dashboard-insert-section' 宏对 list 参数求值 4 次(heading
判断 / if 分支 / subseq / section-list 的 car),agenda 的
org-map-entries 全量扫描被重复 4 次,是渲染耗时与 GC 压力的大头;
缓存命中直接复用,未命中扫一次并记住。"
  (or custom/dashboard--agenda-once
      (setq custom/dashboard--agenda-once (funcall orig))))

(defun custom/dashboard--insert-lists-once (orig &rest args)
  "dashboard-insert-startupify-lists 的 :around advice:渲染入口。
let 绑定请求级缓存变量,渲染结束自动丢弃,下次渲染重新扫描。"
  (let ((custom/dashboard--agenda-once nil))
    (apply orig args)))

*** 实验性
本节集中管理生效中的版本兼容兜底 Shim。它们是针对上游已知 Bug 的临时规避措施，代码已经生效，移除的前提取决于上游的修复与更新。

以下 noweb 片段（均为 =:tangle no= ）定义了 Emacs 31 的兼容性 Shim，由靠前章节的代码通过 =<<emacs31/...>>= 展开到 =main.el= 。集中在此处是为了便于追踪，待上游修复后可统一清理。

#+attr_org: :width 70
| Shim                       | 根因                                 | 受影响功能                     | 移除条件                             |
|----------------------------+--------------------------------------+--------------------------------+--------------------------------------|
| =emacs31/source-load-compat= | Guix .elc 与 Emacs 31 宏展开不兼容   | Arei                           | 所有相关包改由 Emacs 31 重编译       |
| =emacs31/arei-compat=        | arei 0.9.7 .elc 与 Emacs 31 宏不兼容 | Scheme 染色([[#language-modes][各语言 major mode]]) | 升级 arei 或 Guix 用 Emacs 31 重编译 |

**** arei .elc 与 buffer-local-set-state 不兼容(bug#80812)
arei 0.9.7 的 =.elc= 字节码在旧版本 Emacs 下编译，与 Emacs 31 的 =buffer-local-set-state= 宏不兼容，会在 =scheme-mode-hook= 中抛出异常并导致 Scheme 代码语法高亮失效。
这里的兜底逻辑通过直接加载 =.el= 源码绕过该问题，保证 Scheme 染色正常工作。

#+begin_src emacs-lisp :noweb-ref emacs31/source-load-compat :tangle no
(defun custom/load-library-from-source (library)
  "从 LIBRARY 对应的 .el 源加载，绕过不兼容的 Guix .elc。
GNU store 只读无法删 .elc，且 .el/.elc 时间戳相同（epoch 1）使
`load-prefer-newer' 无效，故需显式从 .el 加载。返回 t 若成功。"
  (condition-case err
      (when-let* ((found (locate-library library))
                  (source (concat (file-name-sans-extension found) ".el"))
                  ((file-exists-p source)))
        (load source nil t t)
        t)
    (error
     (message "[ERROR] %s 从源加载失败: %S" library err)
     nil)))
#+end_src

#+begin_src emacs-lisp :noweb-ref emacs31/arei-compat :tangle no
(defun custom--maybe-enable-arei-mode ()
  "在真实 Scheme 编辑 buffer 中启用 `arei-mode'(跳过 org src 临时 buffer)。

对 `arei-mode' 调用包裹 condition-case:minor-mode 的故障不应中断
`scheme-mode-hook' 的后续步骤(尤其 font-lock 初始化)。"
  (unless (string-prefix-p " *org-src-fontification:" (buffer-name))
    ;; arei 的 Guix .elc 与 Emacs 31 宏不兼容:首个 scheme buffer 激活时
    ;; 从 .el 源加载绕过(兼容 shim,见 [[#compatibility]]);featurep 短路
    ;; 保证不重复 load,也接住已由 .elc 加载的极端顺序。
    (unless (featurep 'arei)
      (custom/load-library-from-source "arei"))
    (condition-case err
        (arei-mode 1)
      (error
       (message "[ERROR] arei-mode 启用失败,Scheme 染色不受影响: %S" err)))))
#+end_src
