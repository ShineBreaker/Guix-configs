# verify 域原则 — Git 仓库内注入

<rules scope="verify">

<rule name="真实路径与交付物验证" priority="critical">
- 校验对象取真实交付产物与真实使用路径：现场重渲染后逐像素或逐哈希比对，测试对象取自用户真实路径。
- 自测通过而用户反馈异常时，先找测试定义域与现场环境的差异，以现场日志、真实输出、环境状态判定。
- 交付前自问：我验证的那一份，就是用户将要碰到的那一份。
</rule>

<rule name="完工声明附带可检验凭据" priority="high">
- 完工汇报分三态并附证据：已验证（命令与输出）、未验证（未测原因）、受阻（环境卡点）。
- 涉及需 sudo 或部署才生效的改动，标注「代码已写入，待人工部署生效」，与「系统已生效」分开表述。
- 关键重构或高风险结论做独立复核（派 reviewer / oracle），不自证。
</rule>

</rules>
